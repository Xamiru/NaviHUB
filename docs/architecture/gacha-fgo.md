## Gacha section

**Gacha section (2026-07-10)** — standalone tracker at `/gacha` for the live-service games the user plays (HSR/FGO/E7/WuWa): per-game roster (characters + the game's equipment kind), per-unit builds, currencies (inline-edit tiles), banner schedule, subreddit news. ALL per-game vocabulary lives in `src/shared/gacha.ts` (`GACHA_GAMES`: unit kinds, facet/dupes labels + `formatDupes`, currencies, `buildMode`, `subreddit`, `color` hex accent) — the `gacha_*` tables are game-agnostic, so adding a game = one config entry. Kind/currency `key` strings are FROZEN (stored in DB, part of the future catalog importers' `(game, kind, external_source, external_id)` unique dedup key). `gacha_unit.dupes` is 0-based copies-consumed (HSR eidolon, FGO NP-1, E7 imprint, WuWa sequence) — never write 1-based values. FGO is `buildMode:'levelOnly'` → no Builds UI anywhere. **Online fetching is button-only, never automatic.** News = each game's subreddit **hot Atom feed** (`r/<sub>/hot.rss`) — Reddit's unauthenticated JSON API 403s ALL non-browser clients (verified: www/old/api hosts, any UA), only RSS is open, and it rate-limits bursts with 429 + NO retry-after; the fetcher passes `rateLimitWaits: 0` (opt-out added to `fetchWithRetry`) and fails fast with a toast instead of hanging the button 60s. `parseSubredditFeed` is a hand-rolled fixture-tested Atom tag-scan (epub.ts approach). A fetch REPLACES the game's cached feed (`gacha_news.sort_order` = hot rank; empty parse throws before touching the cache); `author`+`sort_order` arrived post-ship → ensureColumn in connection.ts. Per-game hero art (hub cards + dashboard header banners) lives in `gacha_meta 'image'` via `gacha:setGameImage`, picked in `GachaGameImageDialog` — fastest path reuses a games-section RAWG cover (`api.media.list` game search), else file/URL. News thumbnails stay remote https URLs (CSP `img-src` allows it); unit/banner/hero art downloads via `gacha:downloadImage` → content-addressed `media/`. News links open through `app:openExternal` (http/https-guarded; `createWindow` denies all `window.open`) — never raw `<a href>` (HashRouter hijacks). Every `gacha_*` table is personal → wiped in sanitizeSql.cjs; keep any new gacha table added there. Detail phases planned per game (E7 Fribbels-style gear optimizer w/ future `gacha_gear` table, catalog importers with `owned=0` rows, HSR warp history) — all bolt on without destructive migration.

## FGO Coach — the first LLM feature

**FGO Coach (2026-07-13)** — the first per-game gacha detail phase: an LLM coaching chat at `/gacha/fgo/coach`, gated by `GachaGameCfg.coach` (fgo only — flip the flag for others). FIRST LLM feature in the app. **Provider is switchable** (`coach.provider` setting, DEFAULT `gemini`): **Google Gemini via `@google/genai`** (`gemini.api_key` — free AI Studio key, no card; the user picked this because Vertex needs a credit card), OR Claude via `@anthropic-ai/sdk` (`anthropic.api_key`) / `@anthropic-ai/vertex-sdk` (`vertex.project_id`/`region`/`credentials_path`). All three externalized (require() from node_modules — verify `grep require\("@google/genai out/main/index.js`). Model from `coach.model` (default `gemini-2.5-flash`; SettingsPage shows Gemini models when provider=gemini, Claude models otherwise). **Two provider adapters in `gachaCoach.ts`**, both a manual streaming agentic loop (cap 8 iters) sharing tools/context/persistence: `runGeminiTurn` (`models.generateContentStream`, `functionCalls` → run tools → `functionResponse` parts, `parametersJsonSchema` = same JSON schemas) and `runAnthropicTurn` (`messages.stream`, `stop_reason==='tool_use'`, `buildModelParams` opus/sonnet→`thinking:{type:'adaptive'}`/haiku→`{}`, NEVER temperature/top_p). Both stream text deltas into `status.partialText`, phase `tool:<name>` on tool starts. **History is provider-neutral plain text** (`textOf` of stored `api_blocks`) so switching providers mid-thread is safe and both adapters build their own wire format — assistant rows persist `[{type:'text',text}]`, no verbatim block replay. Pure logic (tools, `buildContextBlock`, `buildModelParams`, `npLevelToDupes`, `geminiToolDeclarations`/`toolDefinitions`) lives in `coachTools.ts` so tests skip all SDKs. **17 tools** execute sync against gachaRepo/coachRepo (get_roster/add_unit/update_unit, currencies, banners, goals+recurring tasks, save_note, get_news — NO deletes); FGO vocabulary: np_level 1-5 → `dupes=np-1`, add_unit dedupes by (kind, lower(name)). Every mutator pushes an action chip. **Status+poll like musicDownload** (module-level `status`, `gacha:coachStatus` polled 350ms, `lastSettled` guard by turnId → invalidate broad `qk.gacha.all`); cancel via `AbortController` (Gemini `config.abortSignal`, Anthropic `stream` abort). **Two rows/turn persisted**; user row = text + `[screenshot attached]` markers — **images NEVER replayed**, only sent (as base64) the turn they arrive. Context: fresh `<context>` block (roster/currencies/banners/goals w/ `[OVERDUE]`/`[DUE TODAY]`/notes/doc summaries/news) prepended to the CURRENT user turn only. Vision: `nativeImage` resize long-edge≤1568 → JPEG base64 (Gemini `inlineData`, Anthropic image block). Reminders render from DB with ZERO LLM calls; `dueCounts` drives badges on the Coach pill + FGO hub card. Assistant markdown via `@shared/markdown.ts` pure parser → `components/Markdown.tsx` (NEVER dangerouslySetInnerHTML). All 5 coach tables (`gacha_chat_thread/message`, `gacha_goal`, `gacha_coach_note/doc`) + `gemini.api_key`/`anthropic.api_key`/`vertex.*` settings are personal → wiped in sanitizeSql.cjs. `abortActiveCoachTurn()` in before-quit.

## FGO catalog + Chaldea import

**FGO catalog + Chaldea import (2026-07-21)** — the second FGO detail phase, gated by `GachaGameCfg.catalog` (`{ source:'atlas', backup?:'chaldea' }`, fgo only; both keys FROZEN — `source` is written to `gacha_unit.external_source`). **Atlas Academy** (`api.atlasacademy.io`, NO key) is the FGO catalog source: `src/main/atlas.ts:importCatalog` fetches `/export/NA/basic_servant.json` (421) + `basic_equip.json` (2118), stages them (servant kind + `prettifyFgoClass(className)` element, craftEssence kind), ONE `downloadImages` batch of every `face` (activity pill), then `gachaRepo.upsertCatalogUnits` seeds them all as **owned=0** rows. Two new repo fns own their transactions (replaceNews precedent): `upsertCatalogUnits` (INSERT owned=0 … ON CONFLICT(game,kind,external_source,external_id) DO UPDATE **canonical only** — personal fields never in DO UPDATE, `image_path=COALESCE(excluded,…)` keeps art when a face download fails; a NULL-external manual row with a matching name is ADOPTED not duplicated) and `applyOwnership` (Chaldea backup → flip owned=1 + dupes/level + shallow-merge into `data`; **throws if catalog empty**; non-destructive — rows absent from the backup are untouched). Re-import is authoritative for name/rarity/element/image, preserves owned/favorite/level/dupes/notes/data. **Chaldea import** (`src/main/chaldea.ts`): `parseChaldeaBackup` is the trust boundary (userdata.json `{users,curUserKey}`; servant `cur.favorite`→owned, `_npLv`1-5→dupes, dataMerge ascension/skills/appendSkills/grail/fou/bond with per-field validators; CE `status===2`→owned, `limitCount`→dupes, `lv`→level; bad file throws, bad entry skipped) → `importBackup` picks the file **in main** (JSON never crosses IPC) via generalized `files.pickTextFile({extensions,maxBytes})` (default txt/md 2MB unchanged; Chaldea passes json/64MB). IPC: `gacha:importCatalog` (withActivity) + `gacha:importChaldea`. Renderer: a **Catalog tab** (GachaGamePage, only when `cfg.catalog`) mirrors RosterTab but lists ALL rows — unowned cards dim (`opacity-50`) + open `GachaUnitDialog` in **claim mode** (`unit && !unit.owned` → "Add to roster", save adds `owned:true`); RosterTab itself adds `ownedOnly:true` to its filter for catalog games (non-catalog games keep byte-identical filter/cache keys). GachaUnitPage: catalog rows (externalSource) show **Remove from roster** (`owned:false`) not Delete (re-import would resurrect a deleted row). **Coach is catalog-aware** (coachTools.ts): `gatherSnapshot`/`get_roster` force `ownedOnly:true` (else 2.5k unowned rows swamp the context caps); `add_unit` on an existing row flips owned=1 + never clobbers a catalog row's canonical rarity/element (Atlas authoritative); `findUnit`/`update_unit` on an unowned catalog row returns an "use add_unit" error. NO schema change (columns + `idx_gacha_unit_external` predate this); NO sanitizeSql change (gacha_unit already wiped — catalog rows go with it, fine). Tests: atlasImport (convergence on pre-seeded rows, manual adoption, COALESCE image, atomicity, prettify), chaldeaImport (parse + apply, non-destructive, catalog-empty throw), gachaCoach (owned-only, catalog-aware add_unit). Future: catalog importers for the other games (add `catalog` to their cfg + a source module); material/ascension planner off `gacha_unit.data`.
