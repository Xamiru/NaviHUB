## Wallpapers and fan art

**Wallpapers/fan art (2026-07-09):** every media detail page gets a Wallpapers `MediaImagesSection`; non-movie/TV types also get Fan Art (`cfg.hasFanArt`). One `media_image` table (`kind` column), rows stripped on export (sanitizeSql.cjs). `src/main/pictures.ts` owns SQL + searches: Wallhaven (purity=100 SFW hardcoded — regression-tested) and TMDB backdrops (`tmdb.ts:fetchBackdrops`, movie/tv with `external_source='tmdb'` only). Searches go through IPC (renderer CSP has no `connect-src https:`; remote *thumbnails* are fine — `img-src https:`). `ImageBrowseDialog` per-tile busy/added state; `Lightbox.tsx` is the app's only fullscreen image modal (←/→ wrap). Removing an image deletes its file (pictures/ paths only); deleting media cascades rows but leaves files.

## Books

**Books section (2026-08-04)** — new media type `'book'` (flavor A, `/books`): Open Library import + pages-based tracking + local EPUBs read through the EXISTING reader machinery. **Progress = pages** (`progress` = current page, `total_units` = page count): book is deliberately NOT in `UNIT_PROGRESS_TYPES` and `BOOK` has no `logUnitLabel`, so the detail-page log button is mark-completed / read-again (the movies behavior) — a page is not a sitting. **Importer `src/main/openlibrary.ts`** (rawg.ts template; NO key, descriptive User-Agent — the AnimeThemes posture): work ids are STRINGS (`OL45883W`) → `ImportSearchResult.id` is `number | string`, ImportDialog flattens `api[source.key]` through one structural cast and `importingId` is widened; `ImportSourceCfg` gained `unitNoun` ("352 pages" not "352 ep"). Search carries `author_name` in `native` (the disambiguator); import = work + per-author fetches (cap 6 → person rows by `('openlibrary', OL…A)` + **`writer` credits**, surfaced by `crewTitle:'Authors'` and the `/authors` browse route scoped `role='writer'` + `mediaType='book'` so movie writers can't bleed in) + `editions.json?limit=50` **median** page count (works carry none; `total_units=COALESCE(?, …)` so a null median never wipes a hand-entered count) + `ratings.json` → `metadata.olRating = avg×20` (pre-scaled 0-100, added to `COMMUNITY_SQL`) + subjects → tags **capped at 10** (OL subject lists are noisy). Publishers live on editions as bare strings — hand-curated, v1 skips them. bulk-import.cjs does NOT mirror openlibrary (known debt). **Local EPUBs reuse manga wholesale**: same `manga_chapter` table + manga.ts functions, `rootInfoFor(mediaId)` derives root/prefix/settingKey from the media row's `media_type` (`book` → `books.dir`/`books/` prefix — no schema change; `booksRootDir()` in files.ts, `books/` branches in `absoluteMediaPath` AND the navimg **archive-streaming allowlist** in index.ts, which would otherwise 404 every spine fetch). **`syncMediaProgress` returns early for book media** — finishing an EPUB volume must never slam a page-based `progress` down to a volume count (chapter `read_at`/`last_read_page` still persist; regression-tested). `readerPath(basePath, …)` takes `'/manga' | '/books'`; new chromeless routes `/books/:id/read|book/:chapterId` (isReader regex widened), both readers derive `basePath` from the URL for exits/volume switches. `MangaChaptersSection` de-manga-fies via `m.mediaType`: "Volumes" heading, mokuro OCR + Vocab-deck hidden, `ocrOverview` query disabled. `CoverageSection`'s local-reader gate became **`cfg.key === 'manga'`** (JP comprehension must not appear on English books). **Light novels stay in manga** (jpMilestones/mining untouched). Stats: book in `STAT_TYPES`/`ESTIMATED_TYPES`, `rowMinutes` = pages × `stats.bookPageMinutes` (default 1.5, Settings → Time stats) × passes; `TYPE_COLORS.book` teal; torznab `[7020, 7000]`. `books.dir` (bootstrapped on first attach, Settings → Folders) wiped in sanitizeSql.cjs. Tests: openlibraryImport (string ids, median, capped tags, best-effort endpoints, COALESCE re-import), manga.test.ts book block (books/ prefix + root, the progress guard, manga regression), torrents/mediaProgress/mediaRepo/exportSanitize extended.

## Game launcher, playtime tracking, HLTB lengths

**Game launcher + playtime tracking + HLTB lengths (2026-08-06)** — games/VNs get launch-from-app (`cfg.hasGameLaunch`, GAME + VISUAL_NOVEL): a per-title executable in **`media_item.exe_path`** (init.sql + schema.ts + ensureColumn; absolute machine path — wiped in sanitizeSql.cjs next to local_dir, deliberately absent from mediaRepo's COL map AND from `MediaItem` — it rides `games:overview`, the local_dir posture) and sessions in **`game_session`** (media_id CASCADE, UTC started/ended, duration seconds; wiped on export). `src/main/gameLaunch.ts` is the mokuroRun singleton with THE one deliberate deviation: the child is spawned `detached:true` + `unref()` and is **never killed** — no cancel channel, and before-quit calls `finalizeActiveGameSession()` (records the in-flight session, must run BEFORE `closeDatabase()`) while the game keeps running. Sessions under `MIN_SESSION_SEC` (60) are discarded with a launcher-stub hint (a stub that spawns the real game and exits is the known v1 limitation — link the real exe); an app crash loses the in-flight session (accepted; documented in-module). **The fold** (`gameLaunchCore.ts:foldedProgress`, pure + exhaustively tested): `game_session` is the source of truth for tracked seconds, and `media_item.progress` moves by the **delta of the rounded cumulative** (`unitSecondsFor`: game=3600, vn=60), so short sessions never round away, hand-entered baselines survive, and a manual progress edit just becomes the new baseline — progress stays hours(game)/minutes(vn), which is why `rowMinutes`/Stats needed ZERO changes. Windows-only launch (`process.platform` guard throws a friendly error; overview carries `supported`); picker is main-side `games:pickExe` (manga.attachFolder posture). Renderer: `GameLaunchSection` (Playtime tab, above the HLTB boxes) + `lib/useGameSession.ts` (useOcrRun port, 1 s poll so the elapsed chip ticks; settled toast invalidates games+media+checklist). Checklist gained detected source `gameSession` (`game-session` def, daily, NOT seeded; sessions counted by `date(started_at,'localtime')`). **HLTB is now the authoritative game length**: `hltb.ts:hltbLengthHours` = `max(1, round((main ?? allStyles)/60))` hours, written to `total_units` at BOTH sites — rawg.ts import (RAWG's crowd-average `playtime` is only the fallback) and `fetchForMedia` (game rows only, a miss never writes), so the existing detail-page Fetch/Refresh button fixes wack lengths on already-imported games; VN lengths stay VNDB minutes untouched; re-import-to-apply otherwise. `GAME.totalFieldLabel` is now 'Length (hours)'. Tests: gameLaunch (fold matrix), gameSessionRepo (atomic insert+fold, cap/order, CASCADE), hltb (both write sites, VN untouched, miss keeps value), rawgImport (+HLTB-beats-RAWG, URL-routed http mock), checklist + exportSanitize extended. Windows spawn/exit end-to-end is UNVERIFIED on this Linux box — needs a manual pass on the user's gaming PC after the next release.

## Achievements

**Achievements (2026-08-14)** — Xbox/Steam-style achievement tracking for games and VNs (`cfg.hasAchievements`, GAME + VISUAL_NOVEL — the same pair that can link an executable). Three new tables, no migration work: **`achievement_game`** (media_id PK, `provider` `steam`/`ra`, `provider_game_id`, `schema_fetched_at`), **`achievement`** (the set: api_name, name, description, hidden, both icon paths, `points` RA-only, `global_pct`, UNIQUE(media_id, api_name)) and **`achievement_unlock`** (achievement_id PK — **a row's presence IS "unlocked"**, so nothing stores a locked state; `source` `emu`/`ra`/`manual`). The first two are canonical and SURVIVE an export (the theme_song posture, declared in sanitizeCoverage's CANONICAL_SURVIVORS); `achievement_unlock` is personal and wiped, as are the three new settings keys.

**Why it works on pirated games at all**: a cracked game still calls the Steam achievement API — the crack just points it at a Steam emulator, and every one of them writes unlocks to a well-known file. `achievementsCore.ts` (pure, `gameLaunchCore` seam) holds a table of ~15 candidate paths (Goldberg/GSE in `%APPDATA%`, CODEX/RUNE/EMPRESS/Online-Fix under `%PUBLIC%\Documents`, SKIDROW/SmartSteamEmu, ALI213's globbed profile folder, plus Goldberg's local-save-beside-the-exe mode) and two tolerant parsers (Goldberg JSON object-or-array; the INI family, both section-per-achievement and flat-container shapes, `Achieved`/`HaveAchieved`/`earned` spellings). **`parseUnlockFile` never throws** — the watcher reads these files while the game writes them, so a torn read must look like "nothing new", not a crash. `emuScan.ts` is the IO half behind an injected `EmuFileIO`, which is what makes the whole thing testable on Linux. Roots come from env vars, and a missing one just drops its candidates.

**Providers**: `achievements.ts` gets the Steam set from **three sources in order, first hit wins** — the user's Steam account is "limited" (Steam only issues Web API keys to accounts that have spent money), so the list has to work with no key. (1) **The crack's own `steam_settings/achievements.json`** beside the exe (or up to two folders above it), which Goldberg/GSE releases ship: full schema INCLUDING the api names the emulator writes unlocks under, icons copied in content-addressed via `files.importImageFile`, zero network — `parseGoldbergSchema` handles string and localized-object names, `hidden` as "0"/"1"/bool, and both `icongray`/`icon_gray` spellings. (2) The **Web API** `GetSchemaForGame`, only if `steam.web_api_key` is set. (3) **Steam's public community stats page** (`steamcommunity.com/stats/<appid>/achievements`), which has names/descriptions/art/global % but **no api names** — those come from the keyless `GetGlobalAchievementPercentagesForApp` and `joinCommunityWithPercentages` pairs the two lists by percentage (both are sorted by % desc; ties keep shared order; a page row with no partner is dropped and counted as `unmatched`, surfaced in the setup toast). On that path the percentages endpoint is load-bearing, not decoration, so its failure IS a failure. `AchievementSetupResult.schemaSource` says which source won. Rarity for the other two sources comes from the same keyless endpoint, best-effort. `exeDirOf` picks path flavor by separator, not host — the posix `dirname` of a `C:\…` path is `.`, which was a silent miss on the Linux test box. Icons go through `downloadImages` like any importer, and the whole thing is two-phase atomic. Rarity tiers (`rarityTier`: >25 common, >10 uncommon, >3 rare, else ultra-rare) are computed main-side so the renderer never re-derives cutoffs; **no gamerscore is invented** — `points` stays NULL for Steam. `retroAchievements.ts` covers emulated games: `API_GetGameInfoAndUserProgress` returns the set AND the user's full unlock history in ONE call, RA points are shown because RA actually awards them, and `parseRaDate` appends the missing `Z` (RA sends UTC unzoned, so `Date.parse` would shift every unlock by the machine's offset). RA has no free-text search endpoint — the dialog pulls a console's game list and filters locally, with direct game-id entry as the escape hatch.

**Appid without Steam**: only `external_source='steam'` rows know their appid. Everything else resolves through the keyless storefront `search()` and the user confirms; the choice lands in `achievement_game.provider_game_id` (no `media_item` column, no ensureColumn) and is **written BEFORE the fetch**, so a failed network half doesn't cost the user the lookup.

**Eligibility is "exe linked now or ever"** — `exe_path IS NOT NULL OR EXISTS(game_session) OR EXISTS(achievement_game)`. `games:clearExe` nulls the path and keeps no history, so the latter two clauses are what make "or ever" true; once tracking exists its own row is the durable marker.

**The live half** — `achievementWatcher.ts` owns the app's ONE main-side `setInterval` (5 s for emulator files, 30 s for RA), started by `gameLaunch.startSession`, cleared in `endSession` and by `stopAchievementWatcher()` in the before-quit registry (ahead of `closeDatabase()` — it writes rows). Both stop paths run a **final sweep**, because emulators commonly flush as the game exits. The OS notification is raised from main (`new Notification`, not `webContents.send` — the push freeze is intact) because during a fullscreen game the renderer is occluded and its timers throttle; the renderer separately polls `achievements:watchStatus` for the in-app toast (`toast.ts` gained an `unlock` kind) and the list refresh. `pollOnce(deps)` takes injected fs/fetch/now/notify, so the whole detect→write→notify path is tested with no game, no emulator and no timer. An mtime short-circuit makes the 5 s interval free in the common case. First tick deliberately does NOT seed `lastMtimeMs`, so an unlock earned between the last sweep and this launch is still caught.

**Re-fetch is authoritative** for the set (prunes what the provider dropped, refreshes names/art/rarity) but **unlocks survive it** — the UNIQUE upsert keeps achievement ids stable, so only a genuinely removed achievement loses its unlock by CASCADE. Unlock imports keep the **earliest** timestamp: an emu file rewritten today must not relabel a two-year-old unlock. A file with no usable time falls back to the file's mtime (far closer than "now" for a retroactive sweep). **Timestamps are range-checked twice** (`normalizeTime`, then again in `insertUnlocks`): SQLite's `datetime(?, 'unixepoch')` returns NULL past year 9999 and `unlocked_at` is NOT NULL, so an emulator fork writing microseconds would otherwise abort the insert transaction and discard every good unlock in the batch — and in the watcher that failure is swallowed *after* `lastMtimeMs` advances, silently killing detection for the rest of the session.

**Two watcher races the lifecycle has to survive**, both because `gameLaunch.endSession` clears `active` BEFORE the (async) final sweep, so a new launch is legal inside that window: `stopWatch` retires only the watch it started with (`if (watch === mine)`) and sweeps that same one explicitly (`pollOnce(deps, mine)`), and `startWatch` clears `watch` FIRST so launching an *untracked* game cannot leave the previous game's watch standing. Both are regression-tested. Setting up a provider writes the association before the fetch (so a failed network half doesn't cost the appid lookup) **except** when it would flip a title already tracked on the other provider — that commits only once the new set lands, or the old provider's achievements would sit on screen mislabelled.

**The renderer polls past the end of a session** (`GRACE_MS`, 20 s): the session status flips to `ended` the instant the game exits, but the final sweep — the one that catches what an emulator flushes on exit, a network call later for RA — lands after that. Without the grace window those unlocks only ever appeared as OS notifications. `useGameSession` also invalidates `qk.achievements.all` on settle, so the tab, chips and Home strip aren't left showing pre-session counts, and a watcher that has stopped detecting (RA unreachable) surfaces its `message` as a toast rather than looking like a session where nothing was earned.

**Manual toggling is always available** (`source: 'manual'`), the floor for games nothing can track — and it will not overwrite a tracked unlock. **The Goldberg wizard** (`GoldbergWizardDialog` + `generateGoldbergConfig`) is guided, not automatic: it writes a `steam_settings/` folder (achievements.json in Goldberg's shape, steam_appid.txt, copied icons) into a directory the USER picks and shows the copy steps — it deliberately never touches the game folder, since a wrong guess there breaks an install.

**Surfaces**: an Achievements tab on the detail page (`?tab=achievements` deep-links), `/games/achievements` (recent feed, per-game completion, rarest), `/games/installed` (exe-linked titles with Play — a launcher view, not another filtered library list), a Home "Recent unlocks" strip that hides itself when empty, and a `✓ n/total` chip on list cards fed by ONE `cardSummaries` map rather than a query per card. Both new routes sit above `/games/:id` (the `/anime/seasonal` precedent) and are `GAME.children` sidebar links. Tests: achievementsCore (path matrix, every file format + damaged input, rarity boundaries, Goldberg round-trip), emuScan (injected IO, glob expansion, multi-emulator merge), achievementRepo (prune-preserves-unlocks, earliest-wins, CASCADEs, real SQL), achievements (URL-routed fixtures for both providers), achievementWatcher (detection, mtime short-circuit, final sweep, quit killer), plus initLegacyDb and sanitizeCoverage extended. **Windows end-to-end — real emulator files, a real fullscreen notification — is UNVERIFIED on this Linux box** and needs a pass on the user's gaming PC; the emulator path table is community knowledge, so "Import from emulator files" reporting `found: 0` on a game that should have files is the signal to extend it from a real sample.

## Seasonal anime

**Seasonal anime (2026-07-10)** — `/anime/seasonal` (`SeasonalAnimePage`) shows the library's anime as four stacked Winter→Fall shelves per selected year; entry points are `MediaConfig.hasSeasonal` (list-header button), an `ANIME.children` sidebar link, and a CommandPalette nav item (route sits above `/anime/:id` in App.tsx). Season data: the AniList anime importer persists canonical `season`/`seasonYear` into the `metadata` JSON (`mergeMetadata` accepts positive numbers AND non-empty strings — mirrored in bulk-import.cjs); `@shared/season.ts:seasonForItem` (tests/season.test.ts) prefers validated metadata, falls back to release-date quarters (Jan–Mar=winter …), else the page's Unknown bucket. Known skew: year-only AniList dates are padded to `-01-01` → Winter, and Dec premieres belong to next-year WINTER — both self-correct on re-import. The page reuses `qk.media.home('anime')`, so its queryFn filter must stay byte-identical to HomePage's (`{ mediaType: 'anime' }`).

## Library filtering and sorting

**Library filtering & sorting (2026-07-19)** — every media type's `MediaListPage` gets one filter model, all of it inside `MediaListFilter` (shared/types.ts) so the whole filter object stays the query key. Repo side (`mediaRepo.list`): `buildWhere()` assembles clauses for multi-status (`statuses`, superseding the legacy single `status`), multi-tag with `tagMode:'any'|'all'` (legacy `tagId` still honored), favorite, `unrated` (score IS NULL — wins over any score range), and inclusive numeric ranges for personal score, community score, year and `total_units`. Three derived SQL expressions are shared by filters/sorts/facets and must move together: `COMMUNITY_SQL` COALESCEs every importer's rating key into ONE 0-100 scale (averageScore / metacritic / vndbRating / imdbRating×10 — **any new importer rating key belongs here**), `YEAR_SQL` (release year, falling back to metadata `seasonYear`), and `SEASON_SQL` (metadata season first, then month quarters — mirrors `seasonForItem` in @shared/season.ts, keep in step). Sort keys come from the `SORT_SQL` whitelist (never interpolate filter input); `random` is a SEEDED multiplicative hash of `m.id` — the multiplier carries the seed (an additive seed only rotates the same order) and is folded in JS so `id * mult` can't overflow int64, which makes a shuffle stable across refetch/scroll-batching while the page's Shuffle button re-seeds. `mediaRepo.facets(mediaType)` (`media:facets` → `qk.mediaCounts.facets`) feeds the sliders real library bounds and is the page's true title count — `statusCounts` drops NULL statuses and undercounts. Renderer: `MediaFilterPanel.tsx` owns `MediaFilters` + `EMPTY_FILTERS`/`activeCount`/`toListFilter`, range convention **`null` = unconstrained** (a slider spanning its full bounds collapses back to null, which is what keeps untouched filters out of the query key); `RangeSlider.tsx` is the app's dual-thumb slider (two transparent native ranges over a div track, thumbs styled in the styles.css WIRED CHROME block). Status pills are multi-select; active narrowings render as removable chips with Clear all. HomePage/SeasonalAnimePage still pass `{ mediaType }` only, so their shared `qk.media.home` cache entry is untouched — don't add defaulted fields at those call sites.


## Franchises

**Franchises (2026-08-15, reworked same day on user feedback)** — `/games/franchises` (`FranchisesPage`) + `/games/franchises/:id` (`FranchisePage`), both above `/games/:id`, sidebar via `GAME.children`. A third feature shape beside CLAUDE.md's A/B: a **curated overlay** over an existing media type. The canon lives in `src/shared/franchises/` (`types.ts`, one file per franchise, `index.ts` catalog — the `wrestling.ts`/`programming/` pattern); franchise, entry and character ids are FROZEN (persisted UI state + route params), entry arrays are authored in release order and `tests/franchises.test.ts` enforces that plus id uniqueness, chrono completeness, `appearsIn` integrity and https-only art URLs. Library rows are matched client-side by `matchLibrary` (`match.ts`, `tests/franchiseMatch.test.ts`): external-id pass first (multiple refs per entry cover Steam re-listings, e.g. Kiwami legacy + 2026 appids), then exact-normalized title/alias equality — never substrings, which is what keeps FF7 and FF7 Remake apart; remakes are separate entries. The pages reuse `qk.media.home('game')` (byte-identical `{ mediaType }` filter, the HomePage rule) and the **positional** finished check (`statuses[1]` via `useStatuses(GAME)`, rename-safe) plus the `progress >= totalUnits` fallback.

**Page layout**: rows in the LEFT half (`lg:grid-cols-2`), Timeline + Characters in the right half, trivia full-width below. Sorting is by **clickable column headers** (Title=release order, Year, Story [hidden when the franchise has no `chrono`], ★ your score, MC) — click again flips direction; nullable columns always sink unowned/unscored rows to the bottom. Rows re-sort **live** with `lib/useFlip.ts:useFlipList` (a dependency-free FLIP: measure `[data-flip-key]` rows in a layout effect, invert with a translateY, reflow, play) — nothing else in the app animates a data-driven reorder (dnd-kit only animates during a drag). The timeline is a horizontally scrollable year strip of **covers** (fixed px per year, lane-packed on collisions): library cover for owned entries (accent ring + ✓ when finished, links to the game), greyed tile when not owned.

**Background** — ONE per franchise, pinned. `FranchiseCfg.heroUrl` (curated, curl-verified) is both the index-card image and the page's default background; the user replaces it with `Set background` in the header (`api.files.pickImage()` → a `media/` path in the settings row `franchise.<id>.background`, `''` = reset since settingsRepo has no delete; `franchiseBackgroundKey()` names it and `scripts/sanitizeSql.cjs` wipes `LIKE 'franchise.%'` on export). `FranchiseBackground.tsx` is a page-local absolute layer using **`background-attachment: fixed`** — anchored to the window viewport but painted only inside the page box, so it holds still while `main` scrolls and can never paint over the sidebar/Topbar; needs no shell widths and is immune to `ui.scale`. Preload-then-cross-fade on URL change, viewport-fixed base-900 gradient scrim. Per-game `bgUrl` on every entry and the `media_image` kind `'background'` are **RESERVED** for the future game-detail-page background — nothing on the franchise page uses them (the first cut's hover/click per-game swap was explicitly rejected).

Curated art (heroes, entry `bgUrl`, character `portraitUrl`) renders from the remote URL immediately (CSP allows `img-src https:`) while `src/main/franchiseArt.ts` caches it content-addressed via `downloadImage` — `franchise:ensureArt(id)` / `franchise:ensureHeroes()` fire a single-flight fire-and-forget batch (one `franchiseArt` task-registry row), `franchise:artStatus` is polled at 1.5 s while running, `franchise:artMap(id)` / `franchise:heroMap()` map url → cached rel path (`files.ts:dlFileName` is the extracted shared derivation; `tests/franchiseArt.test.ts`). Adding a franchise = one data file + a `FRANCHISES` entry; nothing else changes.
