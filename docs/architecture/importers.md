## Network and archive memory boundaries

Structured API responses are consumed through `fetchWithRetry` with a 32 MiB body ceiling. The
wrapper checks a trustworthy `Content-Length` early and also counts bytes while reading, so chunked
or dishonest JSON/XML/text responses cannot grow the main process without bound. Large binary
assets do not use whole-body readers: media files and the games catalog stream to a temporary file
with their own input/output limits, and only a fully validated staged catalog replaces the installed
database.

## Games importer switched to IGDB

**Games importer switched to IGDB (2026-08-07)** — RAWG went down hard (site + API dead for a full day; the service has been semi-maintained for years), so `src/main/igdb.ts` is now the games source: `GAME.importSource = { key: 'igdb' }`, `ImportSourceCfg.key` union widened, `igdb:search/import` IPC + `api.igdb` + preload. **Auth is Twitch OAuth client-credentials**: settings `igdb.client_id`/`igdb.client_secret` (free app at dev.twitch.tv/console/apps; both wiped in sanitizeSql.cjs; Settings → Keys card replaced RAWG's) exchanged at id.twitch.tv for a bearer token cached module-level (~60 days; 401 → re-auth ONCE, the hltb.ts creds posture). Queries are **APIcalypse text** POSTed to `api.igdb.com/v4/<endpoint>` — user input is quote-stripped (`sanitizeQuery`) because APIcalypse strings have no trustworthy escape. Covers come from images.igdb.com (`t_cover_big` thumbs, `t_cover_big_2x` stored). Length stays HLTB-authoritative; the fallback is IGDB's own `game_time_to_beats` endpoint (`normally`/`hastily` in SECONDS → hours, best-effort, never blocks). `metadata.igdbRating` (0-100) joined `COMMUNITY_SQL`. `involved_companies` booleans split developer/publisher roles (one company can be both). Dedup key `('igdb', id)` — **existing 'rawg' rows are untouched and independent**; `rawg.ts` + its IPC channels remain (re-importable if RAWG recovers) but the UI no longer reaches them, so importing a RAWG-era title via IGDB creates a separate row (delete the old one by hand). Tests: tests/igdbImport.test.ts (rawgImport recipe incl. Twitch-token route, role split, TTB fallback vs HLTB, atomicity, quote-strip).

Legacy IGDB imports request company IDs alongside names, and skip a company with no ID so unrelated studios cannot share an `undefined` identity. IGDB and RAWG re-imports keep the stored game length when both their provider fallback and HLTB lack a replacement.

## …and to Steam

**…and to Steam (2026-08-10)** — IGDB lasted three days: registering the Twitch app requires 2FA, and Twitch's SMS enrollment can't reach the user's phone region (+98), so IGDB is unusable for THIS user. `src/main/steam.ts` is the third and current games source — **completely keyless** (Steam storefront API: `storesearch` + `appdetails`, `l=english&cc=US` pinned because `release_date.date` is a LOCALIZED string, parsed by `parseSteamDate`). `GAME.importSource = 'steam'`; `steam:search/import` IPC + `api.steam` + preload; `ImportSourceCfg.key` union widened again. Covers prefer the portrait capsule (`shared.akamai.steamstatic.com/store_item_assets/steam/apps/<id>/library_600x900_2x.jpg` — best-effort, falls back to `header_image` when it 404s). `metadata.metacritic` comes straight from appdetails (already in COMMUNITY_SQL — no SQL change). **Steam has no length data**: HLTB is the ONLY length source (`total_units=COALESCE(?, total_units)` so a miss keeps a hand-entered value) and no cast. **Steam companies are bare name strings** (no ids) → `upsertCompanyByName` dedups case-insensitively against ALL sources, `external_id` NULL. Non-`game` types (dlc/music/demo) are rejected with a friendly error; search drops non-`app` items (bundles). **Metacritic backfill (2026-08-12)**: RAWG's Metacritic sync went stale for 2023+ releases, so `steam.ts:backfillMetacritic` (dialog row for games, `steam:backfillMetacritic`, withActivity) walks game rows missing a score and copies the REAL one from Steam appdetails — `lookupMetacritic` requires an EXACT normalized-name storesearch match (a wrong score is worse than none) and treats a title whose normalization is EMPTY (all-CJK/symbols — `normTitle` keeps only `[a-z0-9]`) as a definitive miss, since ''-vs-'' would "exactly match" any equally-empty store name; definitive misses are stamped `metadata.metacriticChecked` so re-runs skip them (= resumable), throttled 1.6 s/title for appdetails' ~200/5min limit, bails with a resume hint after 10 consecutive network failures. Console exclusives with no Steam page stay unscored — accepted (their RAWG-era Metacritic was still good). The IGDB Settings card was removed (Settings → Keys has NO games row now); `rawg.ts`/`igdb.ts` + their IPC channels + sanitize entries all remain, UI-unreachable. Tests: tests/steamImport.test.ts (date parse, capsule fallback, name-dedup, HLTB-only length, type rejection, atomicity).

`appdetails` can key its answer by an edition's package id instead of the requested app id (`appids=1245620`, Elden Ring, answers under `"2855530"` with `data.steam_appid` 1245620). Every reader goes through `steam.appDetails(payload, appId)`, which accepts the requested key or the entry whose `steam_appid` matches, and never an unrelated entry. Before this, such games failed to import with "Game not found on Steam".

Full Steam re-imports replace the game's developer, publisher and genre links when the corresponding storefront array is supplied. An omitted array leaves existing links alone. Partial Library Refresh requests stop before all child writes and prunes. Non-genre tags and other company roles remain untouched.

## Offline games catalog

**Offline games catalog (2026-08-12)** — console coverage without any API: RAWG's final public dataset (CC0 HF dump `atalaydenknalbant/video-games-dataset`, snapshot 2026-06-27, refreshed weeks before RAWG died) packed into a local SQLite and downloaded once. **The numbers that shaped it**: of ~900k dump rows, ~780k have `added == 0` (shovelware no RAWG user ever tracked) — filtering to `added >= 1` keeps 120,067 real games and turns 4.1 GB into a **57 MB** pack. `scripts/build-games-catalog.cjs` (run via ELECTRON_RUN_AS_NODE electron; streams the JSONL, 2KB description cap) builds `rawg-catalog.db.gz`, published as the **`games-catalog-1` PRERELEASE** asset — prerelease is load-bearing: electron-updater reads `/releases/latest`, which must keep resolving to app releases. App side: `gamesCatalogSchema.ts` (electron-free DDL, drift-guarded against the script's embedded copy by tests/gamesCatalog.test.ts), `gamesCatalogDb.ts` (own file `userData/rawg-catalog.db`, NOT exported, lazy readonly handle, `closeCatalogDb()` in before-quit AFTER closeDatabase), `gamesCatalog.ts` (install downloads the public release asset without a token, streams gzip expansion through independently bounded compressed/uncompressed counters, validates the staged SQLite with `quick_check` + a nonempty game count, then swaps it so a bad replacement cannot destroy the installed catalog; search = contentless FTS5 over name+alt-names ranked `added DESC`, `ftsQueryFor` quotes tokens to neutralize FTS operators; import is the rawg.ts import re-sourced from the local row — **external_source 'rawg' with RAWG ids**, so API-era rows and companies dedup/update instead of duplicating; length = HLTB ?? dump `playtime`; covers from media.rawg.io which OUTLIVED the api — a miss never blocks). **ImportDialog is now multi-source**: `MediaConfig.importSources` renders pill switchers (GAME: Steam + 'Catalog (offline)'); `importSource` stays the primary so every existing gate is untouched; the catalog pill shows an Install panel (with the activity bar) until `rawgCatalog:status` says installed. IPC group `rawgCatalog:search/import/status/install`; `qk.gamesCatalog.status`. Platform slugs render as the result row's format line — the console disambiguator. The dialog's original bulk row moved to the /bulk section (2026-08-12, below) — `gamesCatalog.ts` now exports `listTop`/`buildCatalogQuery` instead of `bulkImport`, and `rawgCatalog:bulkImport` is gone. Games source history: RAWG (dead) → IGDB (Twitch-2FA-blocked) → **Steam (current PC) + this catalog (console/back-catalog)**.

Full catalog re-imports apply the same developer, publisher and genre replacement. Missing or invalid catalog arrays preserve the previous links; an explicit empty array clears its corresponding links. Re-importing is required to update links already saved in the library.

## Imported details (2026-09-27)

An audit of what the sources return but the importers dropped added four things, all in existing tables and columns:

- **AniList tags.** `tags { name rank isMediaSpoiler isGeneralSpoiler isAdult }` on the anime and manga detail queries. Only rank 60 and above, with spoiler and adult tags left out, since the detail page prints tags with no reveal control. They are stored with `tag.category = 'anilist'`. A full re-import replaces the title's links to every importer scope in `tagRepo.IMPORTED_TAG_SCOPES_SQL`, because `tag.name` is unique and a tag another source created first is linked as-is. Genres and uncategorized hand-made tags are never touched. The detail page lists genres before tags.
- **Person bio and birthday.** AniList staff and Japanese voice actors (`description`, `dateOfBirth`) and Open Library authors (`bio`, `birth_date`). The bio is editable on the person page and nothing marks a hand-written one, so imports only fill an empty bio (`COALESCE(bio, ?)`), unlike the usual authoritative re-import. AniList markdown is reduced to plain text by `cleanBio`. Birthdays are partial ISO (`fmtBirthday`, `olBirthday`) and shown as "Born …" in the person header. `peopleRepo.upsert` keeps the stored birthday when the input omits one, because the person page has no birthday field.
- **TMDB collections.** `belongs_to_collection` costs one `/collection/{id}` request, and the other films become `media_relation` rows (`related_source = 'tmdb'`) marked PREQUEL or SEQUEL by release order, with undated parts last, so the existing Related section shows them. The fetch is best-effort: if it fails, the stored relations stay. A movie that has left its collection loses them. Partial refreshes skip the request.
- **Steam store categories.** Player-facing categories from an id allowlist (`STEAM_TAG_CATEGORIES`: play modes, controller support, achievements, Workshop, Remote Play Together) become tags with `category = 'steam'`.

HowLongToBeat moved its search to `/api/search/site` (init returns only `{ token }`, with no honeypot pair). The old `/api/bleed` path returns 404, so every HLTB lookup had been failing silently. `pickBest` now skips results whose `game_type` is not `game`, so DLC or a mod with the same name cannot win the match. `scripts/bulk-import.cjs` ports the HLTB change, the AniList tags (additive, like its genres) and the AniList bio and birthday. It does not port TMDB collections.

## Games catalog v2, Bangumi cast and the games upgrade (2026-10)

The games section lagged far behind anime: Steam has no cast, the RAWG pack's "covers" were RAWG background screenshots cropped into portrait slots, platforms were never stored, and there were no relations or staff. Three keyless sources together approach AniList. The user chose Japanese box art first for every game, Japanese voice actors only, and Metacritic as the only card score.

**Sources.** LaunchBox Games Database (`gamesdb.launchbox-app.com/Metadata.zip`, refreshed daily: 189k per-platform entries, 140k with front box art per region, 31k Japanese, English overviews, companies, genres, alternate names, Steam ids, Wikipedia URLs, images at `images.launchbox-app.com/<file>`). Bangumi (`api.bgm.tv/v0`, keyless with a User-Agent; weekly full dump on GitHub `bangumi/Archive`, no image URLs in it): game characters with images and voice actors, staff, relations, covers. Wikidata: Bangumi subject id (P5732) per item with its English article and Steam app (P1733); only 231 items carry a LaunchBox id, so the bridge runs through a LaunchBox entry's Wikipedia URL or Steam id. Ruled out: IGDB (Twitch two-factor by SMS), MobyGames (paid), TheGamesDB and ScreenScraper (keys by approval), Wikidata as a cast source (about 280 Japanese games), English Wikipedia box art (250-380 px fair-use).

**The pack.** `scripts/build-games-catalog2.cjs` (run with `ELECTRON_RUN_AS_NODE`, about 90 s; inputs: LaunchBox `Metadata.zip`, a Bangumi `dump-*.zip`, optionally `rawg-catalog.db`, and a cached Wikidata query) writes `games-catalog.db.gz` (~60 MB, 148k works), published as the `games-catalog-2` PRERELEASE asset; the app installs it through `catalogRelease.ts`, the same stage-validate-swap path the RAWG pack now uses. Per-platform entries collapse into works: same `titleKey`, then a shared Wikipedia article always joins, a different article never does, otherwise the platform must be new to the work and the years within one (remakes and same-platform re-releases stay apart). A work's id is its smallest member DatabaseID and its media key is `('launchbox', id)`. Box art is ranked Japan, North America, World, Europe, unmarked, then by member release order.

**Matching**, all unique matches (October 2026 numbers). Bangumi: exact title (name or alias, `titleKey`) within a year first — because Wikidata hangs a re-release's Steam id on the base game and would give Persona 5 Royal the original's subject — then Wikidata for what titles could not decide; several subjects claiming one work resolve to the one released that year under the work's own title, else the oldest subject that year. 20,960 works link (30 of 30 sampled correct). RAWG: the full title within a year, a work titled exactly that winning over an edition listing it as an alternate name, then the bare title (`bareTitle` drops edition and year suffixes) only when the full one found nothing, then a second pass with a three-year window for early-access dates. Several RAWG ids may share a work. 45,523 RAWG games join, 94% of the RAWG top 500 and 90% of the top 6,000. The pack also bakes the kana reading and romaji of every person on a linked game (`bgm_person`) and the Latin names of its characters (`bgm_character`); the app reads them through `bakedRow`, which answers null on an older pack rather than failing a cast read.

**Import** (`launchboxCatalog.importWork`). A new title or a `launchbox` row is authoritative: title, Japanese title (`title_original`), overview, date, HLTB length, Metacritic from the RAWG join, companies by name, `genre` tags and `platform` tags (platform names as typed: "PlayStation 4", "PC"). A RAWG-era or Steam row found through `targetFor` (own key, a recorded link, or a RAWG/Steam id the work states) is enriched in place: cover, platforms, Japanese title, the overview for a RAWG row (Steam keeps its store text), a missing Metacritic, and the links; its key, title and date stay. Cover order: every Japanese box, then the Bangumi cover (one request, only when there is no Japanese box), the other boxes, Steam's library capsule. Covers are stored at 1000 px on the long edge (`files.downloadScaledImage`) under their own content-addressed name. `platform` is deliberately not an imported tag scope: Steam and AniList re-imports delete every tag in those scopes.

**Cast** (`gameCast.enrichGame`, through the game's `bangumi` link). Three requests (characters, staff, relations), one transaction. A voice actor counts as Japanese only with a kana reading (in the name or baked/fetched for the person), which leaves out English dubs and kanji-only Chinese dubs; a kanji-only actor missing from the pack costs one cached lookup, at most 40 per game. People go through `personMatch.upsertSharedPerson` (the VNDB matcher, lifted): same source id, else kanji name without spaces through the `idx_person_native_key` expression index, AniList rows first, with romaji allowed only to veto (order, long vowels and repeated spellings folded), else exact romaji, else a new `bangumi` person with the romaji name flipped to given-first. `anilist.upsertPerson` adopts a VN or game person with the same kanji when the romaji does not disagree, so importing the anime later does not make a second person; `scripts/bulk-import.cjs` ports it. Characters are their own `bangumi` rows (romanized, else English, else Japanese name). Staff roles map from a fixed table to `director`/`writer`/`composer`/`staff` with an English note; relations map to SEQUEL, PREQUEL, ALTERNATIVE, SPIN_OFF, PARENT, SIDE_STORY, SAME_SERIES, SAME_SETTING, EXPANSION, COMPILATION, and only between catalog works (`related_source='launchbox'`; `mediaRepo.get` and the quiz franchise grouping resolve them through `media_external_link` too). A re-read replaces only rows with `credit.origin='bangumi'` and `bangumi` characters; unlinking Bangumi by hand removes what it brought (`clearGameCast`). A dialog or bulk import never fails on the cast (`gameLinks.importWithCast` logs and keeps the game).

**The upgrade** (`gamesUpgrade.ts`, /bulk → Refresh → Upgrade games). The plan is a dry run, chunked with event-loop yields: a row's work comes from its own key, a recorded link, the RAWG or Steam id the pack states (several works for one Steam app: the one titled like the row), or a unique exact title within a year; anything else is listed for the user's pick, never guessed. The run is resumable (`metadata.catalogUpgraded` = pack snapshot), cancellable, `TaskKind` `gamesUpgrade`, and shares `libraryJobLock` with bulk import and Library Refresh. Library Refresh then serves linked games from the catalog: the catalog owns their cover (a Steam refresh skips the cover aspect), a full re-import also re-reads the cast, and an unlinked RAWG-era row with only the v2 pack installed is skipped, not failed. Achievements and the Art tab's Steam sources read a linked Steam app too.

**Links panel** (game detail, Characters tab → Sources): the work and Bangumi entry with how each was matched, search-and-pick re-linking (manual links), "Not this game" (a manual unlink: a `manual` row with an empty id that automatic passes respect), and "Let matching decide" (removes the manual row). The cover picker offers the work's box art per region.

**Publishing.** The `games-catalog-2` prerelease must exist before the app's Install button works; until then the dialog and /bulk report the missing release. Rebuild monthly or so: LaunchBox changes daily, Bangumi weekly.
