# Adding features and importers

Moved verbatim from `CLAUDE.md` (2026-10-18). Read this before adding a media type, section or overlay, or before changing an importer.

## Adding features: three flavors

**A) New media type** (fits `media_item`): add to the `MediaType` union in shared/types.ts; create a `MediaConfig` in `src/renderer/src/lib/mediaConfig.ts` and append to `MEDIA_CONFIGS`; add the 4 routes in `App.tsx` pointing at the shared `MediaListPage`/`MediaDetailPage`/`MediaFormPage` with `cfg={…}`. The Archive Broadcast library drawer reads `MEDIA_CONFIGS` through `lib/adaptiveNav.ts`; add any special contextual tab there too. Config flags drive everything: `castLayout`, `hasCrew`, `listTabs`, `hideFromSidebar`, `importSource`, `hasThemes`, `hasLocalReader`, `mediaTabLabel`, etc. The detail page is tabbed with ONE `btn-primary` and Delete in the `ActionMenu`; see [media-types.md](media-types.md) "Detail page tabs". Optional importer: see Import conventions for the template.

**B) Standalone section** (Japanese/Music/Lists style): full vertical slice — tables (init.sql + schema.ts), repo, IPC block, api.ts group, preload mirror, pages + routes in App.tsx, drawer + contextual entries in `lib/adaptiveNav.ts`, `qk.<feature>` query keys, tests. `music_*` (2026-07) is the newest complete reference.

**C) Curated overlay** (Franchises, 2026-08, cross-media since 2026-10): hardcoded content in a `src/shared/<feature>/` module (frozen id strings, one file per unit + an index catalog — the `wrestling.ts`/`programming/` pattern), matched client-side against the existing media types' lists; no new tables, user state rides existing ones (a settings row per franchise for the user's background). Reference: [media-types.md](media-types.md) "Franchises" — the curated-remote-art cache, the viewport-pinned background shared with the per-media Art-tab background, and the FLIP re-sort hook. **History** (2026-10) is the scaled-up form: one file per entity under `src/shared/history/content/`, collected by `import.meta.glob` and loaded lazily in main only, with its own personal-layer tables — see [history.md](history.md).

## Import conventions

- **Two-phase atomic**: ALL network work first (API calls + `downloadImages` batch prefetch), then ALL DB writes inside ONE `db.transaction()`. Upsert helpers are synchronous and take pre-downloaded image paths.
- Dedup by `(external_source, external_id)`. **Re-import is authoritative**: refreshes canonical fields, prunes removed children, but preserves personal tracking (status/score/progress) via COALESCE.
- **Re-import to apply**: changes to import logic/ordering only affect existing titles after the user re-imports them — always say so.
- `fetchWithRetry` (http.ts) handles 429/5xx **and applies a per-attempt timeout** (default 30s, `timeoutMs` option) so a stalled host can't hang an import + the activity pill. 429 waits are bounded by `MAX_RATE_LIMIT_WAITS` only and must NOT consume the 5xx/network retry budget (tests/http.test.ts). Callers pass `timeoutMs`, never a fixed `signal: AbortSignal.timeout(…)`; task cancellation is the internal `taskSignal`, composed with a fresh timeout on every attempt and inherited from `withActivity` through `AsyncLocalStorage`. `downloadImage`/`downloadAudio` route through it; `downloadImages` runs a 5-worker pool (keep per-image `imageProgress` reporting intact). AnimeThemes needs a User-Agent header (403 otherwise); every Wikipedia, Wikidata and Commons request sends `WIKIMEDIA_USER_AGENT` (`@shared/wikimediaAgent`) and asks only for Wikimedia's standard thumbnail widths, or the whole IP is limited to 10 requests a minute and other widths are refused. `fetchWithRetry` enforces both halves of the budget centrally (`tests/http.test.ts`): it sets that agent on every request to those hosts, image downloads included, and spaces every attempt through the one process-wide `wikimediaThrottle`; do not add per-feature Wikimedia slots, and store image URLs through `stripWikimediaTracking` so the content-addressed file names stay stable; MusicBrainz-style 1 rps sources get their own throttle. AniList requests are spaced by the one process-wide `anilistThrottle` inside `anilist.gql`, Hardcover's by `hardcoverThrottle` inside `hardcover.gql` and Open Library's by `openLibraryThrottle` inside `olGet`; do not add per-caller delays for those sources. Bulk import and Library Refresh share one run slot (`libraryJobLock.ts`).
- Whole-body API consumers pass `maxResponseBytes` to `fetchWithRetry` (normally `MAX_API_RESPONSE_BYTES`, 32 MiB). Large binary assets stream through `streamResponseToFile` with feature-specific input/output caps; do not turn them back into `arrayBuffer()` downloads.
- yt-dlp args must keep the `--` before the user URL (option-injection guard, enforced by tests/musicUrlAcquisition.test.ts). ffmpeg has no `--`, so it uses `assertSafeArgPath` **and** a `file:` prefix on every path.
- **Copy `steam.ts`** as the importer template (smallest complete current example — keyless, two-phase, HLTB length) or `openlibrary.ts` (string ids, best-effort endpoints). **Not `rawg.ts`** — that API is dead; the file survives only so RAWG-era rows stay re-importable.
