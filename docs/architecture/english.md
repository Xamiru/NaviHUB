## English dictionary

**English dictionary (2026-07-29)** — `/english` (Learn section, one page): English→English lookup via **dictionaryapi.dev** (no key) in `src/main/english.ts` — pure `parseEnglishEntries` (fixture-tested) + `lookup` through `fetchWithRetry` (`timeoutMs: 15s, rateLimitWaits: 0`; **404 = unknown word = `[]`, anything else throws** so the QueryCache toast fires — the deliberate opposite of jisho.ts's swallow-everything). Saving a definition writes `en_word` (word, phonetic, pos, meaning, example) via `englishRepo.saveWord` — **idempotent on exact (word, meaning)**, returns the existing id — and the saved list renders on the same page from ONE unfiltered `qk.english.words('')` query (saved-state chips + client-side filter both read it; the repo's LIKE search exists but the renderer doesn't use it). Deliberately NOT part of the jp SRS ("save it for me, just that"). `en_word` is personal → wiped in sanitizeSql.cjs.

## Offline English dictionary

**Offline English dictionary (2026-08-01)** — the online API is now the FALLBACK: `english.ts:lookup` tries `lookupOffline` first when a bank is installed (mirroring `dict/lookup.ts:lookupWord`), and `EnDictEntry.source` (`'offline' | 'online'`) badges the difference in the UI. The data lives in the EXISTING `dictionaries.db` (dict/init.sql + `sweepOrphans` + the version-bump DROP list, all extended) as `en_dict` registry + `en_lemma` / `en_synset` / `en_exc` / `en_pron`. `src/main/dict/wordnet.ts` imports **WordNet 3.0** (one 10.7 MB zip from nltk_data — it is the only mirror that ships the `*.exc` morphology files; the npm `wordnet-db` package does NOT) plus **CMUdict** for IPA, both pinned to a commit sha (KanjiVG precedent; nltk's gh-pages and cmudict's master both move). It reuses importer.ts wholesale — `runImport` (the single global gate), `downloadToTemp`, `openZipReader`, `setImportPhase`/`setImportProgress` — so progress renders through the same polled `dict:importStatus` (two new phases `english`/`pronunciations`) and the two dictionary cards share one busy state. Same stage-then-swap discipline as sentences.ts: everything under a fresh `bank_id`, registry row LAST, catch deletes the staged rows. **`importWordNetText(files, cmuText)` is the seam** — tests drive the real SQL from real-format fixture slices with no network or zip. Parsing is hand-rolled and fixture-tested: WordNet's index (offsets are the sense order — that's why the index files are kept rather than deriving lemmas from the data files), data (HEX word counts, `(a)`/`(p)` markers stripped, `s` satellites stored as `a`), the exception lists, and ARPABET→IPA. Lookup candidates = the word + `en_exc` hits (ran→run) + `morphyCandidates` (WordNet's suffix rules, over-generating on purpose like deinflect.ts). Per-definition synonyms are the rest of that synset; meaning-level synonyms are deliberately EMPTY offline (unioning them across senses claims a mouse is both a rodent and a black eye). Verified against the real full data: 155k lemmas / 118k synsets / 126k prons, ~10s import, 30 MB, 1-8 ms lookups. Settings → **Dictionaries** (the `japanese` tab, relabelled; key unchanged) holds both cards.

## English tests + SRS

**English tests + SRS (2026-08-02)** — the English section became a full LEARN vertical: `/english` is now a HUB (JapaneseHomePage pattern; the dictionary moved to `/english/dictionary`, CommandPalette + Sidebar NavGroup updated), with SRS review, four test pages and LLM-graded writing. Test-first by design — the user (assessed strong-B2/C1 from their own chat corpus) wanted tests, not courses; weak spots are spelling/punctuation/articles/confusables/register, which is what the mechanics drill targets. **SRS: `en_word` IS the deck** — the same 8 SRS columns as jp_card (init.sql + schema.ts + **8 ensureColumns**; the old "deliberately not SRS" note is superseded), so every dictionary/mining save enters as a 'new' card with zero changes to the save paths; `en_review_log` mirrors jp_review_log; `englishRepo.submitReview/reviewQueue/srsStats/saveWords` port japaneseRepo verbatim (fresh queue drains FIFO by save order — saving = opting in); `/english/review` is the JapaneseReviewPage port minus typed mode. **Vocab/spelling misses AUTO-SAVE into the deck** (`english:saveWords` batch, band sources only — myWords are already there), reported as "N added to your review deck". **Frequency pack** (`dict/enFreq.ts`, kanjium recipe): hermitdave/FrequencyWords en_50k sha-pinned → `en_freq_set`/`en_freq` in dictionaries.db (sweepOrphans + DROP list + dictSchemaSync `registries` all extended); rank = position AFTER filtering to `/^[a-z][a-z'-]*$/`. Bands in `englishDrills.ts:EN_BANDS`: upper 4-10k / advanced 10-25k / rare 25-50k; **ranks <4k are never quizzed** (C1 reader). Pools (`src/main/englishDrills.ts`, jpDrills pattern): band SQL joins `en_freq`×`en_lemma`, resolves FIRST sense via `offsets[0]` batch-load, filters by pure `quizzableCandidate` — the proper-noun check MUST read `en_synset.words` (case preserved) because `en_lemma.lemma` is lowercased at import; distractors = same-POS nearest-rank with jitter; `buildVocabPool` takes an injectable rng for tests. Synonyms mode needs synset data → silently falls back to word2def for myWords. **Content is code** (`src/shared/english/`: 12 C1/C2 passages ≈250-450 words, ~100 mechanics items keyed `<category>-<nn>`, 14 writing prompts; keys FROZEN; tests/englishContent.test.ts validates incl. answer-position distribution) — reading/mechanics pages are client-side pools (ProgrammingQuizPage skeleton), spelling imports `TypedDrill` directly (misses recorded inside each item's `accept()`, the one call site per submission). QuizKind += `englishVocab englishSpelling englishReading englishMechanics`; checklist gained detected source `enReviews` (distinct `en_review_log.word_id`, item `english-reviews`, NOT seeded). **Writing** (`/english/writing`): `src/main/llm.ts` now holds the provider plumbing EXTRACTED from gachaCoach.ts (`resolveProvider/coachModel/makeGemini/makeAnthropic/friendlyError` + new one-shot **`completeOnce({system,prompt,maxTokens})`**; gachaCoach imports from it, importDoc refactored onto it; same `coach.*` settings keys, NO new ones). `englishWriting.ts`: pure `buildFeedbackPrompt` (examiner persona naming the user's weak spots, strict one-JSON-object contract) + fixture-tested `parseFeedback` (fence-strip, first-{-to-last-}, clamp scores 0-10) → `en_writing` row (submission + feedback JSON + rubric-mean score). **Plain await over IPC on purpose** (importDoc precedent — a submit needn't survive navigation; no status object). Corrections render as custom rows (Markdown.tsx has no tables); modelRewrite/overall go through `components/Markdown.tsx`. Personal → sanitizeSql wipes `en_review_log`/`en_writing` (children before en_word). Settings → Dictionaries: the English card gained the frequency PackRow (shared busy gate unchanged). Tests: englishSrs, englishDrills (real SQL both DBs), enFreqImport, englishWriting, englishContent + extended dictSchemaSync/exportSanitize/checklist.
