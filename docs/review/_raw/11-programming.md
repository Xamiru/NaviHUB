## Questionable / ambiguous questions

### Systemic: the correct answer is the longest option

Measured exhaustively across all 219 `ProgQuestion`s in `PROG_COURSES` (script: loaded the real module via esbuild, compared each option's string length): **the marked-correct option is the strict longest of the four in 169/219 questions (77%)**. Per-course:

| course | longest-is-correct | rate |
|---|---|---|
| docker | 27/30 | 90% |
| git-internals | 28/33 | 85% |
| regex | 22/28 | 79% |
| shell-scripting | 25/34 | 74% |
| go-from-python | 48/65 | 74% |
| sql | 19/29 | 66% |

This is exactly the giveaway the task brief warns about: a test-taker who has never read a line of the lesson can score well above chance by picking "the option with the most qualifying clauses." It isn't automatically wrong content (a precise, correct answer often *needs* more words than a punchy wrong one — see `errors#3` below, where the correct option genuinely is the only one that states the actual mechanism), but at 77% it stopped being incidental lesson-by-lesson and became a house style the test-writing process leans on. A handful of the starkest examples (short blunt distractors vs. one long qualified correct option):

- `goCourse.ts:74-81` — "Where do a Go project's pinned dependency versions live?" — correct option is 54 chars; the three wrong options are 32-35 chars.
- `goCourse.ts:483-491` — "What is wrong with logging an error AND returning it?" — correct is 84 chars (the only option with a full causal clause); distractors are 23-33.
- `goCourse.ts:951-959` — the nil-interface trap question — correct is 93 chars vs. a 9-char "It panics" distractor that's trivially eliminable by shape alone, not just length.
- `dockerCourse.ts:677-685` — "Why should secrets not be passed as ENV?" — correct 101 chars, shortest wrong option 38.
- `sqlCourse.ts:733-741` — "Why is INSERT OR REPLACE dangerous..." — correct 94 chars vs. 47 shortest.
- `shellCourse.ts:803-811` — "Why check dependencies with command -v curl rather than which curl?" — correct is 127 chars (by far the longest of any option in the catalog) vs. a 28-char distractor.

Fix is mechanical, not content-level: pad the wrong options to comparable length/qualification (or trim the correct one), independent of any correctness edit.

## The drill's actual learning value

`CliPracticePage.tsx` prompts with `current.desc` (the plain-English task) and requires typing `current.cmd` (or any listed `answers[]` spelling), checked **on every keystroke** (`onType`, `cheatsheets.ts` `normalizeCmd`): the moment what's typed is no longer a prefix of *any* accepted answer, it goes red and stays red (`miss()` sets `wrong=true`, and the canonical answer (`answers[0]`) is revealed immediately underneath the input — not gated behind pressing Enter). So the exercise genuinely is desc → cmd recall, not "type what's on screen": nothing shows the target text before you've either gotten it right or already failed.

Two design details shape what actually gets reinforced:

- **Requeue is asymmetric.** If you self-correct after a miss (keep typing until it matches), `onType` advances with `advance(false)` — **no requeue**. Only an explicit Enter-to-skip while `wrong` (`onEnter` → `advance(true)`) reinserts the item at queue positions 3 and 13. So a fumbled-but-finished answer is scored as a miss but never comes back for spaced practice, while a "I have no idea, skip" genuinely does — the item that most needs reinforcement gets it, the merely-mistyped one doesn't. Reasonable if misses-that-get-finished are usually typos; indistinguishable from "didn't know the flag order" in the data actually collected.
- **The reveal-then-requeue loop can teach "copy what I just saw" instead of "recall from the description."** Because the correct answer is flashed in red immediately on a miss, and the same item resurfaces within the next 3-13 questions, a long single session can degrade into short-term echo rather than durable desc→cmd recall — the interval is short enough that the prior reveal is still in working memory. This is a real tradeoff of the "endless dojo" pattern borrowed from `KanaDrill`; kana glyphs are memorized through exactly this kind of tight-loop repetition, but CLI flags are lower-frequency/higher-entropy targets where a longer interval (or actual spaced repetition) would likely stick better.

Comparison: `ProgrammingQuizPage.tsx`'s "Which command?" mode (`commandQuestions`, line 76) inverts the direction — prompt is still `desc`, but you *recognize* `cmd` among 4 options rather than *produce* it. Recognition is a weaker test of recall than typing (matches the CLAUDE.md-documented intent of the two modes existing side by side), and per the systemic MCQ finding above, recognition is further weakened by the fact that the correct option is very often typed differently in the codebase catalog (not applicable here, since `commandQuestions` options are literal `cmd` strings, not prose — so the length-giveaway pattern found in course questions does **not** transfer to this mode; its own weakness is the tmux distractor-shape issue documented above).

Net: for the *typing* drill specifically, yes — it tests real desc→cmd recall, more rigorously than most "flashcard" apps, with the one caveat about requeue asymmetry and reveal-then-return timing above.

## What's missing

Grounded in what already exists and is already being computed, just discarded:

1. **The CLI drill already computes a per-session `missed` set (`CliPracticePage.tsx:112`, `Set<string>` of `current.cmd`) and shows it at the end — and then throws it away.** The smallest change that makes repeat visits worth having: persist miss counts per `sheetKey`/`cmd` (one new small table, or fold into `prog_progress`-style rows) and bias `shuffle()`/`practicePool()` selection toward historically-missed entries. No new UI concept needed — it's the same data already on screen at the "Stop" summary.
2. **`quiz_session.settings` is written and never read back**, for both `kind:'programming'` (`{mode, courseKey, sheetKey, length}`, `ProgrammingQuizPage.tsx:190`) and `kind:'cli'` (`{sheets}`, `CliPracticePage.tsx:49`). `QuizRecord` only ever surfaces aggregate score/streak. The data to show "you're weakest on Docker networking" or "you keep missing `git` commands" is already persisted, one row per round — nothing currently queries it.
3. **`prog_progress` is a boolean per lesson** (`programmingRepo.ts` — `complete`/`uncomplete`/`progress`, no score column at all). A lesson's own end-of-lesson questions are self-check only (per `ProgLessonPage`, matching the CLAUDE.md note "self-check only, nothing logged") — there's no signal anywhere that ties "marked complete" to "actually got the questions right," so a lesson can be marked done after guessing through it once.
4. **No link from a quiz miss back to its source lesson.** `courseQuestions()` already carries `context: \`${c.title} · ${l.title}\`` (`ProgrammingQuizPage.tsx:62`) — the lesson identity is right there in the question object — but the summary screen doesn't surface "you missed 3 questions from *Interfaces: duck typing, checked* — review it" as a Link. Wiring the existing `context` string to a `progLessonKey`-based route would close the loop cheaply.

None of these need new tables beyond maybe one small miss-counter table; #2 and #4 are pure read-side additions over data that's already being written today.

## Test coverage gaps

`tests/programming.test.ts` validates, and only validates:

- **Structure**: unique kebab-case course/lesson keys; non-empty titles; every course has ≥1 lesson; lesson keys unique and kebab within a course.
- **Markdown well-formedness**: non-empty body, balanced ``` fences (even count), and that the real `parseMarkdown` produces ≥1 block — i.e., it won't crash the renderer, says nothing about whether the prose inside is true.
- **Question shape**: exactly 4 options, `correct` index in `[0,4)`, and the 4 option *strings* are pairwise distinct (`new Set(...).size === 4`) — catches literal duplicate text, not "two options that are both defensibly correct for this input" (the `archive.tar.gz` case above has 4 distinct strings and passes this check fine) and not the longest-option giveaway (never measured).
- **Cheatsheet shape**: unique kebab sheet keys, non-empty entries/`cmd`/`desc`; if `answers` exists it's non-empty; `practicePool()` only returns answer-bearing entries, correctly filtered by sheet; every stored answer is already in `normalizeCmd()`-canonical form. It does **not** check that an accepted answer, if actually executed, does what `desc` claims — which is exactly the failure mode of all seven cheatsheet rows above.
- **DB/repo**: idempotent `complete`, rejection of lesson keys absent from the catalog, harmless `uncomplete` of an unknown key.

What it structurally cannot catch, by design (it never imports a shell, an interpreter, or a fact-checker): a factually wrong but well-formed prose claim (the Go 1.22 regex claim, the `go build ./...` claim), a `correct` index pointing at the wrong option, an MCQ answerable without reading the lesson because of option-length asymmetry, or a cheatsheet `answers[]` entry that's syntactically a string but semantically a different command. Every error found in this review passes every existing test.

## What's genuinely good here

- The SQL course's dialect-specific version claims (`FILTER` since 3.30, `STRICT` tables since 3.37, `RIGHT`/`FULL JOIN` since 3.39, `MATERIALIZED` CTEs since 3.35, `->`/`->>` since 3.38, the `FLOATING POINT` → INTEGER-affinity footgun, `WHERE`-alias leniency) all check out **exactly** against the app's own bundled SQLite 3.49.2, verified by actually running them — a genuinely rare level of rigor for hand-written course content (`sqlCourse.ts`, several lessons).
- `dockerCourse.ts` and `gitCourse.ts` read like they were written by someone who has actually debugged these tools at 3am: the shell-form-CMD-eats-SIGTERM chain, the `ON`-vs-`WHERE` outer-join trap, the typed-nil-interface gotcha, the stash-is-a-merge-commit internals — all correct and all the kind of thing that actually bites.
- `shellCourse.ts`'s `set -e` exception list (checked contexts, function-in-a-checked-context, `((count++))` at zero, `var=$(cmd)` vs `echo "$(cmd)"`) was verified live in bash and is correct in every particular, including the exit-code details.
- The regex course's flavor-comparison discipline (Go/RE2 has no backreferences or lookaround, Python vs. PCRE lookbehind width restrictions, the `\A`/`\Z`/`\z` table) is accurate everywhere except the one Go named-group claim flagged above — a strong track record for content that's inherently easy to get subtly wrong across four language flavors in one lesson.
- The typed CLI drill's per-keystroke red-and-stay plus immediate-reveal design is a genuinely defensible recall mechanic (not a "type what you see" exercise), and its `3`/`13` requeue plus endless-until-Stop loop is a deliberate, well-executed port of the kana dojo pattern into a very different content domain.
