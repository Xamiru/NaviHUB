## Rule repair and transfer

`/english/repair` adds a small offline teaching layer without replacing the advanced test-first tools. Twelve authored units in `shared/english/remediation.ts` teach specific article, punctuation, clause-boundary, confusable, register and spelling rules. Each includes a worked example, two guided items, two different delayed prompts, and a writing task with a self-review checklist. Exact-answer results are narrow checks; the writing record is explicitly self-assessed and does not invoke an LLM.

The writing mistake ledger links to a category's repair units. Mechanics rounds retain the exact missed item keys in the personal `learning.evidence.v1.english.mistakes` setting; the Home queue and summary link those items to repair while displaying the original prompt, answer and explanation. Rule suggestions are heuristic, labelled as suggestions, and can be changed. A later correct first response clears the item; repeated post-reveal answers in the same round cannot erase a miss. `?weak=1` retests the saved items without repeating within that round, and `?category=` seeds a focused round. Interrupted rounds that never reach End are not added to this queue.

Shared `LearningPractice` tracks guided/assisted versus delayed evidence, reserves exposure before showing cold prompts and labels repeats honestly. `LearningProject` saves the learner's written work and checklist separately. All evidence uses the sanitized `learning.evidence.v1.` settings prefix. Existing provider-graded full writing tasks remain unchanged and still require the configured provider; the repair layer itself works offline.

## English dictionary

**English dictionary (2026-07-29)** — `/english` (Learn section, one page): English→English lookup via **dictionaryapi.dev** (no key) in `src/main/english.ts` — pure `parseEnglishEntries` (fixture-tested) + `lookup` through `fetchWithRetry` (`timeoutMs: 15s, rateLimitWaits: 0`; **404 = unknown word = `[]`, anything else throws** so the QueryCache toast fires — the deliberate opposite of jisho.ts's swallow-everything). Saving a definition writes `en_word` (word, phonetic, pos, meaning, example) via `englishRepo.saveWord` — **idempotent on exact (word, meaning)**, returns the existing id — and the saved list renders on the same page from ONE unfiltered `qk.english.words('')` query (saved-state chips + client-side filter both read it; the repo's LIKE search exists but the renderer doesn't use it). Deliberately NOT part of the jp SRS ("save it for me, just that"). `en_word` is personal → wiped in sanitizeSql.cjs.

## Offline English dictionary

**Offline English dictionary (2026-08-01)** — the online API is now the FALLBACK: `english.ts:lookup` tries `lookupOffline` first when a bank is installed (mirroring `dict/lookup.ts:lookupWord`), and `EnDictEntry.source` (`'offline' | 'online'`) badges the difference in the UI. The data lives in the EXISTING `dictionaries.db` (dict/init.sql + `sweepOrphans` + the version-bump DROP list, all extended) as `en_dict` registry + `en_lemma` / `en_synset` / `en_exc` / `en_pron`. `src/main/dict/wordnet.ts` imports **WordNet 3.0** (one 10.7 MB zip from nltk_data — it is the only mirror that ships the `*.exc` morphology files; the npm `wordnet-db` package does NOT) plus **CMUdict** for IPA, both pinned to a commit sha (KanjiVG precedent; nltk's gh-pages and cmudict's master both move). It reuses importer.ts wholesale — `runImport` (the single global gate), `downloadToTemp`, `openZipReader`, `setImportPhase`/`setImportProgress` — so progress renders through the same polled `dict:importStatus` (two new phases `english`/`pronunciations`) and the two dictionary cards share one busy state. Same stage-then-swap discipline as sentences.ts: everything under a fresh `bank_id`, registry row LAST, catch deletes the staged rows. **`importWordNetText(files, cmuText)` is the seam** — tests drive the real SQL from real-format fixture slices with no network or zip. Parsing is hand-rolled and fixture-tested: WordNet's index (offsets are the sense order — that's why the index files are kept rather than deriving lemmas from the data files), data (HEX word counts, `(a)`/`(p)` markers stripped, `s` satellites stored as `a`), the exception lists, and ARPABET→IPA. Lookup candidates = the word + `en_exc` hits (ran→run) + `morphyCandidates` (WordNet's suffix rules, over-generating on purpose like deinflect.ts). Per-definition synonyms are the rest of that synset; meaning-level synonyms are deliberately EMPTY offline (unioning them across senses claims a mouse is both a rodent and a black eye). Verified against the real full data: 155k lemmas / 118k synsets / 126k prons, ~10s import, 30 MB, 1-8 ms lookups. Settings → **Dictionaries** (the `japanese` tab, relabelled; key unchanged) holds both cards.

## Use of English, mechanics games, idioms, deck hygiene (2026-08-15)

**Deck hygiene** — `/english/deck` (`pages/EnglishDeckPage.tsx`): every saved word with its OpenSubtitles frequency rank (`src/main/englishDeck.ts:deckOverview` joins `en_word` with `en_freq` in JS, `englishDrills.ts` pattern; pure `attachRanks`; no pack → all ranks null and the page says so), SRS state, lapses; filter pills All / Due / Leeches / Rarer than 10k-25k-40k / Unranked, sort pills, debounced search, per-row Remove, and a bulk `btn-danger` "Remove the N shown" behind `confirmDialog` → `english:removeWords(ids)` (`englishRepo.removeWords`, chunked IN, `en_review_log` cascades). `englishRepo.listLeeches` = `lapses >= LEECH_LAPSES` (no learning-step counter — saved words are not lessons). Channels `english:deck | listLeeches | removeWords`; `qk.english.deck/leeches`. Deliberately manual — nothing auto-prunes. **Use of English** — `/english/use` (`pages/EnglishUsePage.tsx`), one page with Format pills (Open cloze / Word formation / Transformations) + Length 10/20/Everything, over three content modules with FROZEN keys: `src/shared/english/cloze.ts` (`EnClozeItem`, one sentence + one `___`, function-word answers), `wordFormation.ts` (`EnWordFormItem`, STEM in caps → derived form, `negative` flag), `transformations.ts` (`EnTransformItem`, original + KEYWORD + gapped, 3-6-word answers with contraction/word-order variants). Matching is `@shared/english/answers.ts` (`normalizeAnswer` NFKC/lowercase/curly quotes/edge punctuation, `expandContractions` for the unambiguous n't/'ll/'re/'ve/'m only — 'd/'s stay listed as variants, `matchesAnswer`, `wordCount`). **Mechanics games** — three routes under `/english/games/*`, hub Section "Games", palette rows:
- *Punctuate it* (`EnglishPunctuatePage.tsx`, kind `englishPunctuate`): pure model `@shared/english/punctuate.ts` — `tokenize(answer)` (whitespace tokens; internal marks `, ; :` and a SPACED em dash belong to the previous token; terminals `. ? !` stay visible and ungraded; `[,]` = optional comma; `bare` = the word without apostrophes), `strip`, `apostropheVariants(bare)` (auxiliary n't, pronoun contraction whitelist, `s`-final → `'s`/`s'`, o'clock/ma'am/y'all — the ONLY solvable apostrophes, so `tests/englishPunctuate.test.ts` asserts every apostrophe word in every item is reachable and that `render(tokens, answerState)` round-trips), `cycleMark`, `cycleApostrophe`, `grade` → `{targets, hits, extras, pct, allCorrect, slots}`. Page: click a gap to select/cycle, click a word to cycle its apostrophe, keys `, ; :` `-` Space `'` ←/→ Backspace, Enter grades then advances; logs score = items fully correct. Content `punctuateItems.ts` (48, `EnPunctuateItem`, focus splice/apostrophe/introductory/list/relative/mixed).
- *Spot the error* (`EnglishSpotErrorPage.tsx`, kind `englishSpotError`): `spotErrors.ts` (`EnSpotErrorItem {tokens, wrongIndex|null, fix|null, category}`, ~1 in 8 no-error); tokens as inline buttons + "No error" (key 0 / n), ←/→ + Enter; weighted by `errorTally` when Focus = everything through the extracted pure `@shared/english/weightedDeck.ts:weightedOrder` (Efraimidis-Spirakis, every item once — `EnglishMechanicsPage.orderDeck` now calls it too).
- *Collocation match* (`EnglishMatchPage.tsx`, kind `englishMatch`): `collocations.ts` (`EnMatchSet`, exactly 6 pairs, themes verb-noun / adjective-noun / phrasal-verb / preposition; `tests/englishGames.test.ts` checks lefts/rights distinct, no string on both sides, no pair reused across sets — the semantic "exactly one right per left" is the author's job); lefts ordered, rights shuffled, click or keys 1-6, wrong = 400 ms flash + miss; score = pairs matched first try.

**Content depth** — `passagesSet2.ts` (+12 → 24 passages, C1/C2) and `mechanicsSet2.ts` (+100 → every category ≥ 30, so a 20-question round never repeats an item — the pigeonhole the review named), spread into `EN_PASSAGES`/`EN_MECHANICS` (`SET1` + set 2). `idioms.ts` (`EnIdiom`, 76 idioms + 76 phrasal verbs, C1/C2 register, meanings distinct) is the vocab quiz's new source "Idioms & phrasals" (sub-pills Both/Idioms/Phrasal): the pool is built client-side by pure `idiomPool.ts:buildIdiomPool` (mirrors `EnVocabQuestion`, distractors = three other same-kind meanings), synonyms mode falls back to word2def, `bandBlocked` ignores it, and misses auto-save into the deck as `{word: phrase, pos: 'idiom' | 'phrasal verb'}`. `tests/englishContent.test.ts` gained the post-set-2 volume block; `englishIdioms.test.ts` guards the bank + pool.
