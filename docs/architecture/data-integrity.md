# Data, files and integrity rules

Moved verbatim from `CLAUDE.md` (2026-10-18). Read this before any delete, prune, partial refresh, re-import, scanner, progress write, image override, folder move or stored key change. Breaking one of these silently corrupts or loses library data.

## Local files & images

Custom privileged `navimg://` protocol serves everything (images, audio, manga pages incl. streamed CBZ entries, EPUB spine XHTML/images, video). DB stores **relative paths with virtual prefixes**; only `src/main/files.ts:absoluteMediaPath()` maps prefix → real dir (and blocks `..`). This table is the whole list — keep it complete when a root is added:

| Prefix | Resolves to |
|---|---|
| `media/…` | `media.dir` setting, default `userData/media` (`files.mediaRoot()`) — downloaded covers, content-addressed `dl-<sha1(url)>` via `downloadImage`; hand-picked images in `media/picked/` |
| `audio/…` | `audio.dir` setting — anime theme songs |
| `manga/…` | `manga.dir` setting |
| `books/…` | `books.dir` setting — local EPUBs (reuse the manga machinery) |
| `music/…` | `music.dir` setting |
| `pictures/…` | `pictures.dir` setting — wallpapers/fan art, human-readable layout, deliberately NOT content-addressed. Pinned at startup (existing folder kept, fresh libraries in the OS Pictures folder) |
| `video/…` | `video.dir` setting — local anime episodes, and movies/TV while their own roots are unset |
| `movies/…` | `video.movieDir` setting, falling back to `video.dir` — linked movie files |
| `tv/…` | `video.tvDir` setting, falling back to `video.dir` — linked TV episodes |
| `wrestling/…` | `wrestling.dir` setting — local PPV rips |
| `football/…` | `football.dir` setting — local clips, highlights, full matches, interviews and documentaries |
| `history/…` | `history.dir` setting, default `userData/history` — History archive files the user attached (copied in) or downloaded from a research suggestion, one folder per entity |
| `jpaudio/…` | always `userData` — mining clips, minimal pairs, Tatoeba audio |
| `ttscache/…` | always `userData/ttscache` — content-addressed Open JTalk voice clips (`src/main/tts/`), regenerable and deliberately outside `jpaudio/` so library backups never carry them. The voice pack itself is `userData/openjtalk/`, which nothing serves |
| `videocache/…` | always `userData/videocache` — extracted subtitle tracks + legacy converted copies |
| `thumb/<w>/…` | generated cover thumbnails (`userData/thumbs`, `src/main/thumbs.ts`) — disk-cached downscaled JPEG of a stored image (PNG when the source has transparency, so crests and logos keep their background), built on first request from `media/` or `pictures/` (`THUMB_SOURCE_PREFIXES`; `pictures/` names are reusable, so their cache key includes mtime and size); small cover slots and the Gallery use `CoverImage thumbWidth` so grids don't decode full-resolution sources. Missing/undecodable source 404s and the `<img>` falls back to the original |
| `open/<token>` | the ONE stateful branch — a process-lifetime `Map<token, absPath>` for "open any file" |

`slideshow.dir` (default `<pictures.dir>/Slideshow`) is deliberately **absent from that table**: it holds flat COPIES of Art-tab images for the Windows desktop slideshow and nothing in the app ever displays them, so it needs no prefix and no `absoluteMediaPath` branch.

Renderer builds URLs synchronously with `mediaUrl(relPath)` (no per-image IPC); `<img>` onError handles missing files (`CoverImage.tsx`). Settings are rows in the `settings` table (`settingsRepo.get/set`), surfaced in `SettingsPage.tsx`. Cached cover widths come from shared `THUMB_WIDTHS` in `mediaUrl.ts`, used by both `thumbUrl` and the protocol parser; `thumbUrl` rounds small requests up to a supported width and uses originals above the cache range. Keep Installed's long cover grid at 320 px and recent covers at 480 px so scrolling does not decode full-size artwork.

Provider secrets keep their existing setting keys but are stored as versioned Electron `safeStorage` envelopes (`src/shared/secretSettings.ts` → `src/main/secretStorage.ts`). Startup initializes the asynchronous OS-backed provider after `app.ready`, migrates legacy plaintext rows in place, and installs a process-memory reader behind `settingsRepo.get`; provider modules must use that reader and never query secret rows directly. `settings:all` strips secret keys completely. The renderer learns only configured/unreadable state and the protection backend through `settings:secretStorage`; inputs are always blank and support explicit replace/clear. Linux `basic_text` is reported as weak rather than described as secure. Headless scripts cannot use Electron safeStorage: accept a task-specific environment value and never write a plaintext secret back to the DB (`bulk-import.cjs` is the reference).

### Data-integrity rules that are easy to miss

- **`video:markWatched`'s `logProgress` call is guarded on `scope.id === 'video'`.** A wrestling row's owner is an EVENT id; logging it would silently advance whatever `media_item` shares that number.
- **`syncMediaProgress` returns early for `book` media** — books track pages, so finishing an EPUB volume must never slam `progress` down to a volume count.
- **`syncMediaProgress` is deliberately absent from the video path** — it floors progress at the highest watched episode number, which would undo a rewatch wrap the moment `logProgress` started one.
- **The in-app video player plays files directly and never converts them.** No remux/transcode tier and no `video_cache` writes (it was removed once for exactly that). `decideDecodable` in `video/playability.ts` refuses what Chromium cannot decode, and the page's watchdog catches the failures Chromium never reports (a blank HEVC picture, zero decoded AC3/DTS audio), so a file never plays black or silent; every file stays one action from the system player through `video:openExternal`. The `/watch/:kind/:id` kinds `file`/`wrestling`/`clip`/`football` are frozen. Styled ASS subtitles (jassub/libass, WASM in a worker) load only by dynamic import from `StyledSubtitleLayer.tsx`, guarded by `tests/performanceBoundaries.test.ts`.
- **`video:markProgress` writes `resume_seconds` only and never logs progress.** The watched transition (`video:markWatched`, from the list or the player's `ended`) is the one progress write.
- **Scanners that prune by "not seen" need a zero-file guard** — `music.startScan` and `manga.rescan` refuse a zero-file walk when rows exist, so an unmounted drive cannot wipe playlists, likes and play history. Music also aborts before writes on any directory-read or audio-stat failure: a partial walk must never become a complete snapshot for pruning.
- **Music links live in `media_music_link` — never name a table `soundtrack_link`**, which `retireSoundtrackLinks` drops on every startup. Its `album_id`/`track_id` are `ON DELETE SET NULL` with `snap_*` identity, so a moved file orphans the link and `musicLinkRepo.reattachOrphans()` (after every music scan) moves it to a unique match; never change them to CASCADE. Anime full versions key on `theme_song.external_id`, because theme refreshes re-insert every row. Detail: [music-quiz.md](music-quiz.md) "Music links".
- **Music tracks keep `mediaId: null`** (NowPlayingBar links mediaId → anime detail), and player **track-id namespaces are load-bearing**: `theme-`, `quiz-`, `music-`, `tourney-`, `file-`, `history-` (a History archive recording, by `history_archive` row id). Source-aware current-track actions are shared by the persistent bar and full Now Playing view: music gets Like, Add to playlist and Link to title, themes get Favorite, and other namespaces get neither.
- **Every consumer of `qk.media.home(type)` must keep its query byte-identical `{ mediaType }`** — Seasonal and Franchises share those cache entries. Home itself uses the bounded `media:homeOverview` projection and must not regress to per-type full-library reads.
- **Games keep their own key; the games catalog v2 attaches through `media_external_link`.** A RAWG-era or Steam row is never re-keyed: its LaunchBox work, Bangumi subject, Wikidata item and Steam app live in the link table, and relations, bulk dedup, refresh and achievements read it. An automatic pass never replaces a `manual` link or a manual unlink (a `manual` row with an empty id). Uncertain matches go to the upgrade's review list, never a guess.
- **Bangumi text never reaches the database.** Its summaries, tags and Chinese names are dropped by the whitelisting parsers in `bangumiCore.ts`; only ids, names, images and the fixed English role/relation maps are stored. Game cast is Japanese voice actors only, decided by a kana reading. A Bangumi re-read prunes only its own rows (`character.external_source='bangumi'`, `credit.origin='bangumi'`, relations with `related_source='launchbox'`), so hand-made game credits survive. A franchise wiki (`wikiCastCore.FRANCHISE_WIKIS`, Yakuza first) supplements Bangumi the same way: its rows are `character.external_source='fandom'` and `credit.origin='fandom'`, a character Bangumi already lists (same Japanese name) is never added twice, and it gains the wiki's voice only when it has none. Fandom is DNS-filtered in Iran, so the games catalog bakes the wiki casts (`wiki_category`/`wiki_character`, `lb_meta.wikiCast`) and the app asks the live wiki only for an older pack or a game with no catalog work.
- **Every Art-tab Browse source is SFW-only.** Wallhaven hardcodes `purity=100`; Danbooru asks for `rating:g`; VNDB keeps screenshots rated sexual < 0.5; SteamGridDB asks for `nsfw=false`; Steam refuses games with adult content descriptors 3/4; AniList skips `isAdult`. Each parser in `src/main/artSources.ts` re-checks its items' own rating too, so a provider-side change cannot leak through. Regression-tested in `tests/pictures.test.ts` and `tests/artSources.test.ts`; do not parameterise any of it.
- **GameBanana mods are SFW-only and installed only through the ledger.** `gamebananaCore.ts` keeps a mod only when `_sInitialVisibility` is `show` and it has no content ratings (a missing flag fails), re-checks the profile, and `mods.start` re-reads it before any download; do not parameterise it. Files in an emulator's folder are touched only through `mod_install_file`: an install writes a new `.navihub-partial` folder and renames it (never merges or overwrites), and uninstall/disable act only on listed files whose size and mtime still match. Nothing outside userData is written before the user confirms the destination. Guarded by `tests/gamebanana.test.ts` and `tests/modInstall.test.ts`; detail in [emulation.md](emulation.md).
- **Emulator launches never put the game path after `--` for RPCS3 or shadPS4** — both hand everything after it to the emulated game. Every argv element is one array entry (custom lists are JSON arrays with a `{rom}` element), and the game file and core pass `assertLaunchableExe`. Guarded by `tests/emulationCore.test.ts`.
- **Re-import is authoritative**: it refreshes canonical fields and prunes removed children, but preserves personal tracking via COALESCE. Changes to import logic only affect existing titles after a re-import — **always tell the user that**.
- **A partial refresh (`only` on any importer) must run NO DELETE.** `@shared/refresh.ts` selects which media_item columns get written; every child block — characters, credits, companies, genres, staff, relations — is skipped WHOLE, prune included. This is not tidiness: `pruneCharacters` (anilist, vndb) and TMDB's inlined copy derive their keep-set from the payload, and their last two statements sweep orphaned `character`/`list_item` rows for the whole SOURCE rather than for one media id, so a thin payload through the normal path would delete cast across the library. `replaceRelations` is worse still — an unconditional `DELETE FROM media_relation WHERE media_id=?` before it knows whether the payload has edges. `tests/anilistImport.test.ts` and `tests/tmdbImport.test.ts` assert every child count is unchanged after a `only:['cover']` pass. The Library Refresh `full` aspect is deliberately not a partial refresh: it runs the complete import-dialog path with no `only` (and the full AniList cast, never `liteCharacters`).
- **Checklist history is judged by `checklist_rule`, never by the current board.** Board changes (add, remove, target, weekday schedule) go through `checklistRepo.changeTask`, which records a rule from the current period on; `removeTask` is a soft delete (`removed_at`), so its id keeps its rule history and re-adding revives the same row. Never `DELETE FROM checklist_task` outside `deleteCustom` (and the one-off gacha-daily retirement in `runMigrations`), and never judge a past day from `checklist_task` columns directly: that rewrites history the user already lived. Reading sessions (`mediaSession`, books and VNs) never go through `advanceProgress`. Detail: [checklist-progress.md](checklist-progress.md).
- **`tvRepo` never writes `media_item.progress`.** An episode tick returns `firstTime`, and `ipc.ts` routes it through `checklistRepo.logProgress` — the ONE "I watched another one" write, as for `video:markWatched`. Season toggles pass **`{ noRewatch: true }`** so bulk back-filling never wraps a finished show into a rewatch; one hand-ticked episode still wraps. "Season complete" counts aired episodes only (`total - unaired`). Detail: [media-types.md](media-types.md) "TV seasons and episodes".
- **`replaceEpisodes` prunes only inside the seasons it was actually given** (`EpisodeCatalogue.seasons`). A show-wide prune against a partial run deletes that season's rows and their `watched_at`, which no re-import restores. A partial run publishes `absolute: null`; the upsert COALESCEs.
- **A watermark is committed AFTER its write, never before** — `achievementWatcher.pollOnce` moves `lastMtimeMs` only once `insertUnlocks` returns, or a swallowed `SQLITE_BUSY` makes every later tick (and the final sweep) take the "nothing changed" short-circuit and lose those unlocks for the session.
- **Football missing children are coverage, not empty facts.** A missing scorer line, lineup response, or partial/cancelled slice must stay `not_supplied`/`partial`; it never deletes the last complete slice and never enters a quiz deal. API-Football credentials stay in the `x-apisports-key` header (its keyless media host serves crests only as a fallback), and FotMob remains a validated user-pasted deep link only — no scrape, cache, embed or unsupported endpoint.
- **`beginActivity`/`endActivity` callers pass their handle back** (`endActivity(err, own)`) — the activity slot is one global, and a dialog import started mid-run takes it. Settling "whatever is in the slot" marks a still-running import `done`.
- **A credential that is not a recognisable param name needs its own `redact()` rule** in `logCore.ts` — `http.ts` logs full URLs, and the log file is outside the export sanitizer. RetroAchievements' `z=`/`y=` is the host-scoped precedent.
- **Hand-picked covers, person photos, character images and music album/artist art survive re-imports and rescans only through the `image_override` restore triggers in `init.sql`.** Every importer (and `scripts/bulk-import.cjs`), the music scanner and the music art fetcher write those columns unconditionally; the triggers put the pick back and record what the source offered. Music "Clear cover/photo" (`musicArt.clear*Art`) is the one path that releases a pick without Restore. Manual picks go through `imageOverrideRepo.setManual` (override row first, then the column), never a plain column write from a form. Never `REPLACE INTO` `media_item`/`person`/`character` — it bypasses the restore trigger and fires the cleanup one. The export sanitizer deletes `image_override` before it nulls image paths. Guarded by `tests/imageOverride.test.ts`.
- **`pictures.dir`, `media.dir` and `history.dir` change only through `storageMove` (Settings → Folders → Move…).** Rows store paths relative to these roots, so editing one of these settings without moving the files breaks every image or archive file. The move flips the setting only after a complete, size-verified copy and deletes an original only when its copy verifies. Every `media/` path resolves through `files.mediaRoot()` (`tests/storageMove.test.ts` guards it); the headless scripts read `media.dir` from the settings table.
- **Deleting a media item goes through `media:remove`, which calls `pictures.forgetSlideshowForMedia(id)` BEFORE `mediaRepo.remove(id)`** — `slideshow_item` rows cascade with the images, but their copies in `slideshow.dir` do not, and Windows would keep cycling wallpapers for a title the user deleted.
- **Anything feeding a POSITIONAL file reads the provider's order** — `achievementRepo.listInProviderOrder`, not `listForMedia` (which sorts unlocked-first for the UI). The Goldberg config is a positional JSON array; UI order remaps every index and reshuffles on each new unlock.

### Personal hobby state

VN reading plans, notebook entries, text captures and edition snapshots are personal state,
independent of metadata imports and overall minutes/status. A partial VNDB refresh must never
prune their rows or canonical tags/relations. Capture edits invalidate derived coverage;
async scans/deck builds check capture fingerprints before writing. Wrestling journey steps
retain personal context/viewings when imported references disappear. Wipe all of these personal
tables from shared exports; only the public VN release cache may survive.

- **Playthrough membership is captured at launch.** `gameLaunch` passes the launch-time run ID into `gameSessionRepo.recordSession`; never look up the currently active run at exit. Removing a run removes its journal/associations, never `game_session` rows or tracked totals. A run removed mid-session leaves that new session unassigned rather than losing the time.

### Learning evidence

`learning.evidence.v1.*` settings contain personal practice attempts, exposed exercise ids, writing/project notes and English missed-item queues; keep this whole prefix in the export sanitizer. Reserve delayed exercise exposure before revealing a prompt, and retain exposed ids independently of bounded attempt history. Guided, repeated and self-assessed work must never be labelled as automatically demonstrated mastery. Programming completion rows mean marked read; preserve their frozen keys and historical timestamps. Author lesson-specific misconceptions and explanations; never pad answers or generate generic distractors to pass answer-length tests.
