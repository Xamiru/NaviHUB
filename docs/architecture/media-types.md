## Wallpapers and fan art

**Wallpapers/fan art (2026-07-09):** every media detail page gets a Wallpapers `MediaImagesSection`; non-movie/TV types also get Fan Art (`cfg.hasFanArt`). One `media_image` table (`kind` column), rows stripped on export (sanitizeSql.cjs). `src/main/pictures.ts` owns SQL + searches: Wallhaven (purity=100 SFW hardcoded — regression-tested) and TMDB backdrops (`tmdb.ts:fetchBackdrops`, movie/tv with `external_source='tmdb'` only). Searches go through IPC (renderer CSP has no `connect-src https:`; remote *thumbnails* are fine — `img-src https:`). `ImageBrowseDialog` per-tile busy/added state; `Lightbox.tsx` is the app's only fullscreen image modal (←/→ wrap). Removing an image deletes its file (pictures/ paths only); deleting media cascades rows but leaves files.

## Books

**Books section (2026-08-04)** — new media type `'book'` (flavor A, `/books`): Open Library import + pages-based tracking + local EPUBs read through the EXISTING reader machinery. **Progress = pages** (`progress` = current page, `total_units` = page count): book is deliberately NOT in `UNIT_PROGRESS_TYPES` and `BOOK` has no `logUnitLabel`, so the detail-page log button is mark-completed / read-again (the movies behavior) — a page is not a sitting. **Importer `src/main/openlibrary.ts`** (rawg.ts template; NO key, descriptive User-Agent — the AnimeThemes posture): work ids are STRINGS (`OL45883W`) → `ImportSearchResult.id` is `number | string`, ImportDialog flattens `api[source.key]` through one structural cast and `importingId` is widened; `ImportSourceCfg` gained `unitNoun` ("352 pages" not "352 ep"). Search carries `author_name` in `native` (the disambiguator); import = work + per-author fetches (cap 6 → person rows by `('openlibrary', OL…A)` + **`writer` credits**, surfaced by `crewTitle:'Authors'` and the `/authors` browse route scoped `role='writer'` + `mediaType='book'` so movie writers can't bleed in) + `editions.json?limit=50` **median** page count (works carry none; `total_units=COALESCE(?, …)` so a null median never wipes a hand-entered count) + `ratings.json` → `metadata.olRating = avg×20` (pre-scaled 0-100, added to `COMMUNITY_SQL`) + subjects → tags **capped at 10** (OL subject lists are noisy). Publishers live on editions as bare strings — hand-curated, v1 skips them. bulk-import.cjs does NOT mirror openlibrary (known debt). **Local EPUBs reuse manga wholesale**: same `manga_chapter` table + manga.ts functions, `rootInfoFor(mediaId)` derives root/prefix/settingKey from the media row's `media_type` (`book` → `books.dir`/`books/` prefix — no schema change; `booksRootDir()` in files.ts, `books/` branches in `absoluteMediaPath` AND the navimg **archive-streaming allowlist** in index.ts, which would otherwise 404 every spine fetch). **`syncMediaProgress` returns early for book media** — finishing an EPUB volume must never slam a page-based `progress` down to a volume count (chapter `read_at`/`last_read_page` still persist; regression-tested). `readerPath(basePath, …)` takes `'/manga' | '/books'`; new chromeless routes `/books/:id/read|book/:chapterId` (isReader regex widened), both readers derive `basePath` from the URL for exits/volume switches. `MangaChaptersSection` de-manga-fies via `m.mediaType`: "Volumes" heading, mokuro OCR + Vocab-deck hidden, `ocrOverview` query disabled. `CoverageSection`'s local-reader gate became **`cfg.key === 'manga'`** (JP comprehension must not appear on English books). **Light novels stay in manga** (jpMilestones/mining untouched). Stats: book in `STAT_TYPES`/`ESTIMATED_TYPES`, `rowMinutes` = pages × `stats.bookPageMinutes` (default 1.5, Settings → Time stats) × passes; `TYPE_COLORS.book` teal; torznab `[7020, 7000]`. `books.dir` (bootstrapped on first attach, Settings → Folders) wiped in sanitizeSql.cjs. Tests: openlibraryImport (string ids, median, capped tags, best-effort endpoints, COALESCE re-import), manga.test.ts book block (books/ prefix + root, the progress guard, manga regression), torrents/mediaProgress/mediaRepo/exportSanitize extended.

## Game launcher, playtime tracking, HLTB lengths

**Game launcher + playtime tracking + HLTB lengths (2026-08-06)** — games/VNs get launch-from-app (`cfg.hasGameLaunch`, GAME + VISUAL_NOVEL): a per-title executable in **`media_item.exe_path`** (init.sql + schema.ts + ensureColumn; absolute machine path — wiped in sanitizeSql.cjs next to local_dir, deliberately absent from mediaRepo's COL map AND from `MediaItem` — it rides `games:overview`, the local_dir posture) and sessions in **`game_session`** (media_id CASCADE, UTC started/ended, duration seconds; wiped on export). `src/main/gameLaunch.ts` is the mokuroRun singleton with THE one deliberate deviation: the child is spawned `detached:true` + `unref()` and is **never killed** — no cancel channel, and before-quit calls `finalizeActiveGameSession()` (records the in-flight session, must run BEFORE `closeDatabase()`) while the game keeps running. Sessions under `MIN_SESSION_SEC` (60) are discarded with a launcher-stub hint (a stub that spawns the real game and exits is the known v1 limitation — link the real exe); an app crash loses the in-flight session (accepted; documented in-module). **The fold** (`gameLaunchCore.ts:foldedProgress`, pure + exhaustively tested): `game_session` is the source of truth for tracked seconds, and `media_item.progress` moves by the **delta of the rounded cumulative** (`unitSecondsFor`: game=3600, vn=60), so short sessions never round away, hand-entered baselines survive, and a manual progress edit just becomes the new baseline — progress stays hours(game)/minutes(vn), which is why `rowMinutes`/Stats needed ZERO changes. Windows-only launch (`process.platform` guard throws a friendly error; overview carries `supported`); picker is main-side `games:pickExe` (manga.attachFolder posture). Renderer: `GameLaunchSection` (Playtime tab, above the HLTB boxes) + `lib/useGameSession.ts` (useOcrRun port, 1 s poll so the elapsed chip ticks; settled toast invalidates games+media+checklist). Checklist gained detected source `gameSession` (`game-session` def, daily, NOT seeded; sessions counted by `date(started_at,'localtime')`). **HLTB is now the authoritative game length**: `hltb.ts:hltbLengthHours` = `max(1, round((main ?? allStyles)/60))` hours, written to `total_units` at BOTH sites — rawg.ts import (RAWG's crowd-average `playtime` is only the fallback) and `fetchForMedia` (game rows only, a miss never writes), so the existing detail-page Fetch/Refresh button fixes wack lengths on already-imported games; VN lengths stay VNDB minutes untouched; re-import-to-apply otherwise. `GAME.totalFieldLabel` is now 'Length (hours)'. Tests: gameLaunch (fold matrix), gameSessionRepo (atomic insert+fold, cap/order, CASCADE), hltb (both write sites, VN untouched, miss keeps value), rawgImport (+HLTB-beats-RAWG, URL-routed http mock), checklist + exportSanitize extended. Windows spawn/exit end-to-end is UNVERIFIED on this Linux box — needs a manual pass on the user's gaming PC after the next release.

## Seasonal anime

**Seasonal anime (2026-07-10)** — `/anime/seasonal` (`SeasonalAnimePage`) shows the library's anime as four stacked Winter→Fall shelves per selected year; entry points are `MediaConfig.hasSeasonal` (list-header button), an `ANIME.children` sidebar link, and a CommandPalette nav item (route sits above `/anime/:id` in App.tsx). Season data: the AniList anime importer persists canonical `season`/`seasonYear` into the `metadata` JSON (`mergeMetadata` accepts positive numbers AND non-empty strings — mirrored in bulk-import.cjs); `@shared/season.ts:seasonForItem` (tests/season.test.ts) prefers validated metadata, falls back to release-date quarters (Jan–Mar=winter …), else the page's Unknown bucket. Known skew: year-only AniList dates are padded to `-01-01` → Winter, and Dec premieres belong to next-year WINTER — both self-correct on re-import. The page reuses `qk.media.home('anime')`, so its queryFn filter must stay byte-identical to HomePage's (`{ mediaType: 'anime' }`).

## Library filtering and sorting

**Library filtering & sorting (2026-07-19)** — every media type's `MediaListPage` gets one filter model, all of it inside `MediaListFilter` (shared/types.ts) so the whole filter object stays the query key. Repo side (`mediaRepo.list`): `buildWhere()` assembles clauses for multi-status (`statuses`, superseding the legacy single `status`), multi-tag with `tagMode:'any'|'all'` (legacy `tagId` still honored), favorite, `unrated` (score IS NULL — wins over any score range), and inclusive numeric ranges for personal score, community score, year and `total_units`. Three derived SQL expressions are shared by filters/sorts/facets and must move together: `COMMUNITY_SQL` COALESCEs every importer's rating key into ONE 0-100 scale (averageScore / metacritic / vndbRating / imdbRating×10 — **any new importer rating key belongs here**), `YEAR_SQL` (release year, falling back to metadata `seasonYear`), and `SEASON_SQL` (metadata season first, then month quarters — mirrors `seasonForItem` in @shared/season.ts, keep in step). Sort keys come from the `SORT_SQL` whitelist (never interpolate filter input); `random` is a SEEDED multiplicative hash of `m.id` — the multiplier carries the seed (an additive seed only rotates the same order) and is folded in JS so `id * mult` can't overflow int64, which makes a shuffle stable across refetch/scroll-batching while the page's Shuffle button re-seeds. `mediaRepo.facets(mediaType)` (`media:facets` → `qk.mediaCounts.facets`) feeds the sliders real library bounds and is the page's true title count — `statusCounts` drops NULL statuses and undercounts. Renderer: `MediaFilterPanel.tsx` owns `MediaFilters` + `EMPTY_FILTERS`/`activeCount`/`toListFilter`, range convention **`null` = unconstrained** (a slider spanning its full bounds collapses back to null, which is what keeps untouched filters out of the query key); `RangeSlider.tsx` is the app's dual-thumb slider (two transparent native ranges over a div track, thumbs styled in the styles.css WIRED CHROME block). Status pills are multi-select; active narrowings render as removable chips with Clear all. HomePage/SeasonalAnimePage still pass `{ mediaType }` only, so their shared `qk.media.home` cache entry is untouched — don't add defaulted fields at those call sites.
