## The JLPT ladder

**Levels as progress, never a gate (2026-08-16).** `@shared/jlptLevels.ts` owns the rules; `japaneseRepo.jlptLadder()` is one pass over `jp_card ⋈ jp_lesson ⋈ jp_course`; `components/japanese/JlptLadder.tsx` renders it in a "JLPT ladder" section on the roadmap page.

**No schema change.** Courses already carry a free-text level LABEL (`'N5'`, `'N5+'`, `'N4–N3'`, `'N3–N2'` — what the seeds write and the course pages show). `parseJlptLevel` takes the FIRST tier a label names: the tier the course is pitched at, with the range's upper end treated as stretch material. Higher-numbered N is easier, so "first mentioned" is also "lowest". A label naming no tier yields null, and those cards are reported as `unlevelled` rather than dropped — a total the user cannot reconcile with their library is worse than a caveat.

**"Passed" is defined in this app's terms.** The SRS here is Anki-shaped (`new`/`learning`/`review`/`relearn` + `interval_days`), not WaniKani's stage ladder, so Guru has no direct equivalent. A card counts once it is `status='review'` with `interval_days >= PASSED_INTERVAL_DAYS` (7) — it has left the learning steps and earned a real interval. The UI states that definition in its footnote instead of borrowing WaniKani's word without its machinery.

A level clears at `LEVEL_PASS_RATIO` (90%), the user's choice, so a few stubborn cards cannot stall it. `currentLevel` is the easiest uncleared level, **skipping levels with no cards** — a library that starts at N3 must not read as "you are on N5 forever" — and settles on the hardest level with cards once everything is cleared.

**Nothing locks.** The user decided levels track progress and gate nothing: this section is their only Japanese source, so it must never be the reason a card is unavailable. `tests/jlptLadder.test.ts` pins both the pure rules and the real SQL.

## On-screen Japanese keyboard

**On-screen Japanese keyboard (2026-08-12)** — `JpKeyboardInput` (`components/japanese/keyboard/`) is a drop-in for `<input className="input">` at JP-typing sites (v1: dictionary search, shiritori, dictation — deferred: mining/lesson-form fields, textareas): an あ toggle opens a panel with three switchable layouts (gojūon chart rendered COLUMNS right-to-left あ-rightmost, flick 12-key with drag petals in `FlickKey.tsx`, romaji QWERTY) + an IME candidate bar. Pure parts: `@shared/kanaKeyboard.ts` (layout tables + dakuten/handakuten/small toggles + the phone ゛゜小 `cycleKana` orbit base→small→dakuten→handakuten) and `@shared/imeCompose.ts` (`ComposeState {kana, pending}` — typing.ts's interpret() promoted; re-converts the whole pending tail per keystroke, holds a lone trailing "n"; no-op returns the SAME object). **There is no katakana mode** — the engine composes hiragana and the candidate row leads with the two script chips (hira + `toKatakana`), which is also the empty-dict degradation. Candidates: `dict:readingCandidates` (`dict/imeCandidates.ts`) — exact reading match (both scripts, `d.priority >= 0` excludes JMnedict, dedupe by expression, rank freq→common-tag→dict-priority→score, script-form expressions EXCLUDED as chip duplicates) then freq-GATED LIKE-prefix predictions (≥2 kana only), cap 16, `[]` on any failure; renderer queries it via `qk.dict.imeCandidates` on a 150ms-debounced `commitText`. Load-bearing renderer details: EVERY panel control `preventDefault`s pointerdown (focus must never leave the host input), caret restored via rAF `setSelectionRange` after controlled onChange, physical typing bypasses the buffer entirely (goes straight to the input) EXCEPT Enter/Escape, which route through the `JpKeyboardBridge` ref first — Enter with uncommitted kana COMMITS it (never submits the stale value), Escape clears the buffer, then closes the panel, then reaches page cascades (`stopPropagation`). Prefs (layout + romaji hints via `kanaToRomaji` sublabels) in localStorage `jp.keyboardPrefs` (book.readerPrefs idiom). This wave also extended romaji.ts BASE/DIGRAPHS (x/l small kana, ゔ/`vu`+combos, ファ/ティ/ウィ/シェ families) — app-wide effect on `romajiToHiragana`/`acceptedRomaji`, safe because matchState's documented failure direction is "too lenient". Tests: kanaKeyboard (completeness/orbits), imeCompose (keystroke-vs-full-string equivalence), dictIme (real dict schema). GUI smoke pending on the user's machine (headless box).
