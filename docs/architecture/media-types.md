## The detail-page hero

**Art-led headers (2026-08-15).** `MediaConfig.detailHero` picks the shape of the detail header, rendered by `components/MediaHero.tsx`:

- `'banner'` — a 220px strip of wide art with the cover hanging off its bottom edge on a `-mt-24`, title block beside it (anime, visual novels). The cover is the thing the user recognises; the banner is atmosphere.
- `'backdrop'` — a 420px still with the eyebrow, title, synopsis clamp, stats and actions sitting on top of it behind two gradient scrims when a media type calls for an art-led header.
- absent — the original two-column header (manga, books, games, movies, TV). Those types are carried by a data tab where appropriate (volumes, playtime, video, seasons), so the header stays out of the way.

Both hero variants lay the action stack out as a ROW (`actionStack(inline)` in MediaDetailPage) instead of the full-width column beside the cover, and `BackButton` gains an `overlay` prop for them — the sticky strip's `-mx-6` would hang off a full-bleed container that has no padding to cancel. History-back behaviour is unchanged.

**Where the art comes from.** `MediaDetail.heroPath` is resolved once, server-side, in `mediaRepo.get`:

1. `media_item.banner_path` — AniList `bannerImage` (anime + manga queries) or the TMDB `backdrop_path` at `w1280` (movies + TV, both through the shared `persistTitle`). Downloaded in the importers' existing `downloadImages` batch and written with `COALESCE(?, banner_path)`, so a later import that comes back without one cannot blank the hero.
2. else the first `media_image` row of kind `fanart`, then `wallpaper`, by `sort_order` — whatever the user already attached on the Art tab. The page BACKDROP (`is_background`) is a separate field and does not enter this chain: the same image may be both, and picking a backdrop must never move the hero.
3. else null. The `'banner'` variant then DROPS its strip entirely — a 220px strip of the blurred cover reads as broken, not atmospheric (reported 2026-08-22) — so Back moves inline above the cover row and `-mt-24` becomes `mt-4`, exactly like the set-background case below; only `'backdrop'` blurs the cover up as an underlay, because its block carries the title and actions and cannot disappear.

The renderer never re-implements that order; `tests/mediaRepo.test.ts` pins it, and `tests/anilistImport.test.ts` / `tests/tmdbImport.test.ts` pin the import half. **`banner_path` is NULL on every row imported before this shipped — those titles only gain source art when the user re-imports them.**

## TV seasons and episodes

**The episode catalogue (2026-08-15).** `tv_episode` holds TMDB's list of what a show *contains*; `video_file` stays the index of what you *have*. A row exists for every episode whether or not the file does, and `tvRepo.listSeasons` joins the two on `(season, number)` so an episode you own can offer Play without the renderer running a second query. TV's `mediaTabLabel` is `'Seasons'` (the tick grid) and its `videoTabLabel` dropped from `'Episodes'` to `'Files'` — two tabs called Episodes would have been a coin toss.

**Import.** `importTv` fetches `/tv/{id}/season/{n}` once per season, in season order, during the network phase — so `absolute` (1-based across the whole run) is numbered before any write, and the writes stay in `persistTitle`'s single transaction. **Specials (season 0) are skipped**: `absolute` has to agree with `media_item.total_units`, which is TMDB's `number_of_episodes` and excludes them. A season whose fetch fails is logged through `logWarn('http', …)` and skipped rather than failing the import, and `replaceEpisodes` is a no-op when handed an empty list, so a show whose season fetches ALL failed keeps the catalogue it already had instead of being pruned to nothing. Episode stills are deliberately not downloaded — a long-running show is hundreds of images and the grid does not show one.

**Progress.** `tvRepo` never writes `media_item.progress`. `setWatched` returns `firstTime` and `ipc.ts` routes it through `checklistRepo.logProgress`, exactly as `video:markWatched` does — the app keeps ONE "I watched another one" write, which owns status promotion, the rewatch wrap and checklist credit. A season toggle logs once per newly-watched episode, so ticking a season credits the same as ticking each episode by hand. Marking a season skips unaired episodes (you cannot have seen them); unmarking clears every one, so it is a reliable undo. An episode with no air date counts as aired — TMDB leaves it blank on plenty of old shows, and greying those out would be worse than an occasional early tick.

**Re-import is authoritative** here like everywhere else: canonical fields refresh, episodes TMDB no longer lists are pruned by an inlined row-value keep-list (every element forced through `Number()` first, since a row-value `IN` cannot be parameterised), and `watched_at` is never in the UPDATE so it survives. It is also the one personal column in the table, cleared by `sanitizeSql.cjs` while the catalogue itself ships.

## Wallpapers and fan art

**Wallpapers/fan art (2026-07-09):** every media detail page gets a Wallpapers `MediaImagesSection`; non-movie/TV types also get Fan Art (`cfg.hasFanArt`). One `media_image` table (`kind` column — exactly the two Art-tab grids; a page background is a FLAG on one of these rows, not a third kind), rows stripped on export (sanitizeSql.cjs). `src/main/pictures.ts` owns SQL + searches: Wallhaven (purity=100 SFW hardcoded — regression-tested) and TMDB backdrops (`tmdb.ts:fetchBackdrops`, movie/tv with `external_source='tmdb'` only). Searches go through IPC (renderer CSP has no `connect-src https:`; remote *thumbnails* are fine — `img-src https:`). `ImageBrowseDialog` per-tile busy/added state; `Lightbox.tsx` is the app's only fullscreen image modal (←/→ wrap). Remote covers and Art-tab images stream through bounded sibling partials in `files.ts`; only a completed download is renamed into view, and failures/cancellation leave neither a truncated final file nor partial debris. Removing an image deletes its file (pictures/ paths only); deleting media cascades rows but leaves files.

**Right-click on an Art-tab tile (2026-08-17)** — two actions, on the tile and on the same image inside the Lightbox, drawn by `components/ContextMenu.tsx` (the app's first renderer-drawn context menu; see [ui-conventions.md](ui-conventions.md)). Every read of an image row goes through `IMAGE_SELECT` in pictures.ts, which carries both states so the tile markers ("Background" in accent, "Slideshow" in gray, bottom-right beside the w×h badge) need no second query.

- **Set background / Clear background** → `pictures:setBackground(mediaId, imageId | null)` sets `media_image.is_background`, clearing the whole item first so at most one row carries it (transaction; a foreign `imageId` throws and leaves the old flag alone). `mediaRepo.get` resolves it into `MediaDetail.backgroundPath`, and `MediaDetailPage` paints it with the SAME `FranchiseBackground.tsx` the franchise pages use — absolute child of the page root, `background-attachment: fixed`, base-900 scrim, preload cross-fade — under a `relative z-10` content wrapper, so it never covers the sidebar/Topbar. Works on every media type, not just games. **`MediaHero` yields to a background when one is set** (`onBackground = !!m.backgroundPath`), because a hero painting its own `object-cover` crop on top of the backdrop's puts two framings of one file edge to edge — the hard seam reported 2026-08-17 with screenshots. The `'banner'` variant (anime, VNs) drops its 220px strip outright, while a `'backdrop'` variant, if configured, keeps its 420px block with the title, synopsis, stats and actions on it. Movies now use the plain two-column header like TV; the backdrop is no longer used by the current media configs. Storage is a flag rather than a `media_item` pointer so it dies with the row: no dangling id, and the export sanitizer already wipes `media_image` wholesale. **This retires the reserved `ImageKind 'background'`** (2026-08 shape) — it was never written, and a separate kind would have duplicated the file on disk and hidden it from the grid.
- **Add to / Remove from slideshow** → `pictures:toggleSlideshow(imageId)` COPIES the file into `slideshow.dir` (default `<pictures.dir>/Slideshow`, Settings → Folders, with an "Open folder" button) and records `slideshow_item(image_id UNIQUE FK CASCADE, file_name)`. The user points **Windows Settings > Personalization > Background > Slideshow** at that folder once and the OS rotates the images — deliberately NOT an in-app wallpaper setter: that would need a second main-side `setInterval` (the achievement watcher owns the only one) and would stop working the moment NaviHUB closed. `slideshow.dir` is the one picture root that is NOT a navimg prefix — nothing in the app displays these copies. `copyIntoSlideshow` de-clashes names (`Berserk - one (2).jpg`) and throws if the source is gone, so no row can claim a missing copy; removal is best-effort, which is also the repair path for a copy the user deleted in Explorer (toggle off, toggle on). `removeImage` deletes the copy too, and `media:remove` calls `forgetSlideshowForMedia` first — the rows would cascade, but the files would linger in a folder Windows is actively cycling.

## Books

**Books section (2026-08-04)** — new media type `'book'` (flavor A, `/books`): Open Library import + pages-based tracking + local EPUBs read through the EXISTING reader machinery. **Progress = pages** (`progress` = current page, `total_units` = page count): book is deliberately NOT in `UNIT_PROGRESS_TYPES` and `BOOK` has no `logUnitLabel`, so the detail-page log button is mark-completed / read-again (the movies behavior) — a page is not a sitting. **Importer `src/main/openlibrary.ts`** (rawg.ts template; NO key, descriptive User-Agent — the AnimeThemes posture): work ids are STRINGS (`OL45883W`) → `ImportSearchResult.id` is `number | string`, ImportDialog flattens `api[source.key]` through one structural cast and `importingId` is widened; `ImportSourceCfg` gained `unitNoun` ("352 pages" not "352 ep"). Search carries `author_name` in `native` (the disambiguator); import = work + per-author fetches (cap 6 → person rows by `('openlibrary', OL…A)` + **`writer` credits**, surfaced by `crewTitle:'Authors'` and the `/authors` browse route scoped `role='writer'` + `mediaType='book'` so movie writers can't bleed in) + `editions.json?limit=50` **median** page count (works carry none; `total_units=COALESCE(?, …)` so a null median never wipes a hand-entered count) + `ratings.json` → `metadata.olRating = avg×20` (pre-scaled 0-100, added to `COMMUNITY_SQL`) + subjects → tags **capped at 10** (OL subject lists are noisy). Publishers live on editions as bare strings — hand-curated, v1 skips them. bulk-import.cjs does NOT mirror openlibrary (known debt). **Local EPUBs reuse manga wholesale**: same `manga_chapter` table + manga.ts functions, `rootInfoFor(mediaId)` derives root/prefix/settingKey from the media row's `media_type` (`book` → `books.dir`/`books/` prefix — no schema change; `booksRootDir()` in files.ts, `books/` branches in `absoluteMediaPath` AND the navimg **archive-streaming allowlist** in index.ts, which would otherwise 404 every spine fetch). **`syncMediaProgress` returns early for book media** — finishing an EPUB volume must never slam a page-based `progress` down to a volume count (chapter `read_at`/`last_read_page` still persist; regression-tested). `readerPath(basePath, …)` takes `'/manga' | '/books'`; new chromeless routes `/books/:id/read|book/:chapterId` (isReader regex widened), both readers derive `basePath` from the URL for exits/volume switches. `MangaChaptersSection` de-manga-fies via `m.mediaType`: "Volumes" heading, mokuro OCR + Vocab-deck hidden, `ocrOverview` query disabled. `CoverageSection`'s local-reader gate became **`cfg.key === 'manga'`** (JP comprehension must not appear on English books). **Light novels stay in manga** (jpMilestones/mining untouched). Stats: book in `STAT_TYPES`/`ESTIMATED_TYPES`, `rowMinutes` = pages × `stats.bookPageMinutes` (default 1.5, Settings → Time stats) × passes; `TYPE_COLORS.book` teal; torznab `[7020, 7000]`. `books.dir` (bootstrapped on first attach, Settings → Folders) wiped in sanitizeSql.cjs. Tests: openlibraryImport (string ids, median, capped tags, best-effort endpoints, COALESCE re-import), manga.test.ts book block (books/ prefix + root, the progress guard, manga regression), torrents/mediaProgress/mediaRepo/exportSanitize extended.

## Game launcher, playtime tracking, HLTB lengths

**Game launcher + playtime tracking + HLTB lengths (2026-08-06)** — games/VNs get launch-from-app (`cfg.hasGameLaunch`, GAME + VISUAL_NOVEL): a per-title executable in **`media_item.exe_path`** (init.sql + schema.ts + ensureColumn; absolute machine path — wiped in sanitizeSql.cjs next to local_dir, deliberately absent from mediaRepo's COL map AND from `MediaItem` — it rides `games:overview`, the local_dir posture) and sessions in **`game_session`** (media_id CASCADE, UTC started/ended, duration seconds; wiped on export). `src/main/gameLaunch.ts` is the mokuroRun singleton with THE one deliberate deviation: the child is spawned `detached:true` + `unref()` and is **never killed** — no cancel channel, and before-quit calls `finalizeActiveGameSession()` (records the in-flight session, must run BEFORE `closeDatabase()`) while the game keeps running. Sessions under `MIN_SESSION_SEC` (60) are discarded with a launcher-stub hint (a stub that spawns the real game and exits is the known v1 limitation — link the real exe); an app crash loses the in-flight session (accepted; documented in-module). **The fold** (`gameLaunchCore.ts:foldedProgress`, pure + exhaustively tested): `game_session` is the source of truth for tracked seconds, and `media_item.progress` moves by the **delta of the rounded cumulative** (`unitSecondsFor`: game=3600, vn=60), so short sessions never round away, hand-entered baselines survive, and a manual progress edit just becomes the new baseline — progress stays hours(game)/minutes(vn), which is why `rowMinutes`/Stats needed ZERO changes. Windows-only launch (`process.platform` guard throws a friendly error; overview carries `supported`); picker is main-side `games:pickExe` (manga.attachFolder posture). Renderer: `GameLaunchSection` (Playtime tab, executable controls and aggregate tracked time only; dated session history is absent) + `lib/useGameSession.ts` (useOcrRun port, 1 s poll so the elapsed chip ticks; settled toast invalidates games+media+checklist). Checklist gained detected source `gameSession` (`game-session` def, daily, NOT seeded; sessions counted by `date(started_at,'localtime')`). **HLTB is now the authoritative game length**: `hltb.ts:hltbLengthHours` = `max(1, round((main ?? allStyles)/60))` hours, written to `total_units` at BOTH sites — rawg.ts import (RAWG's crowd-average `playtime` is only the fallback) and `fetchForMedia` (game rows only, a miss never writes), so the existing detail-page Fetch/Refresh button fixes wack lengths on already-imported games; VN lengths stay VNDB minutes untouched; re-import-to-apply otherwise. `GAME.totalFieldLabel` is now 'Length (hours)'. Tests: gameLaunch (fold matrix), gameSessionRepo (atomic insert+fold, aggregate overview, CASCADE), hltb (both write sites, VN untouched, miss keeps value), rawgImport (+HLTB-beats-RAWG, URL-routed http mock), checklist + exportSanitize extended. Windows spawn/exit end-to-end is UNVERIFIED on this Linux box — needs a manual pass on the user's gaming PC after the next release.

## Achievements

**Achievements (2026-08-14)** — Xbox/Steam-style achievement tracking for games and VNs (`cfg.hasAchievements`, GAME + VISUAL_NOVEL — the same pair that can link an executable). Three new tables, no migration work: **`achievement_game`** (media_id PK, `provider` `steam`/`ra`, `provider_game_id`, `schema_fetched_at`), **`achievement`** (the set: api_name, name, description, hidden, both icon paths, `points` RA-only, `global_pct`, UNIQUE(media_id, api_name)) and **`achievement_unlock`** (achievement_id PK — **a row's presence IS "unlocked"**, so nothing stores a locked state; `source` `emu`/`ra`/`manual`). The first two are canonical and SURVIVE an export (the theme_song posture, declared in sanitizeCoverage's CANONICAL_SURVIVORS); `achievement_unlock` is personal and wiped, as are the three new settings keys.

**Why it works on pirated games at all**: a cracked game still calls the Steam achievement API — the crack just points it at a Steam emulator, and every one of them writes unlocks to a well-known file. `achievementsCore.ts` (pure, `gameLaunchCore` seam) holds a table of ~15 candidate paths (Goldberg/GSE in `%APPDATA%`, CODEX/RUNE/EMPRESS/Online-Fix under `%PUBLIC%\Documents`, SKIDROW/SmartSteamEmu, ALI213's globbed profile folder, plus Goldberg's local-save-beside-the-exe mode) and two tolerant parsers (Goldberg JSON object-or-array; the INI family, both section-per-achievement and flat-container shapes, `Achieved`/`HaveAchieved`/`earned` spellings). **`parseUnlockFile` never throws** — the watcher reads these files while the game writes them, so a torn read must look like "nothing new", not a crash. `emuScan.ts` is the IO half behind an injected `EmuFileIO`, which is what makes the whole thing testable on Linux. Roots come from env vars, and a missing one just drops its candidates.

**Providers**: `achievements.ts` gets the Steam set from **three sources in order, first hit wins** — the user's Steam account is "limited" (Steam only issues Web API keys to accounts that have spent money), so the list has to work with no key. (1) **The crack's own `steam_settings/achievements.json`** beside the exe (or up to two folders above it), which Goldberg/GSE releases ship: full schema INCLUDING the api names the emulator writes unlocks under, icons copied in content-addressed via `files.importImageFile`, zero network — `parseGoldbergSchema` handles string and localized-object names, `hidden` as "0"/"1"/bool, and both `icongray`/`icon_gray` spellings. (2) The **Web API** `GetSchemaForGame`, only if `steam.web_api_key` is set. (3) **Steam's public community stats page** (`steamcommunity.com/stats/<appid>/achievements`), which has names/descriptions/art/global % but **no api names** — those come from the keyless `GetGlobalAchievementPercentagesForApp` and `joinCommunityWithPercentages` pairs the two lists **by rank, not by value** — both are sorted by % desc, but Steam serves the page from a cache and the endpoint live, so on any active game most values differ by a tenth (an exact-percent join paired 12 of 49 on AC4 Black Flag). Equal counts → zip by index; unequal counts → an order-preserving alignment within `PCT_TOLERANCE`, with the unplaceable rows counted as `unmatched` and surfaced in the setup toast. On that path the percentages endpoint is load-bearing, not decoration, so its failure IS a failure. `AchievementSetupResult.schemaSource` says which source won. Rarity for the other two sources comes from the same keyless endpoint, best-effort. `exeDirOf` picks path flavor by separator, not host — the posix `dirname` of a `C:\…` path is `.`, which was a silent miss on the Linux test box. Icons go through `downloadImages` like any importer, and the whole thing is two-phase atomic. Rarity tiers (`rarityTier`: >25 common, >10 uncommon, >3 rare, else ultra-rare) are computed main-side so the renderer never re-derives cutoffs; **no gamerscore is invented** — `points` stays NULL for Steam. `retroAchievements.ts` covers emulated games: `API_GetGameInfoAndUserProgress` returns the set AND the user's full unlock history in ONE call, RA points are shown because RA actually awards them, and `parseRaDate` appends the missing `Z` (RA sends UTC unzoned, so `Date.parse` would shift every unlock by the machine's offset). RA has no free-text search endpoint — the dialog pulls a console's game list and filters locally, with direct game-id entry as the escape hatch.

The RA console catalogue is cached once per console for the app session, so each debounced query filters the same local snapshot instead of downloading the whole list again. Failed catalogue requests are evicted and remain retryable.

An unavailable or rejected optional Steam Web API key falls through to the public community schema source. The keyless percentages endpoint remains required on that community path because it supplies the API names used to identify unlocks.

**Appid without Steam**: only `external_source='steam'` rows know their appid. Everything else resolves through the keyless storefront `search()` and the user confirms; an exact imported appid remains usable even when that optional search is unavailable. The choice lands in `achievement_game.provider_game_id` (no `media_item` column, no ensureColumn). A first association is written before the fetch so a failed network half does not cost the user the lookup; replacing an existing provider/game identity commits only with the fetched replacement set.

**Eligibility is "exe linked now or ever"** — `exe_path IS NOT NULL OR EXISTS(game_session) OR EXISTS(achievement_game)`. `games:clearExe` nulls the path and keeps no history, so the latter two clauses are what make "or ever" true; once tracking exists its own row is the durable marker.

**The live half** — `achievementWatcher.ts` owns the app's ONE main-side `setInterval` (5 s for emulator files, 30 s for RA), started by `gameLaunch.startSession`, cleared in `endSession` and by `stopAchievementWatcher()` in the before-quit registry (ahead of `closeDatabase()` — it writes rows). Both stop paths run a **final sweep**, because emulators commonly flush as the game exits. Popups surface through the **in-game overlay** (`achPopup.ts`): a frameless transparent click-through window at `#/achpop` pinned bottom-right with `alwaysOnTop('screen-saver')`, rendered by `AchPopupPage` which polls the same `achievements:watchStatus` the in-app toast uses (no push channel — the freeze is intact; main preloads the window at session start so its seq seed lands before the first unlock). The overlay exists because OS notifications are suppressed during fullscreen apps on Windows — the original `new Notification` path was invisible exactly when it mattered — and that path survives only as `fallbackNotify` for environments where no window can be created (`focusable: false`, `showInactive`, and `setIgnoreMouseEvents(true)` so clicks fall through to the game). Bursts above `ACH_POPUP_BURST_AT` collapse into one summary card on both surfaces. `pollOnce(deps)` takes injected fs/fetch/now deps, so the whole detect→write→raise path is tested with no game, no emulator and no timer. An mtime short-circuit makes the 5 s interval free in the common case. First tick deliberately does NOT seed `lastMtimeMs`, so an unlock earned between the last sweep and this launch is still caught.

Ordinary cards beyond the three visible overlay slots wait in a FIFO queue and start their lifetime only when displayed, so closely timed polls cannot silently hide older unlocks.

**Overlay visibility and the real chime (2026-08-23).** The chime is the AUTHENTIC Xbox 360 "Achievement Unlocked" sound — the file Microsoft published on Major Nelson's blog for personal use, bundled at `src/renderer/src/assets/achievement-chime.mp3` and played by `lib/achChime.ts` from inside the overlay window only. Visibility rules every user should know: borderless-windowed games and Windows "Fullscreen Optimizations" (the Win10/11 default) compose the topmost popup over the game; **true exclusive fullscreen bypasses the compositor and NO external window can appear over it** — that needs DLL injection like Steam/Discord overlays, deliberately out of scope. Reliability hardening: raise() re-asserts `alwaysOnTop` + `moveTop()` after every show (fullscreen games can knock topmost windows down the z-order, and Electron has races where the flag silently lapses); failures are logged via `logWarn('achievements', …)` instead of silently falling back; the window anchors to the display nearest the cursor, not blindly the primary (multi-monitor setups get popups on the screen the user is looking at). **"Test popup & sound"** on `/games/achievements` raises the overlay with a fake unlock card without earning anything: `achievements:testPopup` → `requestPopupTest()` stores a test event served through `watchStatus`'s `test`/`testId` fields for a 15 s TTL (lazy age check, no timer); the overlay dedupes by `testId`, the main window's toast hook ignores it, and it works with no session running because showUnlock creates the glass on demand.

Each raise re-evaluates the cursor's display and moves the existing window before showing it, so switching monitors after launch remains correct. The archive explains the exclusive-fullscreen limitation beside the test control.

**Re-fetch is authoritative** for the set (prunes what the provider dropped, refreshes names/art/rarity) but **unlocks survive it while the provider identity is unchanged** — the UNIQUE upsert keeps achievement ids stable, so only a genuinely removed achievement loses its unlock by CASCADE. Changing provider or provider game id first deletes the old set, because `api_name` is not portable between identities and an overlapping value must never inherit an unrelated unlock. Initial provider sync commits the association, canonical set and fetched/on-disk unlock snapshot in one transaction; a failed unlock write restores the prior set. Unlock imports keep the **earliest** timestamp: an emu file rewritten today must not relabel a two-year-old unlock. A file with no usable time falls back to the file's mtime (far closer than "now" for a retroactive sweep). **Timestamps are range-checked twice** (`normalizeTime`, then again in `insertUnlocks`): SQLite's `datetime(?, 'unixepoch')` returns NULL past year 9999 and `unlocked_at` is NOT NULL, so an emulator fork writing microseconds would otherwise abort the insert transaction and discard every good unlock in the batch — and in the watcher that failure is swallowed *after* `lastMtimeMs` advances, silently killing detection for the rest of the session.

**Two watcher races the lifecycle has to survive**, both because `gameLaunch.endSession` clears `active` BEFORE the (async) final sweep, so a new launch is legal inside that window: `stopWatch` retires only the watch it started with (`if (watch === mine)`) and sweeps that same one explicitly (`pollOnce(deps, mine)`), and `startWatch` clears `watch` FIRST so launching an *untracked* game cannot leave the previous game's watch standing. Both are regression-tested. A first-time provider choice is stored before fetch for retry; changing any already-tracked provider/game identity commits only once the complete replacement snapshot lands, or the old achievements could sit on screen mislabelled.

**The renderer polls past the end of a session** (`GRACE_MS`, 20 s): the session status flips to `ended` the instant the game exits, but the final sweep — the one that catches what an emulator flushes on exit, a network call later for RA — lands after that. Without the grace window those unlocks would only surface after reopening the app. `useGameSession` also invalidates `qk.achievements.all` on settle, so the tab, chips and Home strip aren't left showing pre-session counts, and a watcher that has stopped detecting (RA unreachable) surfaces its `message` as a toast rather than looking like a session where nothing was earned.

**Manual toggling is always available** (`source: 'manual'`), the floor for games nothing can track — and it will not overwrite a tracked unlock. **The Goldberg wizard** (`GoldbergWizardDialog` + `generateGoldbergConfig`) is guided, not automatic: it writes a `steam_settings/` folder (achievements.json in Goldberg's shape, steam_appid.txt, copied icons) into a directory the USER picks and shows the copy steps — it deliberately never touches the game folder, since a wrong guess there breaks an install.

**Surfaces**: an Achievements tab on the detail page (`?tab=achievements` deep-links), `/games/achievements` (recent feed, per-game completion, rarest), `/games/installed` (exe-linked games and VNs; a resume-first launcher with wide art when available, hover/focus Play, recent covers, and a searchable/sortable collection), a Home "Recent unlocks" strip that hides itself when empty, and a `✓ n/total` chip on list cards fed by ONE `cardSummaries` map rather than a query per card. Both new routes sit above `/games/:id` (the `/anime/seasonal` precedent) and are `GAME.children` sidebar links. Tests: achievementsCore (path matrix, every file format + damaged input, rarity boundaries, Goldberg round-trip), emuScan (injected IO, glob expansion, multi-emulator merge), achievementRepo (prune-preserves-unlocks, earliest-wins, CASCADEs, real SQL), achievements (URL-routed fixtures for both providers), achievementWatcher (detection, mtime short-circuit, final sweep, quit killer), plus initLegacyDb and sanitizeCoverage extended. **Windows end-to-end — real emulator files, a real fullscreen overlay popup with its chime — is UNVERIFIED on this Linux box** and needs a pass on the user's gaming PC; the emulator path table is community knowledge, so "Import from emulator files" reporting `found: 0` on a game that should have files is the signal to extend it from a real sample.

Installed artwork uses the shared cached thumbnail widths: 320 px for the full cover grid and 480 px for recent covers and the featured foreground cover. A wide featured hero uses its original image. `thumbUrl` selects the smallest supported width that meets a smaller request and uses the original above 480 px or outside `media/`; the server reads the same `THUMB_WIDTHS` list. This prevents a rejected thumbnail request from silently falling back to a full-size cover for every game while scrolling.

Achievements deliberately stay on their own tab rather than gaining a second rail on Playtime — a duplicate of a full grid is chrome, not information.

## Volume thumbnails

**Volume thumbnails (2026-08-16).** `manga_chapter.cover_path` holds the first page of a chapter/volume as a virtual path (`manga/<dir>/<file>`), so the Volumes grid has a thumbnail without opening every chapter. The scanner is the only writer: folder chapters take the first naturally-sorted image (the same order `listChapterPages` uses, so the thumbnail really is the page the reader opens), archives take the first zip entry, and EPUBs get NULL — their "pages" are XHTML spine documents, not images. The upsert COALESCEs it, so a rescan that cannot read the pages keeps the thumbnail it already had. **Existing attached series have it NULL until the next rescan.**

`MangaChaptersSection` gained a Grid/List toggle in `usePersistedState('chapterView')` — grid for browsing (thumbnail, unread ribbon carrying the page count, progress bar on the volume in flight), list for the dense facts and the OCR/EPUB chips. Both views do the same two things: click to read, tick to toggle read.

## Seasonal anime

**Seasonal anime (2026-07-10; bounded projection 2026-09-21)** — `/anime/seasonal` (`SeasonalAnimePage`) shows the library's anime as four stacked Winter→Fall shelves per selected year; entry points are `MediaConfig.hasSeasonal` (list-header button), an `ANIME.children` sidebar link, and a CommandPalette nav item (route sits above `/anime/:id` in App.tsx). Season data: the AniList anime importer persists canonical `season`/`seasonYear` into the `metadata` JSON (`mergeMetadata` accepts positive numbers AND non-empty strings — mirrored in bulk-import.cjs); `@shared/season.ts:seasonForItem` (tests/season.test.ts) prefers validated metadata, falls back to release-date quarters (Jan–Mar=winter …), else the page's Unknown bucket. Its SQL mirrors `seasonForItem` validation, including ignoring a free-form `seasonYear` unless it is a positive integer beside a recognised canonical season.

## Library filtering and sorting

**Library filtering & sorting (2026-07-19, paged 2026-08-31)** — every media type's `MediaListPage` gets one filter model, all of it inside `MediaListFilter` (shared/types.ts) so the whole filter object stays the query key. Repo side, `buildWhere()` and `buildOrder()` remain the one filter/sort implementation, but the browse screen calls `media:listPage` in 96-row pages and receives `MediaSummary`, not `SELECT m.*`; detail prose, notes, provider ids and full metadata never cross IPC for cards. The legacy uncapped `media:list` remains for bounded specialist projections that genuinely need the whole type. Home uses one `media:homeOverview` call: main derives bounded wall/recent/continue/favorite/spotlight shelves plus aggregate counts, preserving positional renamed-status semantics without seven full-library IPC payloads. `mediaRepo.facets(mediaType)` remains the unfiltered title count and slider bounds. Every remaining `qk.media.home(type)` consumer must pass byte-identical `{ mediaType }` because Franchises and Japanese roadmap surfaces share those cache entries; Seasonal owns its year-scoped `qk.media.seasonalAnime` projection.

Home's Spotlight keeps a 24-title payload but rotates that window through the complete planned backlog by local day, so later titles remain eligible. The separate Your people queries request only the eight voice actors and six studios they display. Home treats failed section reads as retryable errors, and waits for the resume query before deciding which continuation belongs in the hero.

**The sort choice is sticky per media type (2026-08-17)** — `lib/listSortPrefs.ts`, one localStorage blob (`library.listSort`) keyed by media type, in the keyboardPrefs idiom. The sort menu itself is unchanged; what changed is that it no longer snapped back to Last updated on every fresh visit, because `usePersistedState` is per-history-entry. `MediaListPage` reads the pref in a `useState` initializer (the shell remounts on every pathname change, so switching libraries re-reads it) and both the menu and the direction toggle write back, so whichever sort you leave a library on IS its default — anime by score, movies by release date, each remembered separately and across restarts. `loadListSort` takes the page's own menu as a whitelist so a renamed key can't restore a blank `<select>`, and a remembered `random` gets a fresh seed per visit rather than the same "random" order forever. `ThemeSongsPage` renders a near-identical sort cluster over the same `MediaSort` type and is deliberately NOT wired to this — it is not a library.


## Franchises

**Franchises (2026-08-15, reworked same day on user feedback)** — `/games/franchises` (`FranchisesPage`) + `/games/franchises/:id` (`FranchisePage`), both above `/games/:id`, sidebar via `GAME.children`. A third feature shape beside CLAUDE.md's A/B: a **curated overlay** over an existing media type. The canon lives in `src/shared/franchises/` (`types.ts`, one file per franchise, `index.ts` catalog — the `wrestling.ts`/`programming/` pattern); franchise, entry and character ids are FROZEN (persisted UI state + route params), entry arrays are authored in release order and `tests/franchises.test.ts` enforces that plus id uniqueness, chrono completeness, `appearsIn` integrity and https-only art URLs. Library rows are matched client-side by `matchLibrary` (`match.ts`, `tests/franchiseMatch.test.ts`): external-id pass first (multiple refs per entry cover Steam re-listings, e.g. Kiwami legacy + 2026 appids), then exact-normalized title/alias equality — never substrings, which is what keeps FF7 and FF7 Remake apart; remakes are separate entries. The pages reuse `qk.media.home('game')` (byte-identical `{ mediaType }` filter, the HomePage rule) and the **positional** finished check (`statuses[1]` via `useStatuses(GAME)`, rename-safe) plus the `progress >= totalUnits` fallback.

**Page layout**: rows in the LEFT half (`lg:grid-cols-2`), Timeline + Characters in the right half, trivia full-width below. Sorting is by **clickable column headers** (Title=release order, Year, Story [hidden when the franchise has no `chrono`], ★ your score, MC) — click again flips direction; nullable columns always sink unowned/unscored rows to the bottom. Rows re-sort **live** with `lib/useFlip.ts:useFlipList` (a dependency-free FLIP: measure `[data-flip-key]` rows in a layout effect, invert with a translateY, reflow, play) — nothing else in the app animates a data-driven reorder (dnd-kit only animates during a drag). The timeline is a horizontally scrollable year strip of **covers** (fixed px per year, lane-packed on collisions): library cover for owned entries (accent ring + ✓ when finished, links to the game), greyed tile when not owned.

**Background** — ONE per franchise, pinned. `FranchiseCfg.heroUrl` (curated, curl-verified) is both the index-card image and the page's default background; the user replaces it with `Set background` in the header (`api.files.pickImage()` → a `media/` path in the settings row `franchise.<id>.background`, `''` = reset since settingsRepo has no delete; `franchiseBackgroundKey()` names it and `scripts/sanitizeSql.cjs` wipes `LIKE 'franchise.%'` on export). `FranchiseBackground.tsx` is a page-local absolute layer using **`background-attachment: fixed`** — anchored to the window viewport but painted only inside the page box, so it holds still while `main` scrolls and can never paint over the sidebar/Topbar; needs no shell widths and is immune to `ui.scale`. Preload-then-cross-fade on URL change, viewport-fixed base-900 gradient scrim. Per-game `bgUrl` on every entry stays **RESERVED** — nothing on the franchise page uses it (the first cut's hover/click per-game swap was explicitly rejected). The per-media background it was reserved alongside SHIPPED on 2026-08-17 as `media_image.is_background` + `MediaDetail.backgroundPath`, painted by this same component on every detail page (see "Right-click on an Art-tab tile" above); the reserved `ImageKind 'background'` is gone.

Curated art (heroes, entry `bgUrl`, character `portraitUrl`) renders from the remote URL immediately (CSP allows `img-src https:`) while `src/main/franchiseArt.ts` caches it content-addressed via `downloadImage` — `franchise:ensureArt(id)` / `franchise:ensureHeroes()` fire a single-flight fire-and-forget batch (one `franchiseArt` task-registry row), `franchise:artStatus` is polled at 1.5 s while running, `franchise:artMap(id)` / `franchise:heroMap()` map url → cached rel path (`files.ts:dlFileName` is the extracted shared derivation; `tests/franchiseArt.test.ts`). Adding a franchise = one data file + a `FRANCHISES` entry; nothing else changes.

## Tier lists

**Tier lists (2026-08-23)** — a tiermaker.com-style board inside the Lists section: `/lists` grew a `Lists | Tier lists` tab pair (`usePersistedState('listsTab')`, shared kind-filter pills), with `/lists/tier/new|:id|:id/edit` routes (the static `tier` segment outranks `/lists/:id`, which is what keeps those URLs unambiguous). Three tables, brand-new so no migration: `tier_list` (same `entity_kind` scoping and KIND-map resolution as `list` — `listRepo.KIND`/`MEDIA_LABEL` are now exported and shared), `tier_row` (label + '#rrggbb' color + sort_order), and `tier_item` whose **`row_id NULL = the unranked pool`** and whose FK is `ON DELETE SET NULL` — deleting a tier returns its items to the pool rather than deleting them, the property the whole UX leans on. New boards seed S–F in the classic pastel ramp; `setRows` replaces ALL rows in one transaction (the Edit-tiers dialog's save) and re-sanitizes label/color main-side (`safeColor` accepts only `#rrggbb`). Every drag persists the WHOLE board through `tierLists:persistBoard(listId, placements)` — containers in display order with their item ids — one transaction per drop, mirroring listRepo's optimistic-reorder-rollback shape.

Renderer: `TierBoard.tsx` is the app's ONE multi-container dnd-kit surface (SortableList is vertical single-container only): one custom `DndContext`, each tray (`row:<id>` strings + `'pool'`) droppable via `useDroppable`, tiles sortable per-container with `rectSortingStrategy`; cross-container moves happen live in `onDragOver` (the official multi-container pattern), order settles in `onDragEnd`. Handlers read a `stateRef` mirror, never the closure — dnd-kit can fire `dragEnd` before React re-renders after the last `dragOver`, and dropping on an empty tray area means `over.id` is the CONTAINER (no index), so the post-dragOver state itself must still be persisted. Export: `lib/tierExport.ts` renders title bar + colored bands + covers to canvas (navimg covers load with `crossOrigin='anonymous'` — the protocol sends ACAO, same contract as the mining screenshot; failures draw initial-letter placeholders) and hands the PNG to `files.saveImageAs`, the one dialog call site that passes a parent window (`BrowserWindow.fromWebContents(e.sender)` — the mitigation for the native-modal focus-steal suspect). Entity deletes clean up via `tierListRepo.removeEntityFromTierLists` from the same four repos that call `removeEntityFromLists`; sanitize wipes all three tables (personal layer, children first); `tests/tierListRepo.test.ts` covers seeding, pool placement, cross-row persistence and row-delete-to-pool.
