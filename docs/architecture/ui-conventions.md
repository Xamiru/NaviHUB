## Shared UI primitives

Renderer interaction tests (2026-09-04) live under `tests/renderer/` and run through the separate `vitest.renderer.config.ts` Node + jsdom suite. Testing Library and user-event drive components through their accessible roles, names and keyboard behavior; `accessibility.ts` runs axe-core for objective markup violations. The main-process suite remains isolated in `vitest.config.ts` and Electron-as-Node so it uses the shipped Node runtime, and `npm run test` first proves the better-sqlite3 N-API binary with a real write/reopen/integrity smoke. `npm run test` and `npm run typecheck` run both halves. Renderer tests are regression evidence, not a substitute for driving the packaged UI on the laptop.

Modal lifecycle is centralized in `components/Dialog.tsx` (2026-09-04). It renders the labelled modal semantics and delegates to `useDialog` for initial focus, capture-phase Escape ownership, Tab containment, and focus restoration; it also owns the existing backdrop-only dismiss rule. `useDialog` remains available for complex legacy overlays but must receive the same labelled panel semantics. ConfirmHost, reader shortcut help, and manga/book completion overlays use the shared component, so a reader shortcut cannot fire behind a focused modal. Anchored menus, popovers, drawers and non-modal reader side panels do not claim modal dialog semantics.

Anchored surfaces share `usePopover` (2026-09-04): outside press, capture-phase Escape, optional first focus, trigger restoration on Escape, and optional Arrow/Home/End menu navigation are one behavior rather than per-component document listeners. It never traps Tab. Triggers own `aria-expanded` and `aria-controls`; pure action lists use `menu`/`menuitem`, while panels mixing navigation, toggles, status and form fields are labelled `region`s. The hook stamps the explicit player-shortcut suspension marker while open, replacing the old accidental dependency on false `role="dialog"` values. Queue, Tasks, Add to List, track actions, playlist actions and ActionMenu use it. ContextMenu keeps its coordinate/scroll/blur listeners but captures the opener before first-item focus, so dismissal restores the actual invoking control. The archive navigation drawer is genuinely modal and uses `useDialog`; the reader settings sibling is an `aside`, not a dialog.

Form naming is centralized in `components/Field.tsx` (2026-09-04). `Field` gives its single native control a stable generated ID, associates a visible or `sr-only` label, and merges description and error references without discarding a caller's existing `aria-describedby`; errors also set `aria-invalid`. `Fieldset` supplies a real legend for related controls, including `PillGroup.Group`. `className="contents"` preserves an existing flex/grid layout when the label is intentionally hidden. Placeholder text remains a hint and never stands in for a programmatic name.

Settings credentials (2026-09-04) never hydrate secret text into the renderer. `settings:all` excludes the protected key registry; `settings:secretStorage` reports only configured/unreadable flags and the selected backend. Secret inputs open blank, blank means keep the existing value, and Clear is explicit and confirmed. The UI names Linux `basic_text` as weak and disables replacement when OS protection is unavailable. Storage and legacy migration live in main (`secretStorage.ts`), not in field components.

Persisted reorder surfaces use both pointer and keyboard sensors (2026-09-04). `SortableList` and `TierBoard` use dnd-kit's `KeyboardSensor` plus `sortableKeyboardCoordinates`: focus a named Move handle, Space to lift, Arrow keys to move, Space to drop, and Escape to cancel. Tier tiles keep Remove as a separate sibling control rather than nesting it inside the drag control. Controls revealed on hover also reveal through `group-focus-within`, and the manga reader's auto-hide timer refuses to hide either bar while focus is inside its chrome.

Nonvisual parity is part of the data and feedback primitives (2026-09-04). `BarChart` hides its decorative bars from the accessibility tree and emits a named exact-value table; `CalendarHeatmap` emits an activity summary plus a table of every active date. Error toasts are assertive alerts, ordinary notifications are polite statuses, and each has a separately named Close control. Their six-second dismissal timer pauses while the notice is hovered or contains focus. `gray-600` remains decorative; meaningful instructions, state, timestamps and category labels use at least `gray-500` and 12px.

Shared UI primitives (2026-07-04, extended 2026-07-06) — reuse before writing new ones: `Section` (uppercase-headed section, `subtitle`/`className` props), `StatTile`, `PageStatus` (page-level loading/not-found), `BackButton` (history-back — ALL detail/form sub-pages use it; fixed-parent `← Japanese`-style breadcrumb Links are the deliberate exception), `SortableList`/`SortableRow`/`useOptimisticReorder` (drag-reorder w/ rollback — playlists + lists; NOT the play queue, which is client-only and can hold duplicate ids → plain ▲▼× buttons), `MusicEntityHeader` (album/artist hero), `playTracks()` in `lib/musicTracks.ts` (every music Play/Shuffle button), `BarChart` (single-series divs chart), `CalendarHeatmap` (GitHub-style year grid), `QuizRecord` (personal best + recent rounds block), `MediaCard` (now `components/MediaCard.tsx` — one card app-wide, `showTypeBadge` for cross-type strips, `showProgressBar` for Continue; MediaListPage re-exports it). **UI consolidation (2026-07-28; semantics repaired 2026-09-04):** `Tabs` is only for page-local view state: the required stable `id` and accessible `label` feed its roving focus, orientation-aware Arrow/Home/End handling and matching `TabPanel` relationship. `RouteTabs` keeps the same underline/inset visual idiom for navigation but renders a named `<nav>`, ordinary Links and `aria-current="page"`, never `role="tab"`; unrelated actions remain outside the `tablist` through the shared `actions` slot. `PageHeader` (title/subtitle/actions; `back="history"` renders BackButton, `back={{to,label}}` renders the quiet breadcrumb — encodes the back convention), `ActionMenu` (text "More" trigger + popover; where Delete and rare actions live — never beside Edit), `DoorCard` (accent-gradient link card, HomePage rail), `EmptyState` (the ONE filled button goes in its `action`), `Pager` (Prev/Next — text labels, no arrows), `StatInline` (compact stat for dense rows — MediaDetail header; StatTile stays for dashboards). **Polish pass (2026-08-01):** `HubCard` (quiet section-hub card — plain card, hover accent border, `to`/`onClick` variants; the hub grids on Japanese/Quiz/Programming homes. DoorCard's glow stays reserved for Home's right rail; GachaHomePage's GameCard is the deliberate exception — it carries the user's per-game hero art), `PillGroup` (`Group`+`Pill` — the labelled single-select pill row on every quiz/tournament setup screen), PageHeader gained `eyebrow` (chip row above the title), `.kbd` (styles.css — THE keyboard-hint chip; quiz options, shortcut lines, Topbar). **Archive Broadcast pass (2026-08-24):** `PageHeader` is now an editorial 3xl title over a bottom hairline, `Section` carries the same expanding hairline, `StatTile` uses a quiet top rule, and `HubCard` is the roomy 126px hub unit. These are global changes; section pages compose them rather than recreating their own mastheads. PageHeader/PageStatus/EmptyState/Section are adopted app-wide — new pages start from them, never a bare `<h1>`/`Loading…` `<p>`. Loading convention: page-level → `PageStatus`; in-section → `<p className="text-sm text-gray-500">Loading…</p>`. One `btn-primary` per screen is enforced; when an `EmptyState` shows, any header button with the same verb is conditionally hidden (its `action` holds the one filled button). Forms convention: `PageHeader back="history"`, labels are `<label className="label">` (never `<div className="label mb-1">` — double margin), full-width bottom `btn-primary` Save, NO Cancel button (Back/Esc is cancel). **NO emoji and NO decorative glyphs anywhere — user directive 2026-07-12, hardened 2026-08-01 (strict purge: button-label prefixes, title glyphs, watermarks, the palette icon column are all gone; `MediaConfig.icon` is no longer rendered anywhere).** Functional glyphs stay: reader HUDs, `✕` close (always with `aria-label`), ✓/○ state marks, ★ score/rarity data badges, `←` in back links, ▸/▾/› disclosure. **Favorite controls (2026-08-27):** every like/favorite mutation uses `FavoriteButton`, backed by `HeartIcon`'s filled/outline SVG states; non-interactive favorite markers reuse the same icon. Unicode hearts are forbidden because their font weight, baseline and presentation vary across platforms. **Right-click menus (2026-08-17):** `ContextMenu` (`{x, y, items, onClose}`) is THE renderer-drawn context menu — `fixed` at the cursor, measured then clamped into the viewport, ActionMenu's look and its mousedown-outside idiom (not `useDialog`), Arrow/Home/End roving focus, closes on scroll (captured — `<main>` scrolls, not the window), resize and window blur, and restores focus to the opener. **Escape and Tab are handled in the CAPTURE phase and stopped**: the Lightbox's `useDialog` also listens for Escape, and without capture one press would close the menu and the viewer together. Electron draws no context menu of its own (main/index.ts adds only cut/copy/paste for text), and an OS menu would be a system-themed rectangle in the middle of the Lain palette. First users: the Art tab's tiles + Lightbox (see [media-types.md](media-types.md)). **Player transport is SVG, never unicode (2026-08-06):** `components/PlayerIcons.tsx` (Play/Pause/Prev/Next, currentColor, 1em) — ⏮/⏭ are emoji-presentation-default codepoints that Windows renders as blue pictures, and `❚❚` never aligns; every transport button (NowPlayingBar, NowPlayingPage, QueuePanel, ThemeRow/ThemeSongsPage play buttons, reader chapter-skip buttons) uses these components.

## Themes — Lain Wired and tactical operations

**Themes (Lain 2026-07, selectable system + Metal Gear 2026-08-30):** Settings → General persists one `ui.theme` value (`lain` or `metal-gear`). `src/shared/appTheme.ts` owns the frozen values, labels and BrowserWindow launch fills; `renderer/lib/theme.ts` owns the localStorage mirror used only to stamp `data-theme` before React paints. The settings database remains authoritative. Lain is the default and retains its phosphor-green Wired terminal. Metal Gear is an original tactical-operations interpretation: charcoal/olive field displays, amber live actions, codec-green linked intelligence, thin grids and a neutral NaviHUB radar mark — never copied logos, characters or game screens. It draws from the series' information-first codec, Mother Base operations/database and iDroid field-terminal ideas without reproducing any one interface.

Palette colors, semantic roles and the radius scale are CSS variables in the styles.css `:root` / `html[data-theme]` blocks, surfaced through Tailwind via `rgb(var(--x) / <alpha-value>)`. Shared chrome prefers `surface-*`, `ink-*`, `line-*`, and `signal-live/link/affirmative/caution/anomaly`; the `base.*`, `accent*`, full `gray` ladder and `white` primitives remain available for content-specific composition and gradual migration. Never hardcode theme colors in renderer code — change or add variables in the theme blocks. Content/data colors stay literal on purpose: StatsPage `TYPE_COLORS`, `shared/gacha.ts` game colors, `MusicPlaceholder`, and stock status colors. Each theme's `gray-500` is AA-safe on every common base surface; `gray-600` and below are decorative telemetry only.

The "WIRED CHROME" section at the bottom of styles.css owns shared metadata typography, brand treatment, glows and inverse video; tactical overrides stay scoped by `data-theme`. Headings/buttons/compact inputs/aside/header use `--font-mono`; body text and all textareas use `--font-body`, with `.code-input` opting SQL or future code editors back into mono. Atmosphere is always a background layer on `.archive-main` and `.wired-surface`, never a viewport overlay above text, dialogs or media art. `ui.signalClarity` is Lain-only; route mood still calms both themes. Any new animation must sit inside `@media (prefers-reduced-motion: no-preference)`. Boot splash `BootSequence` (mounted in main.tsx) runs once per app launch via a module-scope sessionStorage guard (`ui.booted`) and selects its script from the pre-stamped theme. Chrome fonts are bundled `@fontsource` packages: IBM Plex Mono (UI/tactical boot) and VT323 (Lain brand/boot only — single weight, no `…` glyph, no JP). BrowserWindow `backgroundColor` is selected through `appThemeBackground()` and must mirror each theme's `--base-900`. **App icon** (`assets/icon.png`, 512², also the user's desktop shortcut and electron-builder win/linux icon) remains the existing Lain portrait; inside the shell, `AppMark` swaps that portrait for the original radar mark under the tactical theme. The Home cover-wall hero remains pinned and theme-independent.

**Archive Broadcast chrome (2026-08-24, clarified 2026-08-30):** `Sidebar.tsx` is an 80px text-only rail for Home, Library, Play and Learn, with one System destination at the foot. Clicking an area opens its 320px drawer; outside-click, Escape and route changes close it. System owns Tasks, Logs, Bulk Import, Torrents and Settings through that drawer and the contextual Topbar. Drawer destinations, route-area classification and contextual top tabs live in the pure `lib/adaptiveNav.ts` model, which is regression-tested. `MEDIA_CONFIGS` still feeds the library drawer, and `sidebar.hidden` filters both rail drawers and eligible Topbar items without killing routes. `Topbar.tsx` is 76px in two rows: a concrete section noun is primary, its themed descriptor is secondary, and global search sits above horizontally-scrollable route-aware tabs. Longest-prefix matching keeps a parent tab active on detail routes; cross-library entity details use the neutral Connections / Connected archive context. Add or move a routed family in `adaptiveNav.ts`, not ad hoc in either chrome component. The `wired-dot` is the rail's only decorative status. The catch-all route redirects to `/` (Home).

**Wired Hybrid (2026-08-25, extended 2026-08-30):** `lib/surfaceMood.ts` classifies every route as cinematic, standard, quiet or immersive. The persisted `ui.signalClarity` setting adds Clean, Broadcast and Deep Wired levels; `App.tsx` stamps both axes on `<html>`. Mood wins where attention matters: quiet routes remove scanlines, pulse, chromatic split, context scans and ambient glow even when Deep Wired is selected, while the primary action and keyboard focus remain clear. Clean keeps the Lain palette and geometry with atmosphere held still, Broadcast is the balanced default, and Deep Wired strengthens only background depth and signature chrome. `prefers-contrast: more` independently raises muted ink and removes atmospheric interference. `SignalResolve` remains the short selection transition: `ContextPanel` re-keys it with the real entity identity, immediately mounts new evidence, and CSS performs a 180 ms scan-and-lock only when motion is allowed and clarity is not Clean. Readers remain chromeless because they render outside the shell.

## Archive Broadcast composition

The approved family directions are one system with distinct information models: Media uses a hover/focus **Context Lens** beside the catalog; Music leads with the 30-day **Sonic Archive** listening trail; Japanese adds a course-node **Knowledge Map** without removing the adaptive daily loop; English promotes corrections into a **Mistake Ledger**; Programming renders current lessons as a **Skill Graph**; Quiz rotates an existing local format as the daily **Challenge Broadcast**; Gacha sorts the **Operations Board** by due pressure; Wrestling leads with a cross-promotion **Chronology**; manga/books share the optional wider **Study Reader** mining panel; Video defaults new installs to a wider **Transcript First** panel; Tasks/Logs/Imports/Torrents/Settings share the **Task Canvas** navigation rail.

Four renderer-only composition primitives carry that system without changing any feature logic: `EditorialDetailFrame` owns responsive detail widths and optional evidence rails; `ContextPanel`/`ContextFact`/`ContextTrail` render cached relationship evidence; `StudySessionFrame` owns the common context → progress → prompt → evidence → feedback grammar; and `QuietWorkspace` groups forms, configuration and advisory tools behind a calm heading rule. `LearningContextBand` mounts once in the shell and derives the Knowledge Map, Mistake Ledger and Skill Graph summaries from the existing cached queries. These components own geometry only — routes keep their own mutations, shortcuts, scores and persistence.

`StudySessionFrame` exposes determinate session progress as a real ARIA progressbar. Its evidence rail remains sticky at `lg`; below that breakpoint the same evidence and keyboard guidance becomes a collapsed `<details>` block rather than disappearing. `SessionFeedback` owns the polite live region and consumes `signal-affirmative` / `signal-anomaly`, so every learning vertical inherits theme-safe feedback.

The adaptive Topbar is the Task Canvas rail on all five operational routes; pages do not duplicate it in their content. Bulk Import exposes its configure → preview → run state explicitly. Settings search is client-only: `lib/settingsFilter.ts` maps ordinary feature terms to an existing settings section, never reads or sends setting values, and clears when the user chooses a section.

Home remains the exception that identifies the whole product: its user-cover wall is pinned, but its editorial hero now places the newest real resume point first (then the latest in-progress title) before the configurable shelves. At `lg` and above, supporting context panels may sit beside the core surface. Below `lg`, hide those optional panels and keep the primary catalog/player usable; never squeeze a cover grid or video below its useful width. Immersive study panels use `max-w-[44vw]` for the same reason. The shared `.archive-main` atmospheric gradient colors chrome only; artwork supplies content color.

**Renderer performance boundaries (2026-08-31).** `main.tsx` is a thin branch selector: the normal app, player widget and achievement popup are separate lazy roots, so either satellite window never parses the library shell. Inside `App.tsx`, only Home and shared shell chrome are eager; every secondary route sits behind the shared accessible Suspense fallback. Do not turn route pages back into static imports or import one page module from another — move shared constants/helpers into `lib/` instead. `LearningContextBand` reads `PROG_LESSON_COUNT` from the lightweight programming catalog, whose test must agree with the full course bodies. The global audio provider has separate controls and position contexts: rows, shelves, queue panels and study screens use `usePlayerControls()`, while only real scrubber/seek consumers use `usePlayer()` and receive `timeupdate` renders. `CoverImage thumbWidth` belongs on repeated small artwork; `thumbs.ts` serializes cold-cache nativeImage work and yields between jobs because the decode itself is main-thread synchronous. `BookReaderFonts.css` deliberately names only the Japanese WOFF2 assets; Fontsource's stock CSS also emits unused WOFF fallbacks that add 3.75 MiB to every package.

Idle polling remains capability-driven: the task registry keeps its five-second discovery heartbeat because native-menu jobs have no renderer-side start event, while active tasks tighten to 700 ms. TanStack pauses that query in background windows. `OpenFileHandler` collects immediately on focus/visibility and uses a five-second timeout only while visible; do not restore an always-running interval.

**Global search performance (2026-08-31).** `global_search_fts` is a derived FTS5 trigram projection of media, people, companies and characters, maintained by init.sql triggers and count-backfilled in `runMigrations()` for libraries that predate it. Three-character and longer contains-searches use MATCH; one- and two-character searches use escaped LIKE so `%` and `_` are literal. The export sanitizer wipes the projection before pruning library sections, and startup reconstructs it when the source/index counts differ.

## Design previews (the `ui-preview` skill)

**UI previews (2026-08-15):** the VPS has no display, and even on the laptop a redesign is cheaper to judge before it is coded, so `.claude/skills/ui-preview/` renders a screen as ONE self-contained local HTML file under `previews/` (gitignored; the user opens it in a browser or downloads it through VS Code from the VPS — it is never uploaded: standing directive 2026-08-15, nothing from the repo goes to the Claude account). `shell.html` is the app shell in `Sidebar.tsx`/`Topbar.tsx`'s exact markup plus live examples of every primitive above; `build.mjs` runs the mockup through the project's own Tailwind (`tailwind.config.js` + `styles.css`, mockup as the sole content file), inlines the bundled fonts and the Lain avatar as data: URIs (one file, no server, no network), and lists every class token that produced no CSS — a typo in the mock is a typo in the JSX later. The point of compiling with the real config rather than hand-styling a mock: what the user approves is what the component renders, and porting is copy-paste. Mockup sources live in `previews/src/`, builds in `previews/` — both gitignored, neither ever tracked; when the sidebar, topbar or a primitive changes shape, `shell.html` must follow, since it is a copy. A preview is a design step, not verification — the `verify` skill (laptop) still applies once the code exists.

## Menu bar and UI zoom

**Menu bar + UI zoom (2026-08-06):** the native File/Edit/View bar is HIDDEN by default (`ui.menuBar` setting, '1' = shown; Settings → General card, live via `app:setMenuBarVisible`). The default menu STAYS the application menu so its accelerators (Ctrl+R, F11, Ctrl+Shift+I, Ctrl+= / Ctrl+-) work while hidden. Ctrl+wheel zoom is the app's own: a global wheel listener in App.tsx (skipped on reader routes — the manga reader owns Ctrl+wheel for page zoom — and when `defaultPrevented`) calls `app:bumpUiScale`, which steps the SAME persisted `ui.scale` the Settings pills write (main applies + persists, so the controls can't drift). Both `getAllWindows` loops (zoom, menu bar) skip the pop-out player widget (`src/main/widget.ts`) — its 520×64 pill is fixed-size and menu-less by design.
