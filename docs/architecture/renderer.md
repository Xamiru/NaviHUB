# Renderer conventions

Moved verbatim from `CLAUDE.md` (2026-10-18). Read this before any change under `src/renderer/`. Shared primitives and theme designs are in [ui-conventions.md](ui-conventions.md).

- Query keys ONLY from `lib/queryKeys.ts` (`qk`) — invalidation matches by key prefix, so each group's `all` key must remain a prefix of every key in the group.
- The application QueryClient treats renderer queries as local IPC: `networkMode: 'always'` keeps the library readable when Chromium reports the machine offline, and stale mounted queries refetch when the Electron window becomes visible after sleep/minimize. Do not disable focus refetch globally. A failed read is not an empty collection — page-level projections must preserve an error/retry state instead of coercing missing data to `[]`/zero and showing onboarding copy.
- Mutations are plain `await api.…` in event handlers (NOT useMutation); errors surface via the global `unhandledrejection` → toast net in main.tsx. Query errors toast via `QueryCache.onError`.
- Page state that should survive Back: `usePersistedState(name, initial)` from `lib/navState.ts` (never plain useState for filters/search/tabs). It is scoped to the history entry, so it resets on a fresh visit — a choice that should outlive the visit is a **localStorage pref** instead (`keyboardPrefs.ts` and `lib/listSortPrefs.ts`, which remembers the library sort + direction and grid/list layout per media type; seed the `usePersistedState` initial from the pref inside a `useState` initializer so the first render already issues the right query).
- Big lists: `useIncrementalList` (batch 96) + sentinel div. New data never shrinks its rendered window, so a delete, like or poll deep in a list keeps the user's place; pass a `resetKey` (or a `key` on the list's component) for a real change of scope: always for the entity or section a reused route component shows (React keeps the instance across `/people/1` → `/people/2`), and optionally for a search, filter or sort that derives a long list. Search boxes: `useDebouncedValue` before driving queries.
- Launch boundary: `main.tsx` lazily selects `MainAppRoot`, `PlayerWidgetPage` or `AchPopupPage`, so satellite windows never parse the application shell. Inside `App.tsx`, only Home and shared chrome are eager; every secondary route is a `lazy()` import behind the shared Suspense fallback. Never import a page module from another page to share a constant — move shared values to `lib/` or it silently collapses the route split. `tests/performanceBoundaries.test.ts` guards the core boundary.
- Tailwind component classes in `styles.css`: `.btn`, `.btn-primary`, `.btn-ghost`, `.btn-danger`, `.chip`, `.card`, `.input`, `.label`, `.pill`/`.pill-active` (single-select/nav pills — THE active-pill look), `.chip-toggle`/`.chip-toggle-active` (square multi-select grids: kana rows, dojo forms), `.card-glow` (accent gradient card). NOTE: a class that `@apply`s `bg-accent` must set `color: rgb(var(--ink-inverse))` itself — the global inverse-video selector only matches literal markup classes (`.pill-active` does this). Grid: `grid-cols-[repeat(auto-fill,minmax(150px,1fr))]`. Keyboard focus comes from ONE global `:focus-visible` accent-ring rule in styles.css — don't add per-component focus styles. `text-gray-600` is reserved for decorative/inactive markers; readable secondary copy uses `gray-400`+.
- **Routes are navigation, not ARIA tabs.** Use `RouteTabs` for links between URLs; it renders a named `<nav>`, ordinary Links and `aria-current="page"`. Use `Tabs` only for page-local view state, with its required stable `id`/accessible `label` and a matching `TabPanel`; it owns roving focus and orientation-aware Arrow/Home/End keys. Keep unrelated actions in the `actions` slot, which sits outside the `tablist` semantics.
- Archive Broadcast chrome is data-driven: `lib/adaptiveNav.ts` owns rail-area classification, drawer destinations and contextual Topbar tabs. Do not hardcode route models separately in `Sidebar.tsx` or `Topbar.tsx`; update `tests/adaptiveNav.test.ts` with the model. `sidebar.hidden` filters both chrome surfaces but never kills routes. Route changes focus the new page heading through `RouteFocus`. Optional context sidecars disappear below `lg`, except `StudySessionFrame` evidence rails, which may contain instructions and collapse into a `<details>` disclosure. Rail, drawer and Topbar geometry: [ui-conventions.md](ui-conventions.md).
- App themes are persisted by `ui.theme`: `src/shared/appTheme.ts` owns the frozen `lain` / `metal-gear` / `miku` / `twin-peaks` / `seinfeld` / `berserk` / `one-piece` / `jojo` values (Lain is the default). Each theme has one to three styles in `APP_THEME_VARIANT_OPTIONS` (Settings hides the style row for a single style), saved per theme as `ui.themeVariant.<theme>` and stamped as `html[data-theme-variant]`; the first style is the fallback. `renderer/lib/theme.ts` mirrors both values to localStorage only for a flash-free pre-React stamp, and `appThemeBackground(theme, variant)` must match each style's canvas. All themes consume the semantic Tailwind roles (`surface-*`, `ink-*`, `line-*`, `signal-live/link/affirmative/caution/anomaly`); palette changes belong in `styles.css`, never component literals. Fixed dark readers/viewers use `.theme-dark`, and controls over artwork use `.media-contrast` so a light palette cannot erase their text. Artwork and fonts are bundled locally in `renderer/src/assets/themes/` (provenance in its README). Theme behaviour (toasts, loading, empty and error states, the Lain page transition, cursors, palette) branches through `lib/useAppTheme.ts`, which follows the `<html>` stamp; progress ticks report through `celebrateProgress()` in `lib/themeFx.ts`. The approved designs are in [ui-conventions.md](ui-conventions.md).
- Surface intensity is route-driven through the pure `lib/surfaceMood.ts` classifier (`cinematic | standard | quiet | immersive`), plus the Lain-only `ui.signalClarity` choice. Atmosphere stays in shell background layers, never above text, dialogs or media art; quiet routes suppress it, and transitions never delay data or navigation and always honor reduced motion.
- Modals use `components/Dialog.tsx`: it owns the labelled `role="dialog" aria-modal="true"` panel, initial focus, capture-phase Escape, Tab containment, backdrop dismissal and focus restoration. `useDialog(onClose, { initialFocus })` in `lib/hooks.ts` is the low-level escape hatch for an existing custom overlay; attach its ref to a labelled `role="dialog" aria-modal="true" tabIndex={-1}` panel. Anchored non-modal surfaces use `usePopover(open, onClose, options)`: it owns outside press, capture-phase Escape, optional first focus and optional menu-key navigation without trapping Tab; triggers expose `aria-expanded`/`aria-controls`, mixed interactive panels are labelled regions, and action-only lists use `menu`/`menuitem`. Dialog conventions (unified 2026-08-01, lifecycle centralized 2026-09-04): overlay `z-50`, close button is `✕` with `aria-label="Close"`. Icon-only glyph buttons carry `aria-label` mirroring their `title`.
- Native form controls use `components/Field.tsx`: `Field` associates a visible or deliberately screen-reader-only label plus description/error IDs with exactly one input, select or textarea, while `Fieldset` names related controls. Placeholder text is a hint, never the accessible name. Inline layouts may use `className="contents"` to preserve their geometry; do not add an unassociated sibling `<span>` or `<label>`.
- Persisted reordering uses the shared `SortableList`/`SortableRow` or `TierBoard` keyboard sensor: focus the named Move control, press Space, use Arrow keys, then press Space to drop (Escape cancels). Hover-revealed actions must also reveal through `group-focus-within`; auto-hiding reader chrome must stay visible while any of its controls has focus.
- Data-only graphics expose the same exact values as screen-reader tables or summaries (`BarChart`, `CalendarHeatmap`). Error toasts use an assertive `alert`; other notices are polite `status` messages. Every toast has an explicit Close button and its six-second timer pauses while hovered or focused. Meaningful copy and instructions are `text-xs` or larger and `gray-500` or stronger; `gray-600` remains decorative only.
- **Browser tabs** (`lib/browserTabs.ts`, `lib/tabHistory.ts`, `components/TabbedRouter.tsx`, `components/TabStrip.tsx`): up to eight, never restored on launch, strip shown only with two or more. Only the active tab is mounted; a background tab is its own history stack (every entry a unique `location.key`, the first included) plus a title, so `usePersistedState` and scroll restore when it comes back (activation renders as a `POP`). Keep-alive was rejected: pages own window listeners and polling. Navigate only through the router; the routed subtree is keyed by `usePageKey()`; history position comes from `useCanGoBack()`/`useLeaveDeleted()`, never `window.history`. A new quiz, drill or edit form with in-memory progress registers `useTabLeaveGuard(running, 'run')` or `useEditLeaveGuard(draft, ready)`. A page with no heading to read (the readers, the video player) names its tab with `useTabTitleOverride(title)`. Duplicating a tab clones its history under fresh entry keys and copies each entry's navState values across; never let two tabs share a key. Ctrl+W reaches the renderer only because `appMenu.ts` releases the default Close accelerator. Right-clicking a tab opens its menu (Duplicate, Close, Close other tabs, Close tabs to the right, Reopen closed tab). Shortcuts and detail: [ui-conventions.md](ui-conventions.md) "Browser tabs".
- Command palette (`components/CommandPalette.tsx`): Ctrl/Cmd+K anywhere, `/` outside inputs; mounted ONLY in App's shell branch so the chromeless manga reader never sees it. Reuses `qk.search(q)` (shared cache with SearchPage).
- Audio: one global `<audio>` in `lib/player.tsx` (`usePlayer()`). **Every OS-facing metadata surface goes through `displayMeta()` in `lib/playerMeta.ts`** — mediaSession/SMTC, the `PlayerSnapshot` push, the thumbbar — which masks `quiz-` tracks ("Song Quiz", no artist/cover) so the OS overlay can never spoil an answer. Repeat wrap logic must keep its `queue.length > 1` guards so OS media keys cannot skip the quiz's single-track queue. The pop-out widget (`#/widget`) renders `PlayerWidgetPage` alone, with no router, query client or second player provider. The video player takes the OS media session through `usePlayerControls().claimMediaSession` while mounted, so the provider stays the one installer of media-key handlers. Track-id namespaces and `mediaId: null` for music are hard invariants (below); queue editing, persisted prefs and widget geometry are in [music-quiz.md](music-quiz.md).
- Music mutations invalidate the broad `qk.music.all` prefix ON PURPOSE — liked/cover state is denormalized into every track-returning query, and invalidation only refetches *mounted* queries, so narrowing buys ~nothing and risks stale UI. Recent-track query keys include the requested limit because Home, Sonic Archive, and Listening Stats intentionally request different windows.
- Music, Spotify, player and quiz behavior has dense subsystem contracts in [`docs/architecture/music-quiz.md`](music-quiz.md). Before changing those paths, read the relevant sections and preserve their matching rules, persistent state, queue and cancellation semantics, source identities, spoiler boundaries, deterministic dealing, scoring/session policy, metadata masking and tournament-resume behavior unless the user's task explicitly changes them.
- Cross-cutting quiz invariants remain here: time-attack kinds belong in `quizRepo.SCORE_RANKED_KINDS` and log correct/attempted; each page uses one guarded `endGame()` funnel and decides personal best before invalidating history; central pools default to consumed content; shared builders own injected seeded randomness; party/tournament sessions never enter solo personal-best calculations; image/audio loading gates timers and broken assets use unscored replacements.
- HomePage resolves per-type statuses positionally from settings via `statusesFrom` (lib/hooks.ts) — first = in-progress, second = completed, last = planned — so renamed statuses keep the Home strips working. Don't reintroduce `defaultStatuses[i]` lookups. The Settings editor anchors those three roles, inserts new statuses before planned, and checks for titles using a status before renaming or removing it; preserve those guards so tracking values do not become unreachable. Saving a status list also invalidates `qk.media.homeOverview`, whose main-process projection groups titles by those saved positions.
- **After a save or delete, navigate with `replace: true`** so the mutated form/detail route leaves the history stack. Four separate bug reports came from this: Back returning to the edit page after saving, Back landing in the manga reader, Back needing two clicks, Back going to the wrong list after a delete. A page whose subject was **deleted** leaves through `useLeaveDeleted()` (`lib/navState.ts`) instead: it goes back to the nearest earlier history entry that still exists, restored as a Pop with its filters and scroll (so a replaced parent never sits twice in the stack), and replaces with a fallback only when there is none. `TabHistory.forget` drops the deleted page and every entry the `gone` predicate matches from the current tab, behind and ahead, so neither Back nor Forward reaches a dead page; the predicate covers the subject's sub-routes (`/anime/7/edit`, readers, VN study). Leave first, then invalidate without awaiting — awaiting the refetch first flashes "Not found.". Every page whose subject can be deleted (titles, people, studios, characters, lists, tier lists, journeys, Japanese courses and lessons, music, Gallery albums, History entities) leaves this way. `BackButton`, `ParentBackLink` (every `PageHeader back={{to,label}}` crumb) and the readers go back through the tab's history and take a `fallback` for a page opened as a tab's first entry; an in-page Back control never jumps to a fixed parent list.
- Shared UI primitives, the Lain theme and the dialog conventions are catalogued in [`docs/architecture/ui-conventions.md`](ui-conventions.md) — **reuse before writing new ones**.
