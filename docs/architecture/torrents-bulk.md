## Torrent search

**Torrent search (2026-07-21)** — search + orchestration only, NO torrent code: Jackett (user-run, aggregate JSON endpoint `/api/v2.0/indexers/all/results?apikey&Query&Category[]`) supplies results, qBittorrent's WebUI API receives them. `src/main/jackett.ts` (pictures.ts pattern: pure `jackettSearchUrl`/`parseJackettResults` + throwing `searchTorrents`; interactive calls use `rateLimitWaits:0, timeoutMs:20s, retries=1` to fail fast) and `src/main/qbittorrent.ts` (module-level SID session; form-encoded login → `Cookie: SID=…` + `Referer` on `/torrents/add`; creds OPTIONAL = bypass-auth-for-localhost mode skips login; 403 → re-login ONCE, never loop — qBittorrent IP-bans repeated failures; 200 `'Ok.'`/empty = success, `'Fails.'` = duplicate/invalid). Magnet preferred, Jackett-proxied `Link` fallback (`pickAddUrl`). Entry points: unconditional "Find torrents" button on every media detail page (`TorrentSearchDialog`, query prefilled+auto-run from title, categories from `@shared/torrents.ts:torznabCategoriesFor` — anime 5070, manga 7030+5070, game/VN 4050, movie 2000, tv 5000, with an All-categories escape hatch) and the `/torrents` sidebar page (footer, beside Settings; `usePersistedState`). Shared `TorrentResultsTable` sorts client-side (seeders desc default, nulls last), per-row Add with ImageBrowseDialog's pending-map pattern, Details via `app:openExternal`. Settings → Integrations: two Save-&-test cards; Jackett probe = Torznab `t=caps` (instant, hits no indexer — check body for `<error`), qBittorrent probe = `/app/version`; both probes never throw. All 5 settings keys (`jackett.url/api_key`, `qbittorrent.url/username/password`) are wiped in sanitizeSql.cjs. `qk.torrents` is never invalidated (results are ephemeral); dialog/page queries use `retry: false` (main already retried). Tests: torrents/jackett/qbittorrent.test.ts (gachaNews recipe — mocked http, real settings SQL). **Start Jackett button** (`StartJackettButton`, on the Torrents page header, both search-error blocks, and the Settings card): `torrents:ensureJackett` → `ensureJackettRunning` probes the base URL (no API key needed — any HTTP answer = up), and ONLY if down + loopback (`isLocalHost`) runs `jackett.start_cmd` (default `systemctl start --no-ask-password jackett.service`) via `execFile` with **no shell** (argv split by `parseStartCommand`), then polls 45×1s — `--no-ask-password` is load-bearing (a spawned process has no askpass, so a polkit challenge would hang forever). Verified live against the real unit: stop → button → running again in ~13s, which is why the poll budget is generous. `jackett.start_cmd` is machine-specific → wiped in sanitizeSql.cjs. **`TorrentSearchDialog` takes explicit `categories`** (not a MediaType), so non-media callers work: MusicArtistPage's "Find torrents" passes `AUDIO_CATEGORIES` + `discographyQuery(name)` ("<Artist> discography") via `MusicEntityHeader`'s `extraActions` slot.

## Progressive search and filters

**Progressive search + filters (2026-07-21)** — the aggregate endpoint blocks until the SLOWEST indexer answers (measured on the user's 59-indexer instance: 16.7s for a cold query, and a 29.6s case where 56/59 finished in 6.6s but 3 stragglers held the rest), so search is now a **fan-out job**, qBittorrent-style. `jackett.ts` owns a module-level `SearchJob` (musicDownload status pattern — no push channel): `startSearch` (throws synchronously if unconfigured, else returns a job id immediately) enumerates indexers via **`t=indexers&configured=true`** — the ONLY indexer list reachable with just the API key, since `/api/v2.0/indexers` 302s to Jackett's login page even with no admin password (verified live) — then runs a 16-worker pool of per-indexer `searchTorrents(query, cats, indexerId)` calls, pushing rows in as each returns. Empty/failed indexer list ⇒ falls back to ONE aggregate request (`all`), so locked-down Jacketts still work, just not progressively. Workers guard on the job id, so starting a new search or cancelling makes stale ones drop their rows; `cancelSearch` only sets `running=false` and **keeps** what was found (qBittorrent's Stop). `searchStatus(offset)` returns only rows past what the poller holds — a 1359-row search polled every 400ms would otherwise re-clone everything. Renderer: `useTorrentSearch` (lib/) starts + polls via `refetchInterval` while running, accumulating by offset and cancelling on unmount; `TorrentResultsPanel` (shared by page + dialog) shows `N/M indexers · X results`, Stop, and `TorrentFilterBar`. **Filters are pure + tested in `@shared/torrents.ts`** (`applyTorrentFilters`/`EMPTY_TORRENT_FILTER`/`sizeToBytes`): title contains-all-words, exclude-words, min seeders, size min/max (MiB/GiB), tracker multi-select chips built from the results present — a null size/seeder count means UNKNOWN and is kept unless a bound excludes it. Only the standalone page skips auto-run (a fan-out per navigation is too much tracker traffic); the prefilled dialog auto-runs. `TorrentResultsTable` renders through `useIncrementalList` (1000+ rows).

## Search precision

**Search precision (2026-07-21)** — raw indexer results are noisy: substring bleed (searching `akagi` returned `Nige Jouzu no Wak`**`agi`**`mi`) + irrelevant indexers (E-Hentai, audiobook-only). Two fixes, both in `@shared/torrents.ts` (pure, tested) — measured live: `akagi` cat 5070 went 59→30 indexers and 198→44 results. (1) **Word-boundary relevance** (`queryTokens`/`titleMatchesQuery`/`relevanceFilter`): every query token (≥2 chars) must appear in the title as a whole word via Unicode `(?<![\p{L}\p{N}])…(?![\p{L}\p{N}])` lookarounds (CJK-safe); a token-less query is a no-op (never blanks a page). Applied renderer-side in `TorrentResultsPanel` as a **default-on toggle** ("Relevant only · N hidden") BEFORE `applyTorrentFilters` — instant Show-all, never re-queries; `useTorrentSearch` exposes the active `query` to drive it. (2) **Category-scoped fan-out** (`indexersForCategories`, called in `jackett.ts:runSearch`): `parseIndexerList` now also parses each indexer's advertised standard categories (`<category>/<subcat>` ids < 10000); an anime search (`[5070]`) only hits indexers sharing a thousands-bucket (5xxx), skipping audiobook/movie-only ones. Empty categories ("All categories") ⇒ no scoping; indexers advertising no standard cats are kept (unknown coverage); zero matches ⇒ fall back to all. NOTE: general trackers that *claim* anime support still get queried, so the word filter (not scoping) is what removes their junk — scoping is the speed/scope win. No IPC/type contract change (relevance renderer-only, scoping internal, `IndexerInfo` internal to jackett.ts).

## Bulk Import section

**Bulk Import section (2026-08-12)** — `/bulk` (`BulkImportPage`, sidebar FOOTER link beside Torrents): top-N lists for anime/manga/games/VNs/movies/TV, **preview-first** — fetch the list, toggle rows, then import the SELECTION (renderer sends `{sourceId,title}[]` back, so what you saw is what runs). **Previews contain only NEW titles** (2026-08-13, user directive): every source crawl runs each fetched row through the `makeKeep` predicate (`bulkImport.ts`) which rejects duplicates from pagination drift (volatile sorts repeat items across page boundaries; the renderer keys rows and the selection Set by sourceId, so dupes must never leave main), rows already in the library via one `(external_source, media_type)` id-set, and — games only — rows matching a library title after steam.ts's `normTitle` (Steam/IGDB-owned games live in disjoint id spaces; the name bridge is the only thing stopping duplicates). Rejected rows DON'T consume count slots — the crawl keeps paging, so top-100 always means 100 new titles; page caps (`~5x` the minimal pages, TMDB's hard 500) bound the pathological own-everything case. Vocabulary is CODE in `src/shared/bulkImport.ts` (`BULK_SOURCES`, sort keys FROZEN): AniList popular/rated/trending (+ the 18-genre list, anime-only season filter), catalog popular/metacritic/rating/newest (rating needs `ratings_count>=50`, newest needs `added>=5` or day-one shovelware tops it; genre LIKE matches the JSON **with quotes** so 'Card' can't hit 'Board Games'), VNDB rated/voted (rated takes `votecount>=100`; NO genre — tags too rough), TMDB popular/rated (rated takes vote floors 300 movie/150 tv; genre via the per-kind id maps — movie and tv DIFFER; **`EXCLUDED_ORIGINAL_LANGS` drops Indian releases from every movie/TV bulk list** — standing user directive, formerly bulk-import.cjs `--exclude-langs`; discover has no without_original_language param so rows are filtered post-fetch by `original_language` and the crawl keeps paging to fill the count; individual dialog imports unaffected, noted honestly in the page UI. **TV bulk lists additionally drop daily filler and anime** (2026-08-13 directive): talk/news/soap server-side via `without_genres` (`TV_EXCLUDED_GENRE_IDS` = 10763/10766/10767; 'Soap' removed from the TV genre picker since it can never return rows) and anime post-fetch via `isTmdbAnime` — Animation genre 16 AND `ja` original language, so western animation and J-dramas stay; anime belongs to the Anime section via AniList). Books deliberately absent (no usable OL top lists; string ids). Sources gained small additions, existing import paths reused: `anilist.ts` `TOP_QUERY`+`buildTopVariables` (one query serves anime+manga via variables; unset filters are OMITTED — GraphQL skips absent variables, an explicit null would filter on null; FuzzyDateInt year bounds `yyyy0000`/`(yearTo+1)0000`; `topList` spaces its pages 2100ms — 40 back-to-back pages would blow the req/min budget — and a mid-crawl page failure returns the pages already fetched as a PARTIAL list, only a first-page failure throws — `tmdb.discoverTop` (300ms) and `vndb.topList` (600ms) follow the same partial-tolerance + page-delay contract) and **`importAnime/importManga` opts `{liteCharacters}`** (skip the CHARS_QUERY pagination — at AniList's ~30 req/min budget a full-cast 1000-title run is hours; detail-page re-import fetches the rest), `tmdb.ts` `discoverTop`+`buildDiscoverParams` (`/discover`, 20/page, page<=500) and **`importMovie/importTv` opts `{skipOmdb}`** (OMDb free keys are 1000/day), `vndb.ts` `topList`+`buildVndbTopBody` (filters combine `['and',…]` only when >1), catalog `listTop`. **Runner `src/main/bulkImport.ts`** is the musicDownload singleton (NOT withActivity — needs cancel + a readable done state — but the loop calls `beginActivity`/`endActivity` around itself, which is what ARMS progress.ts so each title's images actually reach the Topbar pill; the end is guarded on `status.id` so it never clears a newer run's slot): `start` fire-and-forgets the loop and is polled via `bulk:status` (`lib/useBulkRun.ts`, a useOcrRun port); per-title skip-existing re-check (an `importedById` point lookup + the games title-set, never a per-title Set rebuild), per-title try/catch, **bail after 10 consecutive failures** with a resume hint (steam-backfill posture), cancel keeps counts, inter-title throttle per source (`SOURCE_DELAY_MS`: anilist 2100ms ≈ 28 req/min, vndb 600, tmdb 300, game 0) injectable for tests. No before-quit hook — every title import is its own transaction, so quitting mid-run is already safe. Imports set NO status (user decision). Preview is a plain await in the button handler, NOT useQuery — an enabled query would refire 20 AniList pages on every remount (the Torrents no-auto-run posture) — but the preview + deselection Set are `usePersistedState` so Back never throws away an ~80s crawl; the genre filter is per-source (`bulk.genre` Record, the `bulk.sort` shape) so 'Horror' picked for Movies can't ride into Anime. IPC group `bulk:preview/start/status/cancel`; `qk.bulk` (status only — no preview key, deliberately). Known debt: preview is still ONE blocking IPC with no progress/cancel (the pre-rework Torrents shape); the fix pattern (job + poll) exists in useTorrentSearch if it ever grates. Tests: bulkImport.test.ts (all three builders + the loop with injected importer), gamesCatalog.test.ts listTop block, anilistImport.test.ts liteCharacters (the http mock rejects any paged CHARS_QUERY call).
