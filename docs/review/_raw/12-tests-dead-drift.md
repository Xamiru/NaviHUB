## Tests that assert trivia

The suite genuinely lives up to CLAUDE.md's documented culture ("test the real query, not a hand-written stand-in") — 54 test files were read in full across importers, repos, drill pools, and pure parsers, and nearly all assert exact computed values against real SQL/real logic, with regression-pinning comments (e.g. the `en_word` startup-crash replay in `tests/initLegacyDb.test.ts`, the substring-bleed regression in `tests/torrents.test.ts`, the `out_time_ms`-is-microseconds gotcha in `tests/videoProgress.test.ts`). Content-catalog tests (programming, English content) correctly check uniqueness/shape/referential-integrity, which is the right scope for static authored content.

One genuine finding:

- **`tests/mediaProgress.test.ts:150-154`** —
  ```js
  it('covers every media type with a fallback status list', () => {
    for (const type of ['anime','manga','visual_novel','game','movie','tv','book'] as const) {
      expect(STATUS_FALLBACKS[type].length).toBeGreaterThan(2)
    }
  })
  ```
  Only checks array *length*, never content. `STATUS_FALLBACKS` is read **positionally** by `advanceProgress` (`src/shared/mediaProgress.ts:65-101` — index 0 = in-progress, index 1 = completed, last = planned, a contract CLAUDE.md states explicitly). Cross-checked against the other 102 test files: for `game`, `visual_novel`, `tv`, and `book` specifically, no other test ever drives `advanceProgress`/`parseStatuses`/checklist logging with those types' real status strings (only `anime`/`movie` are exercised via the `ANIME`/`MOVIE` constants elsewhere; `manga` is only incidentally covered for its first transition). A reordered or typo'd entry in `STATUS_FALLBACKS.game` (e.g. swapping the completed/in-progress slots) would still pass this test and silently break the completion flow (checklist mediaLog completion, HomePage's `statusesFrom`, the last-unit-completes branch) for those 4 of 7 media types, with nothing else in the suite catching it. Low severity (config-data typo class, not core logic), but a real gap.

No other genuine trivia found after a deliberately wide search — the suite is not padded here; this is the one instance worth naming.

## bulk-import.cjs drift

`scripts/bulk-import.cjs` (1949 lines) duplicates the import pipeline outside the app, per CLAUDE.md's own "known debt" note (CLAUDE.md:204). Diffed feature-by-feature against `anilist.ts`, `tmdb.ts`, `rawg.ts`, `themes.ts`:

1. **No DB transaction anywhere — every import is autocommit, statement-by-statement, contradicting the "two-phase atomic" rule.** `grep -n "\.transaction\|BEGIN\|COMMIT" scripts/bulk-import.cjs` returns nothing relevant. Real importers wrap writes in `db.transaction()` (`anilist.ts:414,611`, `tmdb.ts:230`, `rawg.ts:82`, `themes.ts:204`). bulk-import.cjs's `alImportAnime`(538-638), `alImportManga`(679-756), `tmdbPersist`(1050-1122), `rawgImportGame`(1547-1601), `atImportThemes`(1773-1819) all interleave image downloads with individual un-transacted `.run()` calls, and each is wrapped in a per-title `try/catch` (e.g. bulk:911-923) that logs "✗ failed" and moves on. A process death mid-title (network drop, OOM on a long run, Ctrl-C) leaves permanently-committed partial rows — a title with a cover but no relations/tags, indistinguishable from a normal row, never retried. **Highest-severity finding**, and it's exactly the scenario a long bulk run is most exposed to.
2. **`downloadImage()` is not content-addressed → orphaned cover files on every re-run.** Real `files.ts:266-283` hashes the URL (`dl-<sha1(url)>`) and skips an already-on-disk file. bulk-import.cjs's own `downloadImage`(bulk:136-151) always fetches and names the file `dl-<pid>-<counter>.ext` — unique every call, no existence check — and does this **before** checking whether the title already exists (`alImportAnime` bulk:544 vs. the `existing` lookup at 546; same pattern at bulk:685, 1051, 1551). The resulting `COALESCE`d UPDATE (bulk:552,693,1058,1564) overwrites `cover_path` with the new file and leaves the old one on disk forever, with no deletion anywhere. `tmdb-top`/`rawg-top` have no `--only-missing` flag, so every run touches every already-imported title — unbounded orphan accumulation on repeat use. (Person/character photos avoid this — they check `row.photo_path` first, bulk:506-509,524-527 — so it's specifically cover art that leaks.)
3. **RAWG: `total_units` is written from RAWG's raw crowd-average `playtime`, never from HLTB — contradicts CLAUDE.md and the script's own `--help` text.** Real `rawg.ts:74-78`: `hltbLengthHours(hltbTimes) ?? (g.playtime > 0 ? g.playtime : null)` — HLTB is authoritative, RAWG is fallback. bulk-import.cjs's `rawgImportGame`(1547-1601) fetches HLTB data and stashes it under `metadata.hltb`(1582) but writes `total_units` unconditionally from `g.playtime`(1566,1573) — there is no `hltbLengthHours`-equivalent anywhere in the file (confirmed by grep). The tool's own `--help` claims "HowLongToBeat play times, same as the in-app importer" (bulk:64-66), which is false for the field the user actually sees ("Length (hours)"). Every bulk-imported game shows a wrong length until manually re-fetched per-title on its detail page.
4. **Missing `epDuration` (per-episode runtime) for AniList anime and TMDB TV.** Real `anilist.ts:331,462` requests/writes `duration`→`metadata.epDuration`; TMDB derives it from data already fetched (`tmdb.ts:427-433`). bulk-import.cjs's `AL_DETAIL_QUERY`(389-421) never requests `duration` at all (zero occurrences of the string in the file), and `tmdbImportTv`(1138-1155) never reads `episode_run_time`/`last_episode_to_air.runtime`. `mediaRepo.ts:359` (`json_extract(metadata,'$.epDuration')`) silently falls back to flat 24min/40min defaults (`mediaRepo.ts:331,350-351`) for every bulk-imported anime/TV title whose real runtime differs (OVAs, shorts, hour-long dramas) — skewing `/stats` time totals, self-correcting only if that exact title is later re-imported through the real UI.
5. **`list_item` cleanup is missing from the character/artist prune step.** Real `anilist.ts:169-174` and `tmdb.ts:355-362` delete `list_item` rows referencing a soon-to-be-swept character *before* deleting the character (since `list_item` has no FK). bulk-import.cjs's shared `pruneCharacters`(219-237, used by both AniList and TMDB paths) skips straight to deleting `credit`/`media_character`/`character` with no `list_item` step; same gap in AnimeThemes' artist sweep (`themes.ts:270-275` cleans it up, bulk's `atImportThemes` bare-deletes at bulk:1817). Effect: a character/artist a user added to a custom List can leave a dangling `list_item` row pointing at a deleted id after a bulk re-import.
6. **Verified accurate (not drift):** AnimeThemes favorite-preservation (snapshot-before-DELETE at bulk:1778-1785, restore at 1803 — genuinely matches `themes.ts:206-216`); season/seasonYear metadata mirroring (`mergeMeta` at bulk:569-573 correctly ports the positive-number/non-empty-string filter); tag caps, `MAX_CHARACTERS`=125/`TMDB_MAX_CAST`=30, dedup keys, and `media_relation`/`media_company`/`credit` population are all consistent between bulk and the real importers.

Net effect for a mixed bulk+UI-import library: partial-write risk on any interrupted bulk run (no rollback), unbounded orphaned cover files on any repeat bulk run, systematically wrong game lengths and skewed anime/TV time-stats for bulk-imported titles that self-correct only per-title on a later UI re-import — producing a library where bulk-imported and UI-imported titles of the same type quietly behave differently in Stats and on detail pages.
