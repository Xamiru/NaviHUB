## Programming section

**Programming section (2026-07-29)** — `/programming` (Learn section): interactive courses + CLI cheatsheets + a typed practice drill. **All content is CODE** (`src/shared/programming/`: `types.ts`, `courses.ts` aggregating one file per course — `goCourse` (17 lessons), `regexCourse`, `gitCourse`, `sqlCourse` — and `cheatsheets.ts`), the checklist.ts idiom taken further: unlike Japanese (seeded to DB because the user edits cards), courses are read-only so app updates update content. Course/lesson/sheet `key` strings are FROZEN; the only table is `prog_progress` (`lesson_key` = `'<courseKey>/<lessonKey>'`, personal → sanitizeSql) and `programmingRepo.complete` validates keys against the catalog. **Lesson bodies are Markdown for `components/Markdown.tsx` — author within its parser's limits** (headings 1-3, FLAT lists, bold/italic/inline code/links, ``` fences; NO tables/blockquotes/nesting), and remember bodies are template literals: escape every backtick and `${`. Pages: `ProgrammingHomePage` (course cards + progress bars), `ProgCoursePage`, `ProgLessonPage` (Markdown body + click-to-check questions — self-check only, nothing logged — + Mark-complete toggle; remounts via `key={courseKey/lessonKey}` so prev/next resets question state), `CheatsheetsPage` (tabs; a non-empty search cuts across ALL sheets), `CliPracticePage` — a **KanaDrill port** (per-keystroke check, red-and-stay miss, Enter reveal/skip with 3/13 re-queue splices, endless, Stop logs `quiz_session` kind **`'cli'`**) with two command-specific twists: Space is typeable (not an Enter alias) and comparison goes through `normalizeCmd` (collapse whitespace, uniform ` | ` around pipes). Practice pool = only cheat entries WITH an `answers` array (canonical spelling first, flags-not-filenames convention); entries without one are reference-only. Adding a course = one new file + an entry in `PROG_COURSES`; adding drillable commands = data only. tests/programming.test.ts validates the whole catalog (unique kebab keys, balanced fences through the real `parseMarkdown`, 4-option questions, normalized answers).

## Round 2

No IPC and no repo: the catalog is shared code, so the whole quiz is client-side. QuizLandingPage gained cards for it and for the existing CLI drill.


## Round 3 — games and tracking (2026-08-15)

**Tracking tables** (all personal → `scripts/sanitizeSql.cjs`): `prog_attempt` (one row per finished lesson self-check — every question answered — append-only; `ProgLessonPage` records it once behind a `recordedRef`, `ProgCoursePage` shows the per-lesson best via the pure `@shared/programming/attempts.ts:bestAttempts()`), `prog_cli_miss` (`cmd_key` = FROZEN `<sheetKey>/<answers[0]>` — now `CliPracticeItem.key`; a miss bumps `misses`, a first-try hit walks it back, rows at 0 are deleted; `CliPracticePage` reports the round at Stop via `programming:recordCliRound`, the home page renders "Weak commands" + "Drill these" → `/programming/practice?weak=1`, which presets the "Weak commands only" pool toggle), `prog_solve` (`kind` FROZEN `sql`|`regex`, `key` = exercise/puzzle key validated against the content module; regex keeps the shortest `best` + its pattern via `ON CONFLICT … MIN`, sql is `INSERT OR IGNORE`). Repo: `programmingRepo.ts` (`recordAttempt/attempts/recordCliRound/cliMisses/recordSolve/solves`); channels `programming:*` mirrored in api/preload; `qk.programming.attempts/cliMisses/solves/sqlExpected(key)`. Checklist def `prog-lesson` (weekly, detect source `progLesson` over `prog_progress.completed_at`) — NOT seeded (the `game-session` precedent); the user adds it from the checklist Add dialog.

**SQL sandbox** (`/programming/sql`, `pages/SqlSandboxPage.tsx`): content is `src/shared/programming/sqlExercises.ts` — `SQL_DATASET` (studio/anime/episode/tag/anime_tag, ~160 rows, deliberate NULLs, `tables[]` drives the Schema panel and is checked against `PRAGMA table_info`) + 30 `SQL_EXERCISES` (levels 1-3, `expectedSql`, `orderMatters` only for "ordered by" prompts, prompts NAME every result column — tests/sqlSandbox.test.ts enforces all of it). Runtime is split pure/IO: `src/main/sqlSandboxCore.ts` (`openSandboxDb` = `:memory:` + `PRAGMA query_only`, `validateUserSql` rejects RECURSIVE/ATTACH/PRAGMA/…, `runUserSql` refuses `!stmt.reader` and multi-statement, caps rows; `compareResults` = columns by name case/order-insensitive, rows as a multiset unless `orderMatters`, numbers ±1e-9, NULL = NULL) and `src/main/sqlSandbox.ts` (IO): the user's query runs in **a utility process** (`sqlSandboxChild.ts`, bundled via electron-vite `?modulePath`, `hard_heap_limit` 128 MB) with a 2 s deadline → `kill()` + respawn on the next run, idle-killed after 5 min (unref'd timeout), `killSqlSandbox()` in the before-quit registry. Why a process and not a worker or a row cap: a missing-join-condition aggregate finishes inside `sqlite3_step()` before any row comes back, better-sqlite3 has no interrupt, and a worker thread cannot be terminated mid-native-call. Expected rows come from trusted content on a memoized main-thread handle. No `quiz_session` — a sandbox has no round; `prog_solve` is the record. **Packaged-mode smoke test pending on the laptop** (`utilityProcess.fork` of a chunk inside app.asar loading the unpacked better-sqlite3); fallback design if it fails: `?nodeWorker` + `terminate()`.

**Regex golf** (`/programming/regex-golf`, `pages/RegexGolfPage.tsx`): `src/shared/programming/regexGolf.ts` = 26 puzzles (`mustMatch`/`mustNotMatch` ≤ 20 chars each — bounds backtracking — `par`, `solution` proven ≤ par by tests/regexGolf.test.ts, optional `flagsAllowed` ⊆ `ims`) + pure `gradeRegexGolf` (JS `RegExp` in try/catch, pattern ≤ 120 chars, renderer-only, debounced 150 ms). A solve → `prog_solve('regex', key, best = length, answer = pattern)`; a round of N puzzles logs `QuizKind` **`regexGolf`** (score = solved, total = played).

**Snippet decks** (predict the output / spot the bug): `src/shared/programming/snippets.ts` concatenates one file per language under `snippets/{go,python,shell,sql,ts}.ts` (`ProgSnippet {key '<lang>-<slug>', lang, kind, code ≤ 20 lines, options[4], correct, explain}`; every python/shell/sql/ts snippet was executed on the authoring machine, go ones reasoned). Served as the third mode of `ProgrammingQuizPage` (Language + Kind pills; kind stays `'programming'` with `settings.mode = 'snippets'`); the pool builders moved to pure `src/shared/programming/quizPools.ts` (`courseQuestions/commandQuestions/snippetQuestions`, rng-injectable, tests/programming.test.ts) and each question carries `reviewTo/reviewLabel`, which the summary turns into "Missed 3 from Go · Interfaces → Review" (course → lesson route, command → `/programming/cheatsheets?sheet=<key>` — CheatsheetsPage seeds its tab from the param). `ProgLessonPage` now shuffles a question's options once per mount (authored order put 43% of answers at index 1). `tests/programmingBias.test.ts` caps strict-longest and strict-shortest correct options at 30% per course and per snippet language, forbids a strict-longest correct wider than 1.5× the runner-up, and lists every offender in its message.

**Courses ×4 + a `linux` cheatsheet (2026-08-15)** — `tsCourse.ts` (`typescript-deep-dive`), `pythonCourse.ts` (`python-beyond-basics`), `linuxCourse.ts` (`linux-internals`), `algoCourse.ts` (`algorithms`): 10 lessons each, 3-5 questions per lesson, authored one file per subagent against the tightened `tests/programming.test.ts` (explain required, no all/none-of-the-above, ≥ 3 q/lesson, ≥ 7 lessons/course) + `programmingBias.test.ts`; python/TS/shell samples were executed on the authoring machine, Go ones reasoned. The 14th cheatsheet `linux` (`strace -f -p`, `dmesg -T`, `ip r`, `ss -s`, `tcpdump`, `nc -zv`, `nft list ruleset`, `resolvectl status`, `lsblk`, `findmnt`, …) carries the commands the course explains that the processes/system/network sheets did not already list; all drillable.

## Round 4 — Data Science and Engineering mastery path (2026-08-30)

`dataScienceEngineeringCourse.ts` (`data-science-engineering`) is the user's self-contained beginner-to-master path and must not assume external study material. Its 36 ordered lessons start with the data lifecycle, Python, reproducible environments, NumPy, pandas, cleaning and analytical SQL; teach visualization, statistics, probability, estimation, experiments and causality; cover classical ML, deep learning, text/retrieval, interpretability, fairness and production ML; then cover ingestion, idempotent ETL/ELT, dimensional modeling, Parquet, warehouses/lakehouses, modular transformations, Airflow 3's `airflow.sdk`, Spark, Kafka, data quality, governance, security, cost and incidents. The final two lessons specify three end-to-end capstones: a local analytics platform, a weekly production-ML intervention system, and a replay-safe streaming reliability system. Every lesson includes `## Guided practice`, `## Worked solution`, and exactly four explained self-checks (144 total), so it also feeds the normal Programming Quiz. `tests/programming.test.ts` freezes the dependency order, 36/144 scope, minimum lesson substance and solution markers; `tests/programmingBias.test.ts` keeps its answers within the same anti-length-tell bounds as every other course.

- `fullStackWebCourse.ts` (`full-stack-web`, 16 lessons) covers web protocols, semantic HTML, CSS, responsive layout, JavaScript, DOM and asynchronous browser APIs; TypeScript, accessibility, React, state and routing; Node APIs, identity, relational data, testing, performance, delivery and an accessible production application capstone.

- `computerSystemsCCourse.ts` (`computer-systems-c`, 17 lessons) covers machine representation, the C language and toolchain, pointers, ownership, buffers, ABI and linking; debugging, system calls, processes, threads, atomics, virtual memory, filesystems, sockets, performance, native-code hardening and shell, allocator and server capstones.
- `databaseEngineeringCourse.ts` (`database-engineering`, 15 lessons) covers relational modeling and SQL, storage pages, indexes and query plans; transactions, MVCC and isolation, online schema evolution, partitioning, replication, sharding, backup and point-in-time recovery, operations, capacity, privacy, security and a production data-platform capstone.

`masteryCourse.ts` owns the shared teaching contract for these paths: `## Foundations`, `## Engineering model`, `## Failure modes and judgment`, `## Guided practice`, `## Worked solution`, and `## Mastery standard`, plus balanced explained self-checks that do not reveal the correct answer by length. `tests/programming.test.ts` freezes all six prerequisite orders, the 100/400 scope, every section marker and a 250-word lesson floor; `tests/programmingBias.test.ts` applies the existing catalog-wide answer-shape limits. Their content is bundled shared code, so study needs no network, account, live documentation or external course.

The full course catalog is a lazy main-process boundary as well as a renderer route chunk. `ipc.ts` registers every `programming:*` channel at startup but dynamically imports `repos/programmingRepo` on first use; `sqlSandbox.ts` does the same only when recording a correct solve. Do not restore a static import in either file — it adds the entire offline catalog to the launch bundle.
