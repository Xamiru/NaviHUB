## VN reading, discovery and editions

`/visual-novels/:id/reading` owns the personal reading workspace. `vnReadingRepo`
validates VN ownership, route parents and cycles, completion dates, ratings and full
reorders. `vn_reading_node`, `vn_reading_resume` and `vn_notebook` are separate from
canonical imports and overall media progress: completing an ending never invents
minutes or completes the whole title. Removing a node clears its references while
retaining child entries, notes and the resume recap. Dated notebook entries paginate
in batches of 20; optional raster attachments are bounded inline data and disappear
with personal rows during export.

`/visual-novels/discover` issues explicit, paginated Kana searches through
`vndbExplore`. Filters include title, language, platform, length category, minimum
rating and up to ten selected tags. Tag filters include spoiler level 2. Nothing
hides source descriptions or results. VNDB imports now authoritatively write tags,
related VNs and language/platform metadata; partial refreshes return before these
child writes. The standalone bulk-import script has no VNDB import implementation
to mirror. Existing library titles need a full VNDB re-import for these fields.

`/visual-novels/:id/editions` reads `vn_release_cache` offline. Refresh explicitly
fetches every release page before replacing the cache; failures or the 3,000-release
cap retain the last complete cache. Partial dates stay partial. `vn_edition` stores
one personal release snapshot plus installation/translation/patch notes. A release
missing from a later cache remains identifiable and editable. It is never silently
replaced by a different release. Personal edition rows are wiped from exports;
public release metadata may remain.

## Detail page tabs

`MediaDetailPage` is tabbed (2026-07-28): Overview / `castSectionTitle` / an optional media tab named by `cfg.mediaTabLabel` (Theme Songs / Chapters / Volumes / Playtime / Seasons — absent means no tab, as for movies) / Art. `?tab=` deep-links a tab; the Comprehension page passes `?tab=media`. **Header (redesigned 2026-10-04).** Every type uses the same three-column header: the cover; then an eyebrow (type and season or year), the title, community scores, tags and ONE action row along the cover's bottom edge; then the `TrackingCard` (below `xl` it drops under the header as a full-width row). The action row has ONE `btn-primary`: log progress, or **Play** for a game/VN with a linked exe (`GameLaunchButton`, which also owns launching — `GameLaunchSection` on the Playtime tab has no Play of its own), in which case the log button drops to ghost. Then Edit, Add to list, More (`ActionMenu`: Find torrents, Refresh, Change cover, Delete) and the `FavoriteButton`. `TrackingCard` is where personal state is edited in place — a status select (the empty choice clears it; completing a unit-based title fills progress), the progress readout and bar, a star score (one star per point up to a ten-point scale, a number input beyond that; clicking the lit score clears it) and times consumed — so `MediaFormPage` is the full editor rather than the only way in. With no Art-tab background, a blur of the cover itself (`CoverBackdrop`) sits behind the header; it downloads nothing, so it is not the removed banner hero (see [removed.md](removed.md)). The Overview tab is a reading column (synopsis held to 72ch, notes, the first six cast entries in the cast-tab cards with "All N ›" switching tabs, related titles) beside a facts column (released, season, companies with their roles, and the user's lists that hold the title).

## TV seasons and episodes

**The episode catalogue (2026-08-15).** `tv_episode` holds TMDB's list of what a show *contains*; `video_file` stays the index of what you *have*. A row exists for every episode whether or not the file does, and `tvRepo.listSeasons` joins the two on `(season, number)` so an episode you own can offer Play without the renderer running a second query. TV's `mediaTabLabel` is `'Seasons'` (the tick grid) and its `videoTabLabel` dropped from `'Episodes'` to `'Files'` — two tabs called Episodes would have been a coin toss.

**Import.** `importTv` fetches `/tv/{id}/season/{n}` once per season, in season order, during the network phase — so `absolute` (1-based across the whole run) is numbered before any write, and the writes stay in `persistTitle`'s single transaction. **Specials (season 0) are skipped**: `absolute` has to agree with `media_item.total_units`, which is TMDB's `number_of_episodes` and excludes them. A season whose fetch fails is logged through `logWarn('http', …)` and skipped rather than failing the import, and `replaceEpisodes` is a no-op when handed an empty list, so a show whose season fetches ALL failed keeps the catalogue it already had instead of being pruned to nothing. When only SOME seasons fail, `replaceEpisodes` prunes only inside the seasons it was actually given — `EpisodeCatalogue` carries `seasons` alongside `episodes` because a season TMDB failed to serve is indistinguishable from one that lost all its episodes, and a show-wide prune against a partial keep-list would delete that season's rows *and their `watched_at`*, which no later re-import restores. A partial run also publishes `absolute: null` rather than numbers it knows are short; the upsert COALESCEs so an earlier complete run's numbering survives. Episode stills are deliberately not downloaded — a long-running show is hundreds of images and the grid does not show one.

**Progress.** `tvRepo` never writes `media_item.progress`. `setWatched` returns `firstTime` and `ipc.ts` routes it through `checklistRepo.logProgress`, exactly as `video:markWatched` does. The tick goes through `checklistRepo.logEpisodeProgress`, whose footprint (log id plus before/after tracking) is stored in the row's `progress_undo` (`tv_episode` and `video_file`); un-ticking takes it and `retractEpisodeProgress` drops the credit and restores the row exactly when nothing moved it since, otherwise steps progress back one, so toggling cannot stack progress. Ticks from before the column existed have no footprint and are not retracted — the app keeps ONE "I watched another one" write, which owns status promotion, the rewatch wrap and checklist credit. A season toggle logs once per newly-watched episode but passes **`{ noRewatch: true }`**: bulk-marking back-fills a catalogue, so it credits the board while holding an already-finished show exactly where it is. Ticking ONE episode by hand still wraps — that is a deliberate "I just watched this". (Without it, the Seasons tab arriving empty on long-finished shows made the natural first click knock them back to Watching with `rewatch_count` bumped, none of which unmarking restores.) The UI's "season complete" test counts **aired** episodes (`total - unaired`), or the button never offers the undo. Marking a season skips unaired episodes (you cannot have seen them); unmarking clears every one, so it is a reliable undo. An episode with no air date counts as aired — TMDB leaves it blank on plenty of old shows, and greying those out would be worse than an occasional early tick.

**Re-import is authoritative** here like everywhere else: canonical fields refresh, episodes TMDB no longer lists are pruned by an inlined row-value keep-list (every element forced through `Number()` first, since a row-value `IN` cannot be parameterised), and `watched_at` is never in the UPDATE so it survives. It is also the one personal column in the table, cleared by `sanitizeSql.cjs` while the catalogue itself ships.

## Wallpapers and fan art

**Wallpapers/fan art (2026-07-09):** every media detail page gets a Wallpapers `MediaImagesSection`; non-movie/TV types also get Fan Art (`cfg.hasFanArt`). One `media_image` table (`kind` column — exactly the two Art-tab grids; a page background is a FLAG on one of these rows, not a third kind), rows stripped on export (sanitizeSql.cjs). `src/main/pictures.ts` owns SQL + searches: Wallhaven (purity=100 SFW hardcoded — regression-tested) and TMDB backdrops (`tmdb.ts:fetchBackdrops`, movie/tv with `external_source='tmdb'` only). Searches go through IPC (renderer CSP has no `connect-src https:`; remote *thumbnails* are fine — `img-src https:`). `ImageBrowseDialog` per-tile busy/added state; `Lightbox.tsx` is the app's only fullscreen image modal (←/→ wrap). Remote covers and Art-tab images stream through bounded sibling partials in `files.ts`; only a completed download is renamed into view, and failures/cancellation leave neither a truncated final file nor partial debris. Removing an image deletes its file (pictures/ paths only); deleting media cascades rows but leaves files.

**Browse sources (2026-09-27).** The Browse dialog renders whatever `pictures:sources(mediaId, kind)` returns (`pictures.listSources`, tab order) and runs every search through one `pictures:search(mediaId, source, query, page)`; the per-source fetchers and pure parsers live in `src/main/artSources.ts`. Sources: Wallhaven (all types); Danbooru (anime, manga, VN, game — first tab for fan art; typed text is resolved through Danbooru's autocomplete to a copyright or character tag, and the dialog offers the title's first eight characters as one-click searches); TMDB backdrops and fanart.tv (TMDB-imported movies/TV; fanart.tv keys TV by TheTVDB id via TMDB `external_ids`); the AniList banner (AniList imports); VNDB screenshots (VNDB imports); Steam store art and SteamGridDB heroes (games — bound to the Steam app id for Steam imports, otherwise title-searched). fanart.tv and SteamGridDB need optional keys (`fanarttv.api_key`, `steamgriddb.api_key`, both secret settings); without one the tab explains where to add it. IGDB artworks were considered and rejected: IGDB's Twitch sign-up is unusable for this user (see importers.md). Steam `appdetails` can answer under an edition's key rather than the requested id, so the art parser reads the single entry. Saved files are named `<source>-<id>`. Danbooru's CDN (`cdn.donmai.us`) refuses two things: any request with `Sec-Fetch-Site: cross-site`, which Chromium sends for every remote `<img>`, and Node's default `node` User-Agent. So Danbooru thumbnails are fetched in main and returned as `data:` URLs, and `files.downloadImageTo` always sends the app's User-Agent.

**Right-click on an Art-tab tile (2026-08-17)** — two actions, on the tile and on the same image inside the Lightbox, drawn by `components/ContextMenu.tsx` (the app's first renderer-drawn context menu; see [ui-conventions.md](ui-conventions.md)). Every read of an image row goes through `IMAGE_SELECT` in pictures.ts, which carries both states so the tile markers ("Background" in accent, "Slideshow" in gray, bottom-right beside the w×h badge) need no second query.

- **Set background / Clear background** → `pictures:setBackground(mediaId, imageId | null)` sets `media_image.is_background`, clearing the whole item first so at most one row carries it (transaction; a foreign `imageId` throws and leaves the old flag alone). `mediaRepo.get` resolves it into `MediaDetail.backgroundPath`, and `MediaDetailPage` paints it with the SAME `FranchiseBackground.tsx` the franchise pages use — absolute child of the page root, `background-attachment: fixed`, base-900 scrim, preload cross-fade — under a `relative z-10` content wrapper, so it never covers the sidebar/Topbar. Works on every media type, not just games. Movies now use the plain two-column header like TV; the backdrop is no longer used by the current media configs. Storage is a flag rather than a `media_item` pointer so it dies with the row: no dangling id, and the export sanitizer already wipes `media_image` wholesale. **This retires the reserved `ImageKind 'background'`** (2026-08 shape) — it was never written, and a separate kind would have duplicated the file on disk and hidden it from the grid.
- **Add to / Remove from slideshow** → `pictures:toggleSlideshow(imageId)` COPIES the file into `slideshow.dir` (default `<pictures.dir>/Slideshow`, Settings → Folders, with an "Open folder" button) and records `slideshow_item(image_id UNIQUE FK CASCADE, file_name)`. The user points **Windows Settings > Personalization > Background > Slideshow** at that folder once and the OS rotates the images — deliberately NOT an in-app wallpaper setter: that would need a second main-side `setInterval` (the achievement watcher owns the only one) and would stop working the moment NaviHUB closed. `slideshow.dir` is the one picture root that is NOT a navimg prefix — nothing in the app displays these copies. `copyIntoSlideshow` de-clashes names (`Berserk - one (2).jpg`) and throws if the source is gone, so no row can claim a missing copy; removal is best-effort, which is also the repair path for a copy the user deleted in Explorer (toggle off, toggle on). `removeImage` deletes the copy too, and `media:remove` calls `forgetSlideshowForMedia` first — the rows would cascade, but the files would linger in a folder Windows is actively cycling.

## Pictures gallery

**Pictures section (2026-10-02).** `/pictures` (drawer entry and `sidebar.hidden` key `pictures`; contextual tabs Gallery and Albums) shows every `media_image` row across titles in justified rows (`lib/justifiedRows.ts`, pure and tested; `components/pictures/JustifiedGallery.tsx`), with filters for section/type, one title, Unsorted, kind, shape, favorites, in-slideshow and tags. Filters ride `usePersistedState`; the sort is a localStorage pref (`pictures.sort`). Since 2026-10-04 the filters are one row (title picker, a Section select, Kind and Shape pill groups (picking the active pill again clears it), Favorites and In slideshow toggles, Sort at the end), and the header holds a single Slideshow menu: the mirror source choices with a ✓ on the current one, then Open slideshow folder. `pictureLibrary.ts` owns the gallery layer; `pictures.ts` keeps the Art-tab operations and sources.

- **Unsorted.** `media_image.media_id` is nullable (the `dropNotNull` rebuild in `runMigrations`, which re-creates `idx_media_image_media`). NULL is the Unsorted bucket, stored under `pictures/Unsorted/<wallpapers|fanart>/`. Its Browse offers only Wallhaven and Danbooru with an empty query; its slideshow copies are named `Unsorted - <file>`. Dedup is per `(media_id IS ?, kind, source_url)`.
- **Personal state.** `is_favorite` on the row (ensureColumn plus a partial index in `runMigrations`); `picture_album`/`picture_album_item` (own `sort_order`) and `picture_tag`/`picture_tag_link`, kept apart from the media `tag` table so they never reach `/tags` or an importer prune. A tag exists only through its images: untagging the last one deletes it, and renaming onto an existing name merges. All four tables and the source setting are wiped on export.
- **Moving.** `moveImages(ids, mediaId | null, kind | null)` moves the file first (`files.moveImageInto`, de-clashed, throws on failure) and then rewrites the row; a move to another title clears `is_background`. The slideshow copy keeps its old name.
- **Dimensions.** `imageDims.ts` reads PNG/JPEG/WebP/GIF/BMP headers (pure parser, then one bounded read; JPEG retries with a larger read when EXIF pushes the frame header past 64 KB). `insertImage` probes file and URL adds; `pictures:gallery` first backfills up to 200 rows with NULL dimensions. 0 means "probed, unreadable", so a broken file is not re-read on every visit; `rowToImage` reports it as null and the renderer falls back to 16:9 or 2:3 by kind.
- **Slideshow mirror.** `pictures.slideshowSource` is `manual` (the per-image toggle), `favorites` or `album:<id>`. With a mirror source the folder equals that set: `syncSlideshow()` diffs `slideshow_item` against it, removes what left and copies what joined, one sync at a time. Favorite and album-membership changes resync; ten or more changes run as a cancellable `pictureSlideshow` task, and `cancelSlideshowSync()` is in the before-quit registry. In mirror mode `toggleSlideshow` refuses and the menus hide the toggle. Deleting the mirrored album, or an album id that no longer exists, falls back to Manual and keeps the current copies. A failed copy is counted and skipped.
- **Shared actions.** `components/pictures/PictureActions.tsx` builds the one menu (favorite, album, tags, move, slideshow, background, cover, open title, remove) used by the gallery, albums and the title Art tab, for one image or the gallery's selection (Ctrl/Shift-click or the tile's Select control). `PictureBrowser.tsx` is the shared body: count, Play slideshow, the bulk bar, grid, Lightbox and menu.
- **Viewing.** `Lightbox` takes `slideshow`/`autoplay`: play/pause (Space), 5/10/20 s and shuffle via `shuffle()`. The timer is a renderer timeout restarted on every image change, not a main-side interval.
- **Elsewhere.** The gallery's Add pictures dialog picks a title or Unsorted, then reuses `ImageBrowseDialog` (now taking a `BrowseTarget`), files or URL. The Home `pictures` widget shows one random favorite, redrawn on each Home visit but not on window focus, and renders nothing without favorites. Gallery tiles use `thumb/480/pictures/…`.

## Hand-picked images

**Manual covers, photos and character images (2026-09-27).** A media cover, person photo or character image can be replaced from one `ImagePickerDialog` (local file, pasted URL, or an image from the title's Art tab, which is copied into `media/` because removing a tile deletes its `pictures/` file). Entry points: the detail page's More → Change cover…, the Edit form, Art-tab right-click → Use as cover, and `EntityHeader`'s More → Change image…, which saves at once (people, characters, studios, music artists and albums; only people and characters carry a lock, since no importer overwrites company logos, and music art only fills missing covers).

On an imported entity (`external_source` set) the pick is held in `image_override(kind, entity_id, manual_path, provider_path)`. Enforcement is three `AFTER UPDATE OF <column>` triggers in `init.sql` rather than per-importer SQL: any write that differs from `manual_path` is recorded as `provider_path` and undone. That covers all importers, library refresh `only:['cover']` and `bulk-import.cjs` without touching them. `imageOverrideRepo.setManual` inserts the row before writing the column, so its own write is a no-op for the trigger; `revert` deletes the row and restores `provider_path` offline. `provider_path` is kept from the first pick, so repeated picks still revert to the imported image. `manual_path` NULL is a deliberate "no image". Delete triggers drop the row with its entity (the table is FK-less across three parents).

Music album covers and artist photos use the same table (`music_album`/`music_artist` kinds, always lockable because the scanner's folder/embedded art and the online fetcher both write `cover_path`); their triggers sit after the music tables in `init.sql`. `MusicEntityHeader`'s Library maintenance menu has Change cover…/Change photo…, saving through `setManual` at once. Clear cover/photo deletes the pick as well, so Find can run again. The picker offers no Remove for music, because Clear already does that.

Forms never write the image column on save: the Edit form omits `coverPath` in edit mode and calls `setManual` only when the cover changed in that session, so a form opened before a re-import cannot write the old cover back. `EntityHeader` calls `setManual` before the page's upsert. Since 2026-10-04 `EntityHeader` is a read view (portrait and facts beside the name, actions and long text, with the page's sections as its children); name, native name, long text and page-specific fields such as a company's type are edited in its Edit dialog. Picks made before this shipped have no override row, so the next re-import replaces them.

## Image storage folders

**Pictures and media roots (2026-09-27).** Two app-owned image roots: `pictures.dir` (Art-tab wallpapers and fan art, one readable folder per title, plus the default `Slideshow/`) and `media.dir` (imported covers, photos and character images, content-addressed `dl-<hash>` files, `music-covers/`, and hand-picked images in `picked/`). Rows store `pictures/…` and `media/…` paths relative to them, so relocating a root is move-files-then-change-one-setting.

- **Pinning.** `storageMove.pinPicturesDir()` runs at startup: an unset `pictures.dir` is pinned to `<userData>/pictures` when that folder already has files, otherwise to the OS Pictures folder (`<Pictures>/NaviHUB`), where Explorer, Photos and the Windows slideshow setting can see it. `media.dir` stays unset (default `<userData>/media`) until moved.
- **Moving.** Settings → Keys & Folders shows both roots read-only with Move… and Open folder (`StorageFolderSetting`). `storageMove.start` refuses while any task runs, and refuses a destination that is not empty or that overlaps the other root or a library folder (`storageCore.moveTargetProblem`, case-insensitive on Windows). `relocate` tries one `rename` (same drive); otherwise it checks free space, copies every file with a size check, **then** writes the setting, copies anything written into the old folder meanwhile, and deletes each original only when its copy verifies. Leftovers (Windows files in use) are counted and reported, never forced. Cancel or quit is honoured only during the copy and leaves the old setting and files untouched. It is a `storageMove` task and has a before-quit killer.
- **Picked images.** `pickImage`, `images:fromUrl` and `images:fromArt` write to `media/picked/`, apart from the re-downloadable cache. Picks made before this change stay in the media root; there is no reliable way to tell them apart.
- Theme audio with no `audio.dir` shares the media root and moves with it. `scripts/bulk-import.cjs` and `scripts/export-library.cjs` read `media.dir` from the settings table.

**Books section (2026-08-04)** — new media type `'book'` (flavor A, `/books`): Open Library import + pages-based tracking + local EPUBs read through the EXISTING reader machinery. **Progress = pages** (`progress` = current page, `total_units` = page count): book is deliberately NOT in `UNIT_PROGRESS_TYPES` and `BOOK` has no `logUnitLabel`, so the detail-page log button is mark-completed / read-again (the movies behavior) — a page is not a sitting. **Importer `src/main/openlibrary.ts`** (rawg.ts template; NO key, descriptive User-Agent — the AnimeThemes posture): work ids are STRINGS (`OL45883W`) → `ImportSearchResult.id` is `number | string`, ImportDialog flattens `api[source.key]` through one structural cast and `importingId` is widened; `ImportSourceCfg` gained `unitNoun` ("352 pages" not "352 ep"). Stats: book in `STAT_TYPES`/`ESTIMATED_TYPES`, `rowMinutes` = pages × `stats.bookPageMinutes` (default 1.5, Settings → Time stats) × passes; `MEDIA_TYPE_COLORS.book` teal (`lib/mediaColors.ts`); torznab `[7020, 7000]`. `books.dir` (bootstrapped on first attach, Settings → Folders) wiped in sanitizeSql.cjs. Tests: openlibraryImport (string ids, median, capped tags, best-effort endpoints, COALESCE re-import), manga.test.ts book block (books/ prefix + root, the progress guard, manga regression), torrents/mediaProgress/mediaRepo/exportSanitize extended.

## Game launcher, playtime tracking, HLTB lengths

**Game launcher + playtime tracking + HLTB lengths (2026-08-06)** — games/VNs get launch-from-app (`cfg.hasGameLaunch`, GAME + VISUAL_NOVEL): a per-title executable in **`media_item.exe_path`** (init.sql + schema.ts + ensureColumn; absolute machine path — wiped in sanitizeSql.cjs next to local_dir, deliberately absent from mediaRepo's COL map AND from `MediaItem` — it rides `games:overview`, the local_dir posture) and sessions in **`game_session`** (media_id CASCADE, UTC started/ended, duration seconds; wiped on export). `src/main/gameLaunch.ts` is the mokuroRun singleton with THE one deliberate deviation: the child is spawned `detached:true` + `unref()` and is **never killed** — no cancel channel, and before-quit calls `finalizeActiveGameSession()` (records the in-flight session, must run BEFORE `closeDatabase()`) while the game keeps running. Sessions under `MIN_SESSION_SEC` (60) are discarded with a launcher-stub hint (a stub that spawns the real game and exits is the known v1 limitation — link the real exe); an app crash loses the in-flight session (accepted; documented in-module). **The fold** (`gameLaunchCore.ts:foldedProgress`, pure + exhaustively tested): `game_session` is the source of truth for tracked seconds, and `media_item.progress` moves by the **delta of the rounded cumulative** (`unitSecondsFor`: game=3600, vn=60), so short sessions never round away, hand-entered baselines survive, and a manual progress edit just becomes the new baseline — progress stays hours(game)/minutes(vn), which is why `rowMinutes`/Stats needed ZERO changes. Windows-only launch (`process.platform` guard throws a friendly error; overview carries `supported`); picker is main-side `games:pickExe` (manga.attachFolder posture). Renderer: `GameLaunchSection` (Playtime tab, executable controls and aggregate tracked time; Games adds dated history in the adjacent `GamePlaythroughSection`) + `lib/useGameSession.ts` (useOcrRun port, 1 s poll so the elapsed chip ticks; settled toast invalidates games+media+checklist). Checklist gained detected source `gameSession` (`game-session` def, daily, NOT seeded; sessions counted by `date(started_at,'localtime')`). **HLTB is now the authoritative game length**: `hltb.ts:hltbLengthHours` = `max(1, round((main ?? allStyles)/60))` hours, written to `total_units` at BOTH sites — rawg.ts import (RAWG's crowd-average `playtime` is only the fallback) and `fetchForMedia` (game rows only, a miss never writes), so the existing detail-page Fetch/Refresh button fixes wack lengths on already-imported games; VN lengths stay VNDB minutes untouched; re-import-to-apply otherwise. `GAME.totalFieldLabel` is now 'Length (hours)'. Tests: gameLaunch (fold matrix), gameSessionRepo (atomic insert+fold, aggregate overview, CASCADE), hltb (both write sites, VN untouched, miss keeps value), rawgImport (+HLTB-beats-RAWG, URL-routed http mock), checklist + exportSanitize extended. Windows spawn/exit end-to-end is UNVERIFIED on this Linux box — needs a manual pass on the user's gaming PC after the next release.

## Game playthrough journal

Games have a resume card on Overview and a playthrough workspace on Playtime.
`playthroughRepo` owns first/replay/New Game Plus runs, one active run per game
(partial unique index), difficulty/build notes, last stop, next objective and dated
journal entries. Activating a run atomically pauses the previous active run;
completing a run does not rewrite the title's library status or playtime.

All tables are additive: `game_playthrough`, `game_playthrough_note` and
`game_playthrough_session`. The last is a one-session-to-one-run association over
existing `game_session` rows. The launcher captures the active run **before spawn**
and passes that identity through exit/quit recording. Changing the active run while
playing cannot redirect the session. A deleted run leaves the session unassigned;
its absence never prevents playtime from being saved. The existing rounded
cumulative progress fold, minimum session duration and detached process lifetime
are unchanged. Older sessions remain unassigned until explicitly attached.

Deleting a run cascades its notes and associations, never the underlying sessions.
Journal entries are personal notes, not manufactured playtime. History pages return
50 dated sessions and 50 notes with independent totals; the pager spans the larger
collection. `playthroughs:*` crosses the usual IPC chain and its query keys live

All three tables are wiped from shared exports. Regression coverage includes a

## Achievements

**Achievements (2026-08-14)** — Xbox/Steam-style achievement tracking for games and VNs (`cfg.hasAchievements`, GAME + VISUAL_NOVEL — the same pair that can link an executable). Three new tables, no migration work: **`achievement_game`** (media_id PK, `provider` `steam`/`ra`, `provider_game_id`, `schema_fetched_at`), **`achievement`** (the set: api_name, name, description, hidden, both icon paths, `points` RA-only, `global_pct`, UNIQUE(media_id, api_name)) and **`achievement_unlock`** (achievement_id PK — **a row's presence IS "unlocked"**, so nothing stores a locked state; `source` `emu`/`ra`/`manual`). The first two are canonical and SURVIVE an export (the theme_song posture, declared in sanitizeCoverage's CANONICAL_SURVIVORS); `achievement_unlock` is personal and wiped, as are the three new settings keys.

**Why it works on pirated games at all**: a cracked game still calls the Steam achievement API — the crack just points it at a Steam emulator, and every one of them writes unlocks to a well-known file. `achievementsCore.ts` (pure, `gameLaunchCore` seam) holds a table of ~15 candidate paths (Goldberg/GSE in `%APPDATA%`, CODEX/RUNE/EMPRESS/Online-Fix under `%PUBLIC%\Documents`, SKIDROW/SmartSteamEmu, ALI213's globbed profile folder, plus Goldberg's local-save-beside-the-exe mode) and two tolerant parsers (Goldberg JSON object-or-array; the INI family, both section-per-achievement and flat-container shapes, `Achieved`/`HaveAchieved`/`earned` spellings). **`parseUnlockFile` never throws** — the watcher reads these files while the game writes them, so a torn read must look like "nothing new", not a crash. `emuScan.ts` is the IO half behind an injected `EmuFileIO`, which is what makes the whole thing testable on Linux. Roots come from env vars, and a missing one just drops its candidates.

**Providers**: `achievements.ts` gets the Steam set from **three sources in order, first hit wins** — the user's Steam account is "limited" (Steam only issues Web API keys to accounts that have spent money), so the list has to work with no key. (1) **The crack's own `steam_settings/achievements.json`** beside the exe (or up to two folders above it), which Goldberg/GSE releases ship: full schema INCLUDING the api names the emulator writes unlocks under, icons copied in content-addressed via `files.importImageFile`, zero network — `parseGoldbergSchema` handles string and localized-object names, `hidden` as "0"/"1"/bool, and both `icongray`/`icon_gray` spellings. (2) The **Web API** `GetSchemaForGame`, only if `steam.web_api_key` is set. (3) **Steam's public community stats page** (`steamcommunity.com/stats/<appid>/achievements`), which has names/descriptions/art/global % but **no api names** — those come from the keyless `GetGlobalAchievementPercentagesForApp` and `joinCommunityWithPercentages` pairs the two lists **by rank, not by value** — both are sorted by % desc, but Steam serves the page from a cache and the endpoint live, so on any active game most values differ by a tenth (an exact-percent join paired 12 of 49 on AC4 Black Flag). Equal counts → zip by index; unequal counts → an order-preserving alignment within `PCT_TOLERANCE`, with the unplaceable rows counted as `unmatched` and surfaced in the setup toast. On that path the percentages endpoint is load-bearing, not decoration, so its failure IS a failure. `AchievementSetupResult.schemaSource` says which source won. Rarity for the other two sources comes from the same keyless endpoint, best-effort. `exeDirOf` picks path flavor by separator, not host — the posix `dirname` of a `C:\…` path is `.`, which was a silent miss on the Linux test box. Icons go through `downloadImages` like any importer, and the whole thing is two-phase atomic. Rarity tiers (`rarityTier`: >25 common, >10 uncommon, >3 rare, else ultra-rare) are computed main-side so the renderer never re-derives cutoffs; **no gamerscore is invented** — `points` stays NULL for Steam. `retroAchievements.ts` covers emulated games: `API_GetGameInfoAndUserProgress` returns the set AND the user's full unlock history in ONE call, RA points are shown because RA actually awards them, and `parseRaDate` appends the missing `Z` (RA sends UTC unzoned, so `Date.parse` would shift every unlock by the machine's offset). RA has no free-text search endpoint — the dialog pulls a console's game list and filters locally, with direct game-id entry as the escape hatch.

The RA console catalogue is cached once per console for the app session, so each debounced query filters the same local snapshot instead of downloading the whole list again. Failed catalogue requests are evicted and remain retryable.

An unavailable or rejected optional Steam Web API key falls through to the public community schema source. The keyless percentages endpoint remains required on that community path because it supplies the API names used to identify unlocks.

**Appid without Steam**: only `external_source='steam'` rows know their appid. Everything else resolves through the keyless storefront `search()` and the user confirms; an exact imported appid remains usable even when that optional search is unavailable. The choice lands in `achievement_game.provider_game_id` (no `media_item` column, no ensureColumn). A first association is written before the fetch so a failed network half does not cost the user the lookup; replacing an existing provider/game identity commits only with the fetched replacement set.

**Eligibility is "exe linked now or ever"** — `exe_path IS NOT NULL OR EXISTS(game_session) OR EXISTS(achievement_game)`. `games:clearExe` nulls the path and keeps no history, so the latter two clauses are what make "or ever" true; once tracking exists its own row is the durable marker.

**The live half** — `achievementWatcher.ts` owns the app's ONE main-side `setInterval` (5 s for emulator files, 30 s for RA), started by `gameLaunch.startSession`, cleared in `endSession` and by `stopAchievementWatcher()` in the before-quit registry (ahead of `closeDatabase()` — it writes rows). Both stop paths run a **final sweep**, because emulators commonly flush as the game exits. Popups surface through the **in-game overlay** (`achPopup.ts`): a frameless transparent click-through window at `#/achpop` pinned bottom-right with `alwaysOnTop('screen-saver')`, rendered by `AchPopupPage` which polls the same `achievements:watchStatus` the in-app toast uses (no push channel — the freeze is intact; main preloads the window at session start so its seq seed lands before the first unlock). The overlay exists because OS notifications are suppressed during fullscreen apps on Windows — the original `new Notification` path was invisible exactly when it mattered — and that path survives only as `fallbackNotify` for environments where no window can be created (`focusable: false`, `showInactive`, and `setIgnoreMouseEvents(true)` so clicks fall through to the game). Bursts above `ACH_POPUP_BURST_AT` collapse into one summary card on both surfaces. `pollOnce(deps)` takes injected fs/fetch/now deps, so the whole detect→write→raise path is tested with no game, no emulator and no timer. An mtime short-circuit makes the 5 s interval free in the common case. First tick deliberately does NOT seed `lastMtimeMs`, so an unlock earned between the last sweep and this launch is still caught.

Ordinary cards beyond the three visible overlay slots wait in a FIFO queue and start their lifetime only when displayed, so closely timed polls cannot silently hide older unlocks.

**Overlay visibility and the real chime (2026-08-23).** The chime is the AUTHENTIC Xbox 360 "Achievement Unlocked" sound — the file Microsoft published on Major Nelson's blog for personal use, bundled at `src/renderer/src/assets/achievement-chime.mp3` and played by `lib/achChime.ts` from inside the overlay window only. Visibility rules every user should know: borderless-windowed games and Windows "Fullscreen Optimizations" (the Win10/11 default) compose the topmost popup over the game; **true exclusive fullscreen bypasses the compositor and NO external window can appear over it** — that needs DLL injection like Steam/Discord overlays, deliberately out of scope. Reliability hardening: raise() re-asserts `alwaysOnTop` + `moveTop()` after every show (fullscreen games can knock topmost windows down the z-order, and Electron has races where the flag silently lapses); failures are logged via `logWarn('achievements', …)` instead of silently falling back; the window anchors to the display nearest the cursor, not blindly the primary (multi-monitor setups get popups on the screen the user is looking at). **"Test popup & sound"** on `/games/achievements` raises the overlay with a fake unlock card without earning anything: `achievements:testPopup` → `requestPopupTest()` stores a test event served through `watchStatus`'s `test`/`testId` fields for a 15 s TTL (lazy age check, no timer); the overlay dedupes by `testId`, the main window's toast hook ignores it, and it works with no session running because showUnlock creates the glass on demand.

Each raise re-evaluates the cursor's display and moves the existing window before showing it, so switching monitors after launch remains correct. The archive explains the exclusive-fullscreen limitation beside the test control.

**Re-fetch is authoritative** for the set (prunes what the provider dropped, refreshes names/art/rarity) but **unlocks survive it while the provider identity is unchanged** — the UNIQUE upsert keeps achievement ids stable, so only a genuinely removed achievement loses its unlock by CASCADE. Changing provider or provider game id first deletes the old set, because `api_name` is not portable between identities and an overlapping value must never inherit an unrelated unlock. Initial provider sync commits the association, canonical set and fetched/on-disk unlock snapshot in one transaction; a failed unlock write restores the prior set. Unlock imports keep the **earliest** timestamp: an emu file rewritten today must not relabel a two-year-old unlock. A file with no usable time falls back to the file's mtime (far closer than "now" for a retroactive sweep). **Timestamps are range-checked twice** (`normalizeTime`, then again in `insertUnlocks`): SQLite's `datetime(?, 'unixepoch')` returns NULL past year 9999 and `unlocked_at` is NOT NULL, so an emulator fork writing microseconds would otherwise abort the insert transaction and discard every good unlock in the batch — and in the watcher that failure is swallowed *after* `lastMtimeMs` advances, silently killing detection for the rest of the session.

**Two watcher races the lifecycle has to survive**, both because `gameLaunch.endSession` clears `active` BEFORE the (async) final sweep, so a new launch is legal inside that window: `stopWatch` retires only the watch it started with (`if (watch === mine)`) and sweeps that same one explicitly (`pollOnce(deps, mine)`), and `startWatch` clears `watch` FIRST so launching an *untracked* game cannot leave the previous game's watch standing. Both are regression-tested. A first-time provider choice is stored before fetch for retry; changing any already-tracked provider/game identity commits only once the complete replacement snapshot lands, or the old achievements could sit on screen mislabelled.

**The renderer polls past the end of a session** (`GRACE_MS`, 20 s): the session status flips to `ended` the instant the game exits, but the final sweep — the one that catches what an emulator flushes on exit, a network call later for RA — lands after that. Without the grace window those unlocks would only surface after reopening the app. `useGameSession` also invalidates `qk.achievements.all` on settle, so the tab, chips and Home strip aren't left showing pre-session counts, and a watcher that has stopped detecting (RA unreachable) surfaces its `message` as a toast rather than looking like a session where nothing was earned.

**Manual toggling is always available** (`source: 'manual'`), the floor for games nothing can track — and it will not overwrite a tracked unlock. **The Goldberg wizard** (`GoldbergWizardDialog` + `generateGoldbergConfig`) is guided, not automatic: it writes a `steam_settings/` folder (achievements.json in Goldberg's shape, steam_appid.txt, copied icons) into a directory the USER picks and shows the copy steps — it deliberately never touches the game folder, since a wrong guess there breaks an install.

**Surfaces**: an Achievements tab on the detail page (`?tab=achievements` deep-links), `/games/achievements` (recent feed, per-game completion, rarest), `/games/installed` (exe-linked games and VNs; a resume-first launcher with wide art when available, hover/focus Play, recent covers, and a searchable/sortable collection), a Home "Recent unlocks" strip that hides itself when empty, and a `✓ n/total` chip on list cards fed by ONE `cardSummaries` map rather than a query per card. Both new routes sit above `/games/:id` (the `/anime/seasonal` precedent) and are `GAME.children` sidebar links. Tests: achievementsCore (path matrix, every file format + damaged input, rarity boundaries, Goldberg round-trip), emuScan (injected IO, glob expansion, multi-emulator merge), achievementRepo (prune-preserves-unlocks, earliest-wins, CASCADEs, real SQL), achievements (URL-routed fixtures for both providers), achievementWatcher (detection, mtime short-circuit, final sweep, quit killer), plus initLegacyDb and sanitizeCoverage extended. **Windows end-to-end — real emulator files, a real fullscreen overlay popup with its chime — is UNVERIFIED on this Linux box** and needs a pass on the user's gaming PC; the emulator path table is community knowledge, so "Import from emulator files" reporting `found: 0` on a game that should have files is the signal to extend it from a real sample.

Installed artwork uses the shared cached thumbnail widths: 320 px for the full cover grid and 480 px for recent covers and the featured foreground cover. A featured tile with an Art-tab background uses that original image. `thumbUrl` selects the smallest supported width that meets a smaller request and uses the original above 480 px or outside `media/`; the server reads the same `THUMB_WIDTHS` list. This prevents a rejected thumbnail request from silently falling back to a full-size cover for every game while scrolling.

Achievements deliberately stay on their own tab rather than gaining a second rail on Playtime — a duplicate of a full grid is chrome, not information.

## Franchises

**Franchises (2026-08-15; cross-media since 2026-10-05, when the cross-media guides merged in)** — `/franchises` (`FranchisesPage`) + `/franchises/:id` (`FranchisePage`), reached from the Library drawer, the Games and Visual Novels contextual tabs and `GAME.children`. The old `/games/franchises*` and `/guides*` URLs redirect (`ParamRedirect` in `App.tsx`); the guide ids became franchise ids. A third feature shape beside CLAUDE.md's A/B: a **curated overlay** over the existing media types. The canon lives in `src/shared/franchises/` (`types.ts`, one file per franchise, `index.ts` catalog — the `wrestling.ts`/`programming/` pattern); franchise, entry and character ids are FROZEN (persisted UI state + route params). Each entry names its `mediaType` (absent = `game`), and there is **one row per release**: every anime season, film, OVA, manga part, novel or TV series (one TMDB series row) is its own entry. Entry arrays are authored in release order and `tests/franchises.test.ts` enforces that plus id uniqueness, `appearsIn` integrity, external sources valid for each type, unique route positions, collision-free titles per type and https-only art URLs.

Library rows are matched client-side by `matchLibrary` (`match.ts`, `tests/franchiseMatch.test.ts`) **separately per media type** — an entry only claims a row of its own type, so the Steins;Gate novel and anime cannot collide and a TMDB movie id cannot claim the TV row with the same number. Within a type: external-id pass first (multiple refs per entry cover Steam re-listings and edition cuts such as Advent Children Complete), then exact-normalized title/alias equality — never substrings, which is what keeps FF7 and FF7 Remake apart; remakes are separate entries. Normalized library titles are cached per row object, because the index matches every franchise against the whole library. `useFranchiseLibrary` reads one `qk.media.home(type)` list per type a franchise spans (byte-identical `{ mediaType }` filter, the HomePage rule) and owns the **positional** finished check (`statuses[1]` of the row's own type, rename-safe, plus the `progress >= totalUnits` fallback).

Three optional orderings sit beside release order. `chrono` is in-universe story order: adaptations share their source's slot (ties break by release order), and an entry from a separate continuity (the live-action Resident Evil films) has none and sinks below the order. `route` is the editorial suggested path inherited from the guides; `optional` route stops are detours that never become the **Next up** chip (`nextRouteEntry`). Flags `spinOff`, `remake`, `adaptation` and `optional` render as row chips, and a media-type chip appears when the franchise spans several types, together with type filter pills (persisted per franchise). Default sort stays release order everywhere. The rating column is the community score in `mediaRepo.COMMUNITY_SQL` key order (`communityScoreFor`) with the curated `mc` fallback; the "h played" chip sums game rows only. A title's detail page shows a **Franchise** fact (`franchisesForItem`, the same matcher on one row) with the next stop in route order, or release order when the entry is off-route.

**Page layout**: rows in the LEFT half (`lg:grid-cols-2`), Timeline + Characters in the right half, trivia full-width below. Sorting is by **clickable column headers** (Title=release order, Year, Story [hidden when the franchise has no `chrono`], Route [hidden without `route`], ★ your score, Rating) — click again flips direction; nullable columns always sink unowned/unscored rows to the bottom. Rows re-sort **live** with `lib/useFlip.ts:useFlipList` (a dependency-free FLIP: measure `[data-flip-key]` rows in a layout effect, invert with a translateY, reflow, play) — nothing else in the app animates a data-driven reorder (dnd-kit only animates during a drag). The timeline (following the type filter) is a vertical year strip of **covers** (gap proportional to the years between releases, clamped): library cover for owned entries (accent ring + ✓ when finished, links to the title), greyed tile when not owned.

**Background** — ONE per franchise, pinned. `FranchiseCfg.heroUrl` (curated, curl-verified) is both the index-card image and the page's default background; the user replaces it with `Set background` in the header (`api.files.pickImage()` → a `media/` path in the settings row `franchise.<id>.background`, `''` = reset since settingsRepo has no delete; `franchiseBackgroundKey()` names it and `scripts/sanitizeSql.cjs` wipes `LIKE 'franchise.%'` on export). `FranchiseBackground.tsx` is a page-local absolute layer using **`background-attachment: fixed`** — anchored to the window viewport but painted only inside the page box, so it holds still while `main` scrolls and can never paint over the sidebar/Topbar; needs no shell widths and is immune to `ui.scale`. Preload-then-cross-fade on URL change, viewport-fixed base-900 gradient scrim. Per-game `bgUrl` on every entry stays **RESERVED** — nothing on the franchise page uses it (the first cut's hover/click per-game swap was explicitly rejected). The per-media background it was reserved alongside SHIPPED on 2026-08-17 as `media_image.is_background` + `MediaDetail.backgroundPath`, painted by this same component on every detail page (see "Right-click on an Art-tab tile" above); the reserved `ImageKind 'background'` is gone.

Curated art (heroes, entry `bgUrl`, character `portraitUrl`) renders from the remote URL immediately (CSP allows `img-src https:`) while `src/main/franchiseArt.ts` caches it content-addressed via `downloadImage` — `franchise:ensureArt(id)` / `franchise:ensureHeroes()` fire a single-flight fire-and-forget batch (one `franchiseArt` task-registry row), `franchise:artStatus` is polled at 1.5 s while running, `franchise:artMap(id)` / `franchise:heroMap()` map url → cached rel path (`files.ts:dlFileName` is the extracted shared derivation; `tests/franchiseArt.test.ts`). Fandom's image CDN (`static.wikia.nocookie.net`) refuses requests without a Referer, so `artRequestHeaders` adds one for that host only; prefer Steam, AniList, TMDB, Nintendo or Wikimedia art over Fandom for new entries. Index cards load a cached hero through `thumbUrl(path, 480)` and fall back to the full file: curated heroes run from 1920×620 to 4496×2779, and decoding 31 of them at full size for 10rem banners dropped scroll frames. Adding a franchise = one data file + a `FRANCHISES` entry; nothing else changes. Curate ids from the public AniList/VNDB/Open Library APIs and TMDB's site (append `language=en-US`; this machine otherwise gets Turkish titles), never from memory.
